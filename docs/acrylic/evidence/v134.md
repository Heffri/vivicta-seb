## The rule

The model reads a row the report prints as dashes and answers 0 — Linc p.100's NAV-reconciliation
line `Räntebärande skulder – –` (v090's standing gap) and Rejlers' `1-2 years - -` … `4-5 years - -`
bucket rows quoted as one block (v097 finding 4). `quote_on_page` can never verify such a quote (a
dash is no number token), and often no 0 is printed anywhere to fall back on, so the answer died as
"dropped as computed, not read" (Linc) or survived unproven at 0.25 with "quote not found" (Rejlers,
kept alive only by the unrelated `0.8 per cent` on the same page). The dash is the report's own
printed nil (v036's convention, v078's translation) — kept under two conditions, both on the rows
the quote matches on the cited page (or the statement spread):

1. the value is exactly 0 (0.0 included), and
2. every matched row (a) carries a label known for the field — `_label_known` over the field's
   `synonyms` **plus, for the total field, its `row_synonyms`** (Linc's bare `Räntebärande skulder`
   is a row_synonym, not a synonym; the same vocabulary `_bucket_total_row` recognises the debt row
   by and `extract`'s own `total_voc` builds), and (b) prints no figure where the fiscal year reads:
   the fiscal-year column per `_row_year_column` when a header names one, else every numeric column
   must be a dash (`_row_amounts(..., nil=None)` all `None`).

**Why no arithmetic gate (v078's two gates reduced to these two conditions).** v078's dash-to-0
fires inside the bucket-column reader, where the selected row prints a total and the real buckets
must sum to it within ±2 — the row's own arithmetic is the proof. A row that prints *only* dashes
has no total to close against and no figure to sum; closure is vacuous, and the model's 0 here is
not assembled from anything. The work order's "no other number can be conjured" is made operational
twice instead: a matched row that *does* print a figure where the fiscal year reads disqualifies the
quote outright (the 0 contradicts its own citation), and so does any *unmatched* row on the same
page that carries real amounts under one of the field's own labels (a dashed `Lease liabilities`
next to a `Bank loans 500` row is not a zero total). A matched row `_bucket_row_prior_year` proves
prior-year is refused too — last year's dash is not this year's 0.

Fired, the answer is kept with evidence `["quote_on_page", "printed_nil"]` (the matched row becomes
the source quote, `raw_label` its label, period the fiscal year), confidence through `score_field`'s
normal path — it lands at **0.5** (the v078 tier: provenance-true, not a printed figure; the
`printed_nil` marker itself weighs 0.0), never a hand-written value. The key joins `stated_zeros` —
the Creades family's own exemption set — because the rule proves a 0 with no printed digit: that is
what lets the later computed-not-read site and the wrong-table scope guard leave the kept value
alone, exactly as they already leave a stated zero alone.

Both drop sites are guarded. The first (the unverified-quote branch) runs *before* the printed-0
fallback — that ordering is what upgrades Rejlers, whose page does print a 0 elsewhere and which
therefore never reached the drop. The second (the final "printed on none of pages" drop) catches a
quote a stray digit made verifiable, whose row still prints dashes.

## Refusals (the counter-examples, all still null end to end)

1. an unknown-label dash row (`Avstämningspost – –` offered as total_debt) — label gate;
2. a known-label row that prints its figure in the fiscal-year column (`Between 1 and 5 years 250
   200`, no year header) — drops as computed, not read, as before;
3. the model says 0 but no dash row of the field's vocabulary exists on the page (`Total borrowings
   – –` on a page printing only real bucket rows);
4. a dashed component row beside a real debt row of the same vocabulary (`Lease liabilities - -`
   next to `Bank loans 500 400` offered as total_debt) — the unquoted-figure refusal.

A fourth case is pinned at the helper level: `Räntebärande skulder - 100` under a `2025 / 2024`
header — the fiscal-year column is the dash, the 100 prints in the prior-year one, the 0 is kept.
Suite note: with the shipped `require_explicit_values` the identity check stays honestly
`missing` on both greens (no bucket table exists on either page); the kept 0 never fakes a pass.
