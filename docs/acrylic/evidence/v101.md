these reports with a minus because the table is a net-debt / financing reconciliation where every

## Mechanism (`extract.py`, additive only)

- `_NET_DEBT_LABEL` — a private regex matching net-debt row labels ("Net debt", "Nettoskuld",
  "Net interest-bearing debt/liabilities", FM Mattsson's "Nettokassa / nettoskuld") on the cleaned
  raw label. A negative under such a label can be a genuine net-cash position, and `total_debt`
  must not point at a net-debt row at all: left exactly as printed, one warning naming the shape,
  never repaired (the v048/v083 label vocabulary judges what points there).
- `_normalize_sign(fields, sfs, schema, texts, warnings, values)` — runs per total/bucket field when
  the value is negative AND the quote is page-verified (`quote_on_page`), AND the sign is the
  table's presentation rather than the debt's: the quoted row itself carries other negative amounts
  beside the field's own, or the same table does (the contiguous amount-bearing run around the
  quote row in `_page_rows`). Flip: value −v → v, `evidence += sign_normalized` (a 0-weight WEIGHTS
  marker, like `identity_kept`/`printed_nil`), one warning in the work order's format:
  `total_debt: -1474 printed with a liabilities-negative sign convention; recorded as 1474`.
- Scope: the buckets-sum-to-total identity shape only (`_identity_parts` + `_DATE_BUCKET_KEYS`),
  the same generic scoping `_date_bucket_derive`/`_finer_split_rows` use — income_statement's
  identities have no `null_as_zero` list, so expenses and other legitimate negatives are out of
  reach by construction.
- Call site: after `_finer_split_rows`, BEFORE the final checks recompute — the identity closes on
  carrying positives after normalization, per the work order ("identity after normalization"); a
  mixed-sign table's printed signs would close identically only when every operand flips together.
