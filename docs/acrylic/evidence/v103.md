## The mechanism

`backend/schemas/debt_maturity.json` gains one top-level key, nothing else:

- `table_scope_words.undiscounted` — `undiscounted`, `non-discounted`, `contractual cash flows`,
  `odiskonterade`, `kontraktsenliga`, `liquidity risk`, `likviditetsrisk`, `maturity analysis regarding`
  (the work order's list; the last is RVRC's own title form and needs its `regarding` — a plain
  `Maturity analysis liabilities` title, Karnell's, does not match).
- `table_scope_words.all_liabilities` — `trade payables`, `accounts payable(s)`, `leverantörsskulder`,
  `other liabilities` (+ RVRC's printed `liabilites` typo), `other current liabilites(/ies)`, `övriga
  skulder`, `expected returns`, `derivatives`, `derivate`, `acquisition-related liabilities`, `contingent
  considerations`.

`backend/pipeline/extract.py` gains `_table_scope(rows, i_header, i_total, basis, scope_words,
debt_scoped) -> "carrying" | "undiscounted" | "all_liabilities" | "unknown"` plus three small helpers
(`_scope_zone`, `_scope_reason`, `_scope_header`). Table boundaries are derived from row anatomy, not a
bare window scan:

- **Body** = the rows directly above the anchor that carry a digit, contiguously (a maturity table's data
  rows all print figures — RVRC's SEKm-sized figures included, which `_row_amounts` would read as note
  references). Prose, footnotes and section text break the walk, so a quote stitched or prose-written far
  below a table never walks back up into it (Storytel's covenants sentence, Synsam's/Humana's prose).
- **Title block** = the digit-free rows above the body, **short ones only** (`_SCOPE_TITLE_MAX` 100): a
  table's own title is a standalone line (Boozt's is 73 chars, RVRC's 52, Ework's 66, Smartcraft's 36);
  the 181-char prose sentence above Boozt's table that says "contractual undiscounted amounts", and the
  torn multi-column glue elsewhere, are not titles and stay outside.
- **Carrying-column exemption** (`_CARRY_COLUMN`: `carrying`, `redovisat`, `bokfört`, `book value`) — a
  table that prints a carrying column is readable under both bases whatever its title says (Ework's and
  Instalco's titles name the *other* column; reading the carrying column is exactly v076; Humble's column
  is headed `Book value`; a torn header can break the phrase `carrying amount` while the bare word still
  names the column — Ework's real p.70). Deliberately not added to `header_synonyms`, which re-tags the
  total slot and must not change meaning.

Verdicts: carrying column anywhere in the span → `carrying`; else a title marker → `undiscounted` under
the carrying basis (refused), while under the undiscounted basis — v089's own table — the verdict is
`all_liabilities` only when non-debt rows sit between the header and a **non-debt-scoped** anchor row
(RVRC's bare `Total`; a debt row like Lime's `Borrowing (incl. overdraft)` or Instalco's `Liabilities to
credit institutions` keeps v089's read), else `unknown`; no marker → `unknown` (baseline behaviour).

**Gates** (one per mechanism, each an early refusal + warning, no other semantics touched):
`_fill_bucket_columns` (inside the candidate loop, after column alignment, before any write), the
model-citation gate in `extract()` (a verified quote that is a printed row of a refused table → null +
warning; stated zeros and stitched/prose quotes are left to the provenance gates that own them),
`_between_rows`, `_finer_split_rows`, `_date_bucket_derive` (each anchored at its own row: the uppermost
operand / total's row). The statement-row fill needs no gate of its own: it runs before the citation gate,
which refuses whatever it filled from a refused table (Smartcraft's case below).

## Two refinements to the work order's rule 1, forced by the "0 家变差" acceptance (disclosed)

1. **`all_liabilities` does not fire on word-list hits alone.** A full-corpus dry run of the plain rule
   (non-debt row label between header and anchor ⇒ refuse) caught five companies whose *label-pinned*
   values would have been nulled: **Alligo** (p.143 balance-sheet `SUMMA SKULDER` read, leverantörsskulder
   rows above), **RaySearch** (p.83 BS `Current lease liabilities 77.5`), **Svedbergs** (p.132 torn
   maturity table, övriga skulder glued in from the neighbouring note — all four label values), **Stillfront**
   (p.109 Note 21 whose own scope includes contingent considerations — the label reads `Total 5,887` from
   it), **Hexatronic** (p.160). Narrowed to: all-liabilities refuses only a table that also carries an
   undiscounted/liquidity title marker (RVRC under both bases), and never a debt-scoped row. A markerless
   all-liabilities table (Karnell's) stays with v095's debt-row-first ordering — unchanged behaviour, and
   the narrower rule still covers every wrong-table story in the corpus.
2. **Markers are matched on the title block only.** A bare 25-row window scan brands carrying tables whose
   section headings say `LIKVIDITETSRISK`/`Liquidity risk` above prose (MedCap p.101's carrying table is
   the label's own source; Humble's and Biogaia's pages carry the prose definition of liquidity risk
   inside torn glue). The anatomy walk stops at prose that names figures, so the heading never reaches the
   table.

Both refinements narrow only (never widen) what is refused, and the full replay below is the proof they
cost nothing: the changed set is exactly the four wrong-table stems.
