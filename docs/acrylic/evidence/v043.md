# v043 — two-pass page selection (`EXTRACT_TWO_PASS`), 30-company before/after on `debt_maturity`

Lane `ao/vivicta-seb-37/v043-two-pass`, off `origin/acrylic` (`1135d20`, the v041 tip at dispatch time).
Codex CLI `gpt-5.6-terra`, `LLM_PROVIDER=codex`.

## What was built

`backend/pipeline/extract.py`: `EXTRACT_TWO_PASS=1` (default **off**) makes `extract()` run a small pass 1
first — a ~400-char head-of-page snippet of *every* `locate.candidate_pages()` candidate (not just the
top-2 the single-pass window shows), asking the model which 1–2 pages hold the statement itself. Pass 2 is
the existing extraction prompt, fed only the page(s) pass 1 picks. Pass 1 failure or an illegal reply (not
1–2 unique page numbers, all members of the candidate list) falls back to the single-pass window — verified
off is byte-identical to before (no code path executes, see `test_confidence.py`).

One correctness fix beyond the page-selection logic itself, found by writing the flag-on test before the
fix (red, then green): `score_field`'s `page_is_statement` evidence (and the "fill a null field from the
statement page's own row" repair) used to always trust `pages[:2]` — the locator's own guess. Under
`EXTRACT_TWO_PASS`, that under-scores every extraction that lands on a candidate pass 1 correctly picked
outside the top-2: a bookkeeping gap, not an evidentiary one. Both now follow pass 1's own pick when it
succeeds. Byte-identical off (the new variable is `None` unless the flag is on and pass 1 succeeds).

`backend/pipeline/llm.py` — **not touched**. Pass 1 reuses the existing `call_llm()`/`llm.chat()` path with
a small schema (`PAGE_SELECT_SCHEMA`) instead of adding `chat_text()`: the codex/claude CLI backends already
ignore the `schema` argument (per `llm.py`'s own module docstring), and the openai-compatible backend
handles a small schema exactly like the main extraction schema. A `chat_text()` would have been unused
code.

`scripts/random_check.py` — **not touched**. The 30-company run below never goes through the HTTP API (see
Methodology): there was nothing to pass through.

## Methodology

The 30 (seed, company) draws are exactly v035/v037/v041's own seed-1/2/3 lists (10 each; `knowit_2025`,
`flat_capital_2025`, `cloetta_2025` were independently drawn by both seed 1 and seed 3, by chance — counted
as two separate rows, once per seed, matching the work order). **Before is each seed's own cached
`extractions/debt_maturity.json`, not rerun**, per the work order.

**After was produced by a standalone offline harness** (`run_two_pass.py`, kept in
`uaw-lanes/v043-two-pass/`, not part of this PR — a throwaway tool, not a deliverable), not through
`uvicorn`/the HTTP API/`random_check.py`:
```
EXTRACT_TWO_PASS=1 LLM_PROVIDER=codex LLM_MODEL=gpt-5.6-terra
locate.candidate_pages(texts, schema) -> extract.extract(texts, pages, schema, report_meta)
```
reading each company's already-parsed `pages.jsonl`/`meta.json` straight from the seed-kb caches
(`uaw-lanes/vivicta-shared/seed{1,2,3}-kb/<stem>/`) that the work order pointed at. Two deliberate
departures from v035/v037/v041's own methodology, both explained:

- **One run per company, not two.** The owner's own call-budget arithmetic ("~80 次(30 家 × 2 次 + 少量重试)")
  only reconciles if "2 次" means the two model calls pass 1 + pass 2 make per company (30×2=60, leaving
  ~20 for retries) — running each company *twice* for the v037/v041-style stability check, on top of
  two-pass's own 2 calls, would be 120 calls before any retries, already past the cap. Went with the
  reading that fits the number the owner actually wrote; see "Variance" below for how this was partly
  recovered anyway.
- **Bypassing the HTTP API entirely.** `POST /extract` unconditionally calls `kb.save_extraction(...)`,
  which **overwrites** `data/kb/<stem>/extractions/debt_maturity.json` on disk. None of these 27 companies
  have a committed `debt_maturity.json` in this repo's own `data/kb/` (`git ls-files` confirms — only one
  company in the whole corpus does, Ericsson), so every prior round's own real-endpoint runs left theirs
  uncommitted "per territory" too — but calling `extract.extract()` directly, in-process, produces the
  identical result the endpoint would (`app.py`'s own `run_extract` is exactly `pages =
  locate.candidate_pages(...); extract_mod.extract(...)`, nothing else) with zero risk of clobbering
  anything and zero port/process management. `git status --short data/kb data/reports` is empty for this
  entire lane — not just uncommitted, untouched.

30/30 pass-1 calls returned a legal page selection (no illegal-output fallback fired); 0/30 needed a
pass-2 retry or widen (no `llm:` timeout warnings). Every company cost exactly 2 codex calls. 3 companies
(`boozt_2025`, `apotea_2025`, `catella_2025` — the most surprising or highest-stakes regressions) were
independently **rerun once more** to check stability before writing them up; all three reproduced
byte-identical (same page selected, same fields, same confidences) — see `*.rerun.debt_maturity.json` in
this directory. Total: 30×2 + 3×2 = **66 codex calls** (the `ncab_2025` smoke test that opened this lane
is one of the 30, not additional), under the ~80 cap throughout.
`provider-usage.py`'s codex line: **69% (seven-day) before → 69% after** (no visible movement, consistent
with every prior round's own observation at this reading's granularity).

## The dominant failure mode: pass 1 picks the wrong page, from a 400-char snippet, in a way the full
## single-pass prompt (which sees the *whole* page) essentially never does on this schema

Three regressions were dug into fully (page text pulled, before-quote's real source page identified, and
independently reproduced on a rerun — see `*.rerun.debt_maturity.json`). All three turned out to be the
**same** mechanism, not three unrelated bugs:

- **Catella**: the before run's `total_debt` (−1474 @1.0) is sourced from **page 108**
  ("...Total interest-bearing liabilities −1,474 −2,735"), not page 107. Two-pass selected **only page
  107** — a liquidity-risk table with a garbled, wrapped column header ("31 SEK December M 2025 < 3 months
  months 4 to 12 Between and 3 yrs...") — and dropped 108 entirely.
- **Apotea**: the before run's `total_debt`/`due_within_1_year` are both sourced from **page 113**
  ("29. Borrowings ... Total secured borrowings 21.6 79.6"), the note ranked #1 in the candidate list.
  Two-pass instead selected **page 104**, ranked 3rd — a multi-instrument financial-risk table headed
  "4.1 Financial risk factors, cont. Interest-bearing liabilities" that opens with the report's own
  front-matter breadcrumb ("01. Introduction 02. Introduction to Apotea...") before reaching that heading.
  Page 113 opens with the **identical breadcrumb line** — the actual heading ("29. Borrowings") and number
  don't appear until past what a 400-char snippet reaches, while page 104's superficially-matching
  "Interest-bearing liabilities" phrase sits right at the top.
- **Boozt**: the before run's three fields are sourced from **page 121** — a liquidity-note summary row
  that already lays out the buckets in one line (`"Lease liabilities 441 26 78 273 63 -"`). Two-pass
  selected **page 108** instead (ranked 5th) — the same lease note's own, more detailed breakdown, with a
  plausible-looking "LEASE LIABILITY" heading right at the top of its snippet — and came back with nothing:
  its own "Total 441 499" / bucket table is present, but the model didn't cite it even alone in the
  window (confirmed on rerun, byte-identical both times).

Both distinct problems recur across the wider set of 13 regressions (not exhaustively re-verified
per-company at this depth, but consistent with every one inspected):

1. **Snippet starvation.** A 400-char head-of-page snippet regularly doesn't reach a note's own heading or
   figures when the page opens with a repeated report banner/breadcrumb (Apotea's case; this corpus prints
   that shape often — `locate.py`'s own `strip_boilerplate` exists for exactly this reason, and pass 1 never
   gets its benefit, since it reads the raw page head, not the boilerplate-stripped text `locate.py`
   scores against).
2. **Liquidity/contractual-note vs. carrying-amount-note confusion.** This is precisely HANDOFF's own
   anticipated risk ("Two tables on one page... We want the one that sums to the balance-sheet
   borrowings") and the schema's `value_convention` already resolves it — for the *full* extraction
   prompt, which is why v035/v037/v041 report **0/0/0 mis-picks** on this exact risk across three rounds.
   Pass 1 has none of that context (just a bare page-vs-page choice from short snippets) and mis-picked it
   at least three times here (Apotea, Catella, and — differently shaped, a liquidity summary vs. the same
   note's own detail rather than two separate notes — Boozt).
3. **Lost companion page**, distinct from the above: Ework, Coor, Alligo, MedCap, Morrow Bank and Hansa
   Biopharma all kept the *same* #1-ranked page pass-1 would have anyway, but the before run's actual
   citation needed the page next to it (`locate.py`'s own "statement spread" — Morrow Bank and Hansa
   Biopharma are the cleanest examples: v041 already named the *correct* half of each pair — p.75 for
   Morrow Bank, p.66 for Hansa Biopharma — and two-pass kept the *other*, wrong half both times). Single
   page selections (pass 1 returned exactly one page in **29 of 30** runs, despite the prompt explicitly
   offering a 2-page answer) removed that safety net almost everywhere.

**A new, distinct risk two-pass introduces that single-pass mostly avoided this corpus: a confidently
wrong, checks-passing partial number.** Better Collective and Acast both landed on a real, verified,
on-page figure (lease liabilities in both cases) that is *not* the company's actual reconciling
interest-bearing debt (v035/v037 already diagnosed both companies' real totals as living elsewhere).
Before, both cases were either all-null (Better Collective — an honest "couldn't find it") or a
check-**failing** answer (Acast — a value a downstream reader would at least see flagged as
inconsistent). After, both are a single field at 0.9 confidence with a passing check — a more
convincing-looking wrong answer than either before state.

## Variance — one direct demonstration, three cited from prior rounds

Not run n≥3 per company here (budget), but not silent about it either:

- **Flat Capital, same input, two different outcomes.** Seed 1 and seed 3 both drew Flat Capital; two-pass
  selected the identical page (18) both times; seed 1's call found the explicit "amounted to 0 TSEK (0)."
  sentence and confidently extracted it, seed 3's call on the *same* page did not. This is the one
  variance data point produced directly by this lane (not cited from an earlier round) — call-to-call
  variance reaches into pass 2 itself, not just page selection.
- **Nelly Group's before value (287.1@1.0) is itself a documented wrong answer**, not a correct baseline —
  v037 traced it to a real `_derived_value` bug (out of this lane's territory, still unfixed) that combines
  a current *and* non-current lease row into one number under a `due_within_1_year` label; the real figure
  is 36.2. Going to null isn't a clean loss of a correct answer, but it isn't a fix either — the correct
  value still wasn't found.
- **Gentoo Media** is v041's own worked example of the single highest call-to-call variance seen across all
  three rounds ("three calls, three different sourced rows for the same two fields"); this draw's
  before→after delta is plausibly dominated by that, not by two-pass.
- **Storytel's `due_within_1_year` 0.25↔0.9 swing is v037's own documented pure model variance** for this
  exact field, reproduced with no code change at the time; the same swing recurring here isn't evidence of
  a two-pass effect either way.

## Cloetta — not a two-pass finding

Seed 1's Cloetta draw shows a large "improvement" (0.5/0.5/null/0.5 → 0.9/0.9/1.0/0.9), but that "before"
snapshot in `seed1-kb` predates the v036/v040 mechanism fixes already on current `acrylic` HEAD — it is not
what single-pass actually does today. Seed 3's own Cloetta draw is the clean, unconfounded comparison:
before and after are **byte-identical**, both already at the fixed state. Two-pass adds nothing beyond what
single-pass on current HEAD already achieves for this company. Not counted as a real two-pass win.

## For the group

The switch is kept, default off, per the work order — three concrete, evidence-backed starting points if
anyone picks this back up, each targeting one of the two distinct mechanisms above:

1. **Lengthen `PAGE_SELECT_SNIPPET`** past 400 chars (Apotea's own page 113 needed more than that to reach
   its heading past the front-matter breadcrumb) — or feed `locate.strip_boilerplate()`'s output instead of
   the raw page head, the same preprocessing `locate.py`'s own scoring already gets.
2. **Give pass 1 the same carrying-amount-vs-contractual steer the schema's `value_convention` already
   gives pass 2** — right now pass 1 has zero domain context, and is asked to disambiguate a distinction
   HANDOFF specifically flagged as needing it.
3. **Never let pass 2's window shrink to fewer pages than the single-pass default would have used** — e.g.
   union pass 1's pick with `pages[:1]`, or require pass 1 to always return 2 pages. 29 of 30 runs here
   returned exactly one page despite the prompt allowing two, and "lost companion page" alone explains at
   least 6 of the 13 regressions.
