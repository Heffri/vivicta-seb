## The 3 schema commits

1. **`4c53128` — `total_debt` synonym `"total borrowing"` (singular).** Ovzon's real note ("NOTE 23 –
   BORROWING", p.61: `"Total borrowing 423 701"`) and MEKO's real note ("23 Borrowing", p.103:
   `"Total borrowing 6,558 5,327 3,446 3,244"`) both print the grand-total row as singular
   `"Total borrowing"`, not the plural `"total borrowings"` already in the list — `_label_known` is a
   prefix match, so the shorter plural synonym never covers a singular row. **Confirmed fixed for
   MEKO** (0.9 → 1.0, label_known now present). Did not move Ovzon's confidence, because Ovzon's page
   61 was never a locator candidate either time (see below) — the synonym only helps once the model
   sees the page. Corpus-wide grep of all 112 companies' `pages.jsonl` for `"borrowing cost(s)"` (the
   one plausible collision — "Total borrowing costs" as a P&L line) found **zero** matches shaped that
   way; the only pages tagged `[total borrowing]` by the same scan are real total-debt rows (aak,
   beijer_ref ×2, bufab, engcon, hufvudstaden, lindab_international, medicover, scandic_hotels,
   swedbank, systemair, telia, verisure, vitec_software, wihlborgs_fastigheter, among others) —
   evidence this singular form recurs well beyond this seed's own two companies.

2. **`74ae3c4` — `total_debt` field description: 0 when the report states in words it has no
   interest-bearing debt.** Creades (p.61: *"Investmentföretaget har varken räntebärande skulder eller
   kundfordringar"* — the investment company has neither interest-bearing debt nor receivables — zero
   digits anywhere in that sentence) is read correctly by the locator (page 61 was already a candidate
   both runs; `räntebärande`/`skuld` are schema keywords) but the *unedited* prompt's "only rows that
   are printed... never compute a value" rule left the model reading "no row" as "null", not "0".
   Deliberately narrow trigger (a plain-language no-debt statement, not "unused credit facility" or
   other indirect signals) to avoid inviting the model to infer zero from weaker evidence elsewhere.
   **Result: directionally confirmed, not fully landed** — pass 2 shows the model *did* attempt 0 this
   time (new warning: `total_debt: 0 is printed on none of pages [61, 62]; dropped as computed, not
   read`), but `_value_in_quote(0, quote)` requires a literal digit "0" in the model's own quoted text,
   and the Swedish sentence has none — the pipeline's own (pre-existing, general) "no source, no value"
   provenance gate then drops it back to null. The schema lever worked on the model; a second, `extract.py`-side
   lever would be needed to actually land it — see "For the group" below.

3. **`d4b7cf2` — `due_within_1_year` synonym `"total borrowings in current liabilities"`.** Intrum
   (p.123, one of HANDOFF's own named "Financials in the universe... structured differently") splits
   its note by current/non-current rather than named buckets: `"Total borrowings in current
   liabilities1"` / `"...in non-current liabilities"`. The current-liabilities row is unambiguous
   (current = due within 1 year, always); the non-current counterpart is deliberately **not** given a
   symmetric synonym, since a bare "non-current" total could span both `due_1_to_5_years` and
   `due_after_5_years` and the schema has no way to know which without a finer split (same caution
   v037/v046 already applied to Gentoo Media's `"borrowings, current"`). **Confirmed fixed**: Intrum
   went from 2/3 fields at 1.0 to 3/3, the only Mid-Cap company at strict full confidence this seed.

## A side effect of the synonym fix (Cloetta's 4th candidate)

`locate.candidate_pages()`'s `fields` score counts *every* synonym string that matches, not just
distinct ones — since `"total borrowing"` is a substring of the pre-existing `"total borrowings"`, any
page that already had the plural form now scores **two** synonym hits instead of one wherever both
literally co-occur. Diagnosed precisely (not just noticed): Cloetta's 4th-ranked candidate moved from
p.39 to p.171 because p.171 contains `"Total Group credit facility"` — wait, more precisely `"total
borrowings"` inside an unrelated per-instrument interest-rate table — which now double-counts. Checked
directly: this only ever touched the 4th-ranked slot for this one company across all 10 drawn this
seed (verified offline, before spending any call budget: 9/10 companies' full candidate lists are
byte-identical old-schema vs. new-schema; only Cloetta's differs, at position 4). Position 4 is
essentially never used (single-pass starts at `pages[:2]`, only widens to `pages[:4]` when under half
the fields come back non-null, which Cloetta's extraction never triggers) — accepted as a known, bounded,
inconsequential side effect rather than reworked into two separate synonym lists (schema doesn't
support locate-only vs. extract-only synonyms without a bigger structural change out of this lane's
scope). Recorded plainly per v046's own precedent for judgment calls with a non-zero but bounded cost.

### Ratos — value was correct, verification fails on a `parse.py` two-column merge (out of territory)

independently verified-correct one). Root cause is `parse.py`'s line-based text extraction, explicitly
out of this lane's territory (`不碰 parse.py`).

## For the group

1. **Creades' schema fix is half-landed**: the model now attempts 0 for an explicit no-debt statement,
   but `extract.py`'s provenance gate (`_value_in_quote`) requires a literal digit in the quote, which
   a prose negation sentence structurally never has. A general (not company-specific) fix: when
   `value == 0`, the quote is verified on the page (`quote_on_page` passes) but contains no digit,
   *and* the schema field's own description says a plain-language statement can mean 0 (a new,
   opt-in marker, mirroring how `null_as_zero` already opts a check into a similar leniency) — accept
   it rather than dropping it as "computed, not read". Ready to pick up; not attempted here, since it's
   real `extract.py` surface, not a keyword/synonym, and deserves its own red/green test pass.
2. **`parse.py`'s two-column-layout merging is now the single most common failure cause across the
   last 3 rounds** (Ratos and Flerie this round; Ependion/Gentoo Media/XANO/Ework/Acast in prior
   rounds) — more so than locator misses or vocabulary gaps at this point. HANDOFF's own "Next"
   item (`find_tables()` / blocks sorted by (y, x)) is the highest-leverage remaining lever for this
   section; every hardening round from here keeps re-diagnosing the same defect class in new companies.
3. **Two-pass page selection still mis-picks under real load** (Flerie, this round) even after v045's
   three fixes — variance, not a regression of this lane's own edits (verified: same candidate list
   both runs, only the model's choice differed). Consistent with v045's own "net positive, but not
   perfect" conclusion; not a reason to revisit the default here.
4. **Acast's keyword-gap hypothesis is now closed** (zero schema-vocabulary hits anywhere in its
   91-page report) — a 6th hardening round drawing Acast again shouldn't re-spend a company slot
   re-diagnosing this; it needs a locator-side or `parse.py`-side look, or acceptance that this report
   has no distinct borrowings note to find.
5. Financials in the universe (Norion Bank this round; Intrum was the one financial that *did* work
   cleanly, since its note is a plain current/non-current carrying split) continue to split into two
   very different shapes: some print an ordinary carrying-amount note (fixable via the same synonym
   lever as any industrial), others (deposit-taking banks) fundamentally don't have a single
   "total interest-bearing debt" row to point at. Not a single fix — per-company judgment, same as
   HANDOFF already flagged.
