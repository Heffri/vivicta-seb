# v174 — Upcoming maturities:Compare 视图里的到期名单(确定性、可比性感知)

工单:`v174-maturity-wall`(上报 `vivicta-seb-72`)。基线 `origin/acrylic` 派工时 `4192a6f`,交付前 fetch + merge 了 6 条新提交(v169 SEB Mid Cap 第三 collection、v173 `/api/kb` 缓存),merge commit 见分支历史。

## 1. 读的前提

`consult-gpt6.md` 第 8 条与 `consult-fable.md` 第 2 条都指向同一件事:Compare 目前只能并排比较**已打开**的几份报告,而 105 份已存 `debt_maturity` 抽取里"谁的到期压力最大"这个问题没有任何确定性入口;gpt6 明确要求"现有 basis 为空时应老实显示不可比,不能为了有图而跳过确认"——核实后仓库里**至今没有一份 debt_maturity 抽取的 basis 被确认过**(`basis.reviewer` 全 None),所以这条规则不是防御性写法,是当前数据的真实状态,必须让整块名单在这个前提下依然有用。

## 2. 后端:`workbench.maturity_wall(extractions) -> {rows, coverage}`

纯函数(`backend/pipeline/workbench.py`),输入是 `kb_export_extractions()` 已经产出的 decorated extraction 列表(CSV/PPTX 导出复用的同一条路径,零 PDF、零模型调用)。核心设计决定,和字面工单对照:

- **`share` 与 `comparable` 分离**:`share = due_within_1_year / total_debt` 只要两个值都在、能确认是同一种货币、分母不为零就会算出来,**即使 basis 未确认、字段证据不足也照样显示**——因为这是纯算术,不是信用判断;"comparable" 是单独一层信任信号(entity/period/debt_basis/leases 是否确认 + 两个字段是否有可靠证据 + 两个单位是否能安全相加),同一行可以是 `share: 0.108, comparable: false`。这个分离是核实到当前数据 100% basis-unconfirmed 之后才定的——按字面"不可比就不算"会让这张表在今天的仓库里空空如也。
- **零汇率换算**:货币/量级解析复用 `pipeline/merge.py` 的 `_unit_key`(v168 已经上线并测过的解析器,处理 MSEK/TSEK/SEK m/SEK '000/Mkr/Tkr 等真实写法),没有重新写一份正则——只加了一层"已知货币白名单"(SEK/EUR/USD/NOK/DKK/GBP/CHF/JPY/CAD/AUD/PLN/CNY),防止 `merge._unit_key` 把无法识别的单位文本(如乱码)当成一个"看似合法"的货币码。同币种、不同量级(MSEK vs TSEK)时两个数会归一到较粗的量级一起显示;不同币种时不换算,直接标 `comparable:false` + 原因,原始单位不改写。
- **`due_1_to_5_years`/`due_after_5_years` 缺失不影响这张表**:这两个桶不是本功能要读的字段,`total_debt` + `due_within_1_year` 两个字段本身完整、有证据就够——这正是"缺长桶但 total/current 可证实 = 局部可计算"的字面落地,不需要额外状态位,因为函数本来就不看那两个字段。
- **零债务是干净状态,不是错误**:`total_debt == 0` 时 `share` 是 N/A(除以零无意义),但不计入 `missing_total`,`comparable` 该是 true 还是 true(basis/证据都在的话)。
- 排序:`comparable` 行在前、按 `share` 降序;不可比的行排在最后但**仍在列表里**(不是过滤掉),`reason` 字段说明原因。
- `coverage = {total, comparable, missing_total, missing_w1y, basis_unconfirmed}`,与 rows 一起返回。

`backend/app.py` 新增 `GET /api/kb/maturity-wall?section=debt_maturity&collection=wallenberg|midcap|all`,直接调用已有的 `kb_export_extractions()` + `workbench.maturity_wall()`,没有新的 I/O 路径。集合为空时返回 200 + `rows: []`(前端渲染空态),不是 404——阈值/空态是产品要求的一部分,不该是错误。

## 3. 后端测试(先红后绿)

**红观察**:`del workbench.maturity_wall` 后重跑 `test_workbench.py`,在新增断言处按预期抛 `AttributeError: module 'pipeline.workbench' has no attribute 'maturity_wall'`——证明新增的断言确实在练习新代码,不是摆设。

**绿观察**(`python test_workbench.py`,`Workbench checks passed...` + `maturity_wall: ...` 两行都打印):15 个场景、22 条纯函数 assert,覆盖工单点名的每一类:

| 场景 | 断言什么 |
|---|---|
| 基线(MSEK/MSEK,basis 全confirm) | `share=0.2`,`comparable=true`,`reason=''` |
| basis 未确认 | `share` 仍是 0.2(不因未确认而消失),`comparable=false`,coverage 里 `basis_unconfirmed=1` |
| 缺 `total_debt` | `share=None`,`comparable=false`,`coverage.missing_total=1` |
| 缺 `due_within_1_year` | 同上,`coverage.missing_w1y=1` |
| 零债务(4 个字段都是 0) | `share=None`,**`comparable=true`**,`reason='No debt outstanding.'`,不计入 missing_total |
| 字段无证据(human_review 清空、evidence 全空) | `share` 仍算出,`comparable=false`,reason 含 "not yet verified" |
| **MSEK vs TSEK**(同币种、异量级) | `share=0.5`(正确按量级换算,不是裸数相除);展示值归一到 `{100.0, 'MSEK'}` / `{50.0, 'MSEK'}` |
| **EUR vs SEK**(异币种) | `share=None`,`comparable=false`,reason 含 "currency";原始单位 `MEUR` 未被静默改写 |
| 无法识别的单位文本 | 与货币不匹配同样处理,`comparable=false` |
| 集团 vs 母公司(`consolidation='Parent'`) | 不因非 Group 而扣分,`comparable=true`,行内如实展示 `consolidation:'Parent'` |
| 租赁排除(`leases='Excluded'`) | 同上,如实展示,不扣分 |
| 长桶缺失(`due_1_to_5_years`/`due_after_5_years` 为 null) | 不影响 `comparable`/`share`(局部可计算) |
| 排序 | 3 行,comparable 的两行按 share 降序在前,不可比的一行(share 数值本来更高)排最后 |
| coverage 聚合(5 行混合) | `{total:5, comparable:2, missing_total:1, missing_w1y:1, basis_unconfirmed:1}` 精确匹配,零重复计数 |
| 非 debt_maturity 的行被忽略 | 混入 income_statement 抽取不炸、不计入 rows |

另加 6 条断言复用既有"whole-KB exports"fixture(`abb_2025`/`ericsson_2025`/`outside_2025`)测端点本身:`GET /api/kb/maturity-wall?collection=wallenberg` 返回 2 行且 coverage 精确匹配、`collection=all` 返回 3 行;reviewed=True 的 abb 行 `comparable=true`,reviewed=False 的两行 `comparable=false`。

真实数据回归(fixture 后端,本机 `data/kb`,零模型):`collection=all` → **105 家**,`comparable=0`(如实反映今天没有一份 basis 被确认),`missing_total=13`,`missing_w1y=49`,`basis_unconfirmed=105`;`collection=midcap` → 104 家(SEB Mid Cap 范围内少一家)。单位解析器对这 105 家的全部已存单位字符串(`MSEK`/`SEK million`/`TSEK`/`SEK m`/`SEKm`/`SEK thousands`/`KSEK`/`kSEK`/`Tkr`/`Mkr`/`EUR'000`/`USD m`/`MEUR`/`PLN '000`/`Miljoner kronor` 等实际变体)**100% 解析成功、零 unresolved**。

其余既有后端套件(`test_collection`/`test_human_review`/`pipeline.test_kb`/`pipeline.test_merge` 等)merge 后重跑全绿,`decorate()` 里抽出的 `_field_ok` 共享函数没有改变既有行为。

## 4. 前端

- 新组件 `frontend/src/components/compare/MaturityWall.tsx`:挂在 `CompareView.tsx` 顶部(**只加了一个插入点**,原有并排比较表格与 Ask 面板未动),独立于 `results` prop——数据来自新端点,不依赖用户当前打开了哪几份报告。
