## Scope and method

This is a measurement-only lane. It starts from `139baac`, which includes v139, and does not change application code, schemas, labels, or committed KB data. The pipeline was configured as `LLM_PROVIDER=codex`, `LLM_MODEL=gpt-5.6-terra`, `EXTRACT_TWO_PASS=1`, and `EXTRACT_MERGE_RUNS=union`; the API configuration confirmed `provider=codex`, `maturity_basis=carrying`, and `merge_runs=union` before any extract route.

The five source PDFs were checked against the saved report metadata and registered from the local library. One API extract route was sent per fixed stem, with no retries. Every response reports `merge.mode=union` and `merge.runs=2`; hence the run made **10 raw extraction runs / 20 Codex invocations** (two-pass page selection plus extraction), exactly the task cap. The five raw run records are copied here as `v143/<stem>.run1.debt_maturity.json` and `run2`; deployable copies (`meta.json`, `pages.jsonl`, extraction) are in the lane-local `run1-kb`, `run2-kb`, and `union-kb` directories. None is committed under `data/`.

No UAW component was adapted: this lane makes no UI, desktop, or theme implementation change. The reference-only UAW material is therefore out of scope.
