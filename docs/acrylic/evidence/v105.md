KSEK / SEKm per report); current/non-current-only reports get `total_debt` + `due_within_1_year`
only; undiscounted/contractual maturity tables are never used for values; printed dash rows are
printed nils (0), never nulls; leases follow the report's own note scope.

## Findings (premise-level, for the record)

1. **BHG has two printed "totals" that differ by the transaction-cost accrual**: FV-note/
   roll-forward `Credit facilities 1,300.0` (nominal) vs Note 21/BS `Loans from banks 1,297.4`
   (carrying). v097's pass1 read the former; the schema's own wording ("must be a carrying amount
   that reconciles to interest-bearing borrowings on the balance sheet") picks 1,297.4. The two
   passes disagreed (pass2 lost the field entirely, the v090 Morrow shape) — the instability is
   route-side, the label is the stable printed row.
2. **Byggmästare's maturity table closes only through its terminal `år 4 -` row**: `Amotering år
   4 -` prints 0 (2025) / 868 (2024); 2025 rows sum to 2,873 exactly, 2024 rows to 3,805 ≈ 3,806.
   The terminal row is a straddling bucket (år 4 and beyond) whose printed nil makes >5y = 0 a
   lossless assignment. The BS current/non-current split (922/1,951) does not tie to the table's
   år 1 / år 2+ split (962/1,911) — a report-internal 40 tkr quirk; the maturity table is the
   report's own maturity disclosure and closes, so it is the label source. The stored w1y 922 came
   from the Klassificering row (`Kortfristiga räntebärande skulder 922 853`, p.53) — a different
   line of the same note family, hence the value ✗.
3. **PowerCell's total prints on two pages**: Note 27's own `Total borrowings 19,055` (p.50) and
   capital management's `Total borrowings (Note 27) 19,055` (p.44). The stored answer cited p.44;
   the label pins p.50 (the borrowings note). Value ✓, page ✗ — the mislabelled-location case,
   distinct from the wrong-value cases.
4. **Rejlers' dash rows are printed nils**: 1-5y = 0 (not null) per the v057 dash convention
   (Linc precedent); no >5y row exists anywhere, so that field gets no label at all. The stored
   1-5y 0@0.25 has the right value with an unmatched quote — the printed-nil conversion gap v097
   item 4 documented; the value itself now scores ✓.
5. **Svedbergs and Byggmästare are the two live instances of v097's computed-not-read drops**
   (435,842 and 1,911 — both sums page-verified correct against printed sibling rows, both still
   null in the stored answers). These two labels are the acceptance criteria for the v096
   vocabulary gap: values ✓ the day re-extraction reads the Swedish long-form / år-row siblings.
