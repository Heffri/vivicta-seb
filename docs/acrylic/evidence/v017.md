## 假设(工单给出)

v008/v008b 的失败案例里,错的页多是"流动性风险"这类标题下的表,对的页标题是"Borrowings / Upplåning / Räntebärande skulder / Interest-bearing liabilities"。现在 heading 加分只看 keywords 是否在前 150 字里出现;两类页都含关键词,所以分不开。设想:schema 级 `title_keywords`,若 schema 给了这组词,heading 加分只在标题窗口命中 title_keywords 时给(keywords 仍参与 distinct 计数),没给 title_keywords 的 schema(income_statement)行为逐字节不变。

**假设部分被推翻**:逐页人工核对后发现,"标题带 liquidity risk 的页是错页"这件事本身因公司而异——对 aq、seb、swedbank、sca、essity、arion,标题恰恰就是"Liquidity risk"/"e5. Liquidity risk"的那一页,里面印着报告唯一的到期表(数字达标、grep 得到 bucket);对 aak、alvotech、asmodee、volvo_car,标题相同的页却是纯叙述或指向另一张表。同一个词在不同发行人的报告结构里,一半时候是对的信号,一半时候是错的信号——这不是词表没选对,是"标题词能不能分开两类页"这件事本身对多数发行人不成立。

## 实现(已回退,仅作记录)

`backend/pipeline/locate.py::candidate_pages()`:

```python
title_keywords = [k.lower() for k in schema.get("title_keywords", [])] or keywords
...
heading = any(k in head for k in title_keywords)   # 原来是 any(k in head for k in keywords)
```

`distinct` 仍用完整 `keywords` 计数,只有 heading 判据换成 `title_keywords`;schema 不给 `title_keywords` 时 `or keywords` 回退,income_statement 逐字节不变(已验证)。

试过的 `debt_maturity.json` 词表(两版,见下),都是通用词(英/瑞),不按公司分支:

## 给小组的建议

1. **"标题词分不开两类页"这件事本身对多数发行人不成立,不要再从 heading 关键词角度攻这题**。aq/seb/swedbank/sca/essity/arion 的真到期表就印在"Liquidity risk"标题下;aak/alvotech/asmodee/volvo_car 的"Liquidity risk"标题页却是叙述页或指向别处。两种结构在真实语料里都常见,任何固定词表都会在其中一边翻车(候选 A 救 aak 但撞碎 aq/swedbank;候选 C 加裸词救回 aq/swedbank 但又撞碎 wihlborgs 的衍生品页)。
2. **essity vs sca 是一组很干净的对照实验**:两家同源(SCA 分拆出 Essity),笔记编号模板几乎相同(e4/e5),但"正确答案"相反——essity 该选 e4(账面值,过 `maturity_sums_to_total`),sca 该选 e5(唯一的完整三桶表,候选池里没有 e4 等价页)。这佐证 v008 已提的建议 #2:**locator 打分之外,用 `checks.identity`(sums-to-total)做事后交叉验证**,比任何标题词/排除词都更能分辨两张表里哪张是真表——essity 的 e4 页能自洽求和,e5 不能;这是词表拿不到的信号。
3. **aak 本身也没有看起来那么干净**:145(liquidity risk)和 169(borrowings)两页的数字其实一致(都来自同一笔银行借款),145 只是把它埋在一张"全部金融负债"大表里(还夹着租赁、应付款、衍生品),提取时更容易抓错行。如果分数机制以后要处理这题,"页面是否单一主题"可能比"标题含哪个词"更有效——但这已经不是关键词工程能表达的东西了。
4. 25 家里有 1 家(`saab_2025`)debt_maturity 候选页数为 0(不是本单引入,before/after 皆为空),值得记入 eval 背景。
