## 1. Candidates endpoint (zero model)

`GET /api/reports/{report_id}/candidates?section=` (backend/app.py, next to /extract) returns
`[{page, heading}]` — the same `locate.candidate_pages` ranking the extractor runs, plus the page's
de-boilerplated, whitespace-normalized opening cut at 80 chars. No model involvement; fixture mode
computes them from the real page text like any other mode, exactly as the work order requires.
Verified by hand: a 70-page upload with the debt note on pages 30–32 returns `[{page:30…},{31},{32}]`
with headings.

One backend behavior fix was required to make the work order's fixture requirement true: the fixture
payload hardcodes `section: "income_statement"` (it is an income-statement sample), so anything that
follows `extraction.section` asked the wrong report section. `_run_extract` now stamps the requested
section onto the fixture result. Consumers checked: HumanReviewForm (fixture results cannot be
reviewed either way — the POST 409s on the missing saved file), CSV/PPTX export (now names the
section the user ran — more correct), e2e specs that mock /extract entirely (unaffected).

Test: backend/test_workbench.py gained an isolated-KB block — boilerplate on every page, one debt
note, asserting the ranking `[11, 12]` (the page, then the page after it), heading start/length/
normalization, the boilerplate line's absence from the heading, an empty heading for a
boilerplate-only page, 404 on unknown report and section, and — with `extract` rigged to raise —
that the endpoint never calls the model.

## 2. The wait line (upload flow)

UploadView now runs `getCandidates` before `extractSection` and, while the model works, the progress
line reads `Reading pages 30–32 of 70 · Note 20 Borrowings … · 2 s` — pages, best candidate's
heading (section title as fallback when a page has no heading of its own), and a stopwatch. The
wording says "pages … of N" from the locator's answer, and stays honest about the two-pass caveat by
never claiming these are the only pages read. Locator failure is advisory: the generic
"Extracting …" line stays and extraction proceeds. The stopwatch's seconds string is computed inside
the interval callback and lands in state, so render stays pure (oxlint's purity rule stays clean;
no new warnings — lint exit 0, the same pre-existing warnings documented since v001/v010).

Provider duration copy (per work order): codex/claude ≈ "about 30 s with the connected model",
OpenAI-compatible base URL (this setup's local model) ≈ "about a minute on the local model", fixture
promises nothing because it answers instantly.

## 3. Not-found banner (Results view)

`NotFoundBanner` (results/) mounts at the top of ResultsView — insertion point only, table and
review form untouched. One secondary block (muted tint, hairline border — deliberately not the
danger recipe): what happened, which pages the locator ranked (`formatPageRanges` collapses runs,
en dash), and a "Fill in below" button that selects the first not-found figure and scrolls to its
review form. Trigger refined from the WIP version to the work order's two cases: every value null,
or a check marked unavailable **while a value is actually missing** (the WIP version fired on any
unavailable check, which also covers unit/period mismatches — there the figures were found and the
banner would have lied).
