## Structure decisions

- **One material.** The screen is a single pane: `bg-linear-to-b from-background to-muted/60`
  (the `--bg-1..2` translucent gradient), hairline `--border`, the `--glass-hi` inset top edge, and
  `overflow-hidden rounded-xl`. No `backdrop-filter` anywhere in the view (DESIGN.md: the shell's `.glass`
  is the only blur; everything inside is a flat translucent step). Faces, list rows, cards and the action
  bar are `--bg-1..4`-family steps of that one pane, separated by hairlines — top-to-bottom while stacked,
  left-to-right at ≥1280px where the faces sit side by side (`grid-cols-[1.1fr_1.1fr_1fr]`, directory gets
  the extra fraction: it's the widest content).
- **Widths.** ≥1280px viewport = three columns (the work order's primary target); ≤900px = single column
  with the rail folded (same breakpoint the shell rail uses). 901–1279 keeps the old `max-w-3xl` single
  column centred — wide enough for the list and grid to breathe, but not enough for three honest columns
  at the pane's real width (~630–1010px after the rail).
- **Cached reports out of `<details>`, collapsible, open by default.** It was buried in a collapsed
  `<details>` before — a first-class path shouldn't start hidden, and the grid scrolls internally
  (`max-h-72`) so the face keeps its neighbours' height even with the full library. The chevron
  (`aria-expanded`, local UI state only) collapses it for directory/upload-only users.
- **Busy = the faces dim, the action bar stays live.** The three-face grid gets `opacity-60 +
  pointer-events-none` (plus `aria-busy` on the pane; the per-control `disabled={busy}` from before is all
  still there), while the footer keeps the spinner in the Extract button and the `(i/n)` progress line.
- **Status colours from the token table only.** The all-failed block and the schemas-error line use
  `--danger` / `--danger-muted` (`border-danger/30 bg-danger-muted text-danger`); the tried-URL `<details>`
  is preserved. No success/warning surface exists on this screen — the `cached` badge stays `secondary`
  because "cached" is a neutral fact, not a status. Selection/checked/drag states use the accent pair:
  rows `bg-primary/10` + check icon, cards `border-ring bg-primary/10`, dropzone `border-ring bg-primary/10`
  while `dragging`. Focus rings are the stock `focus-visible:ring-ring/50` (accent) on every interactive
  element, including the local ones.
- **Action bar.** Section select (with the schemas-error line under it), Extract button, progress line that
  wraps to its own row — one place to read "what will run and what is happening".

## Not done

- The drag-over state is implemented (`border-ring bg-primary/10`, icon tint) but not captured: native
  HTML5 dragover can't be faithfully simulated by Playwright's input pipeline. Everything else in the
  matrix is in the shots.
- No success/warning token usage — this screen has no ok/warn status surface; forcing one would be
  decorative. Danger is the only status that occurs.
