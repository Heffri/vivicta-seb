## Where the three failures occurred

### NVIDIA debt: the real page was never prompted

The downloaded FY2025 report has 181 physical pages.  The aggregate schedule is physical PDF page
**136**, not the debt-instrument table on page 164:

```text
Outstanding Indebtedness and Commercial Paper Program
Our aggregate debt maturities as of January 26, 2025, by year payable, are as follows:
(In millions)
Due in one year $ —
Due in one to five years 2,250
Due in five to ten years 2,750
Due in greater than ten years 3,500
Unamortized debt discount and issuance costs (37)
Net long-term carrying amount $ 8,463
```

Before the fix, candidates were `[164, 165, 159, 146, 137]`; page 136 matched neither the
IFRS-oriented locator phrases nor a field synonym.  The existing bare-year ladder reader correctly
returned false on pages 136 and 164: page 136 has named `Due in ...` intervals, while page 164 is one
debt instrument per row and not a maturity ladder.  The zero-model sweep found only pages 158/159 for
the total and no bucket page.

After the schema additions, candidates are `[136, 137, 164, 159, 146]`.  The sweep now finds page 136
for total, 1–5 years and >5 years; it deliberately does not call the printed dash a numeric hit for the
within-one-year field.  The exact four-row reader handles that dash as zero, groups the two explicit
post-five-year rows, and requires the page's carrying amount and a <=10% principal/carrying gap.  It
does not pretend the arithmetic identity passes: gross principal is 8,500 while carrying debt is
8,463 because the page prints 37 of issuance costs.

### AMD income: page text was good; an empty currency regex corrupted units

In the downloaded 154-page variant, the actual Consolidated Statements of Operations is physical
page **61** (printed page 58).  It already ranked first and its text layer correctly contains
`(In millions)`, `Net revenue $ 34,639 ...`, and `Net income $ 4,335 ...`; pages 70/71 are notes.

The model can validly return the scale-only unit `millions` or `In millions`.  `_ccy(unit)` is then the
empty string.  The old currency correction called `re.sub(re.escape(""), "USD", unit)`, which inserts
`USD` at every character boundary and produces strings such as `USDMUSDI...`.  Two extraction runs
used slightly different scale wording, so union merge saw different corrupted units and nulled the
otherwise matching values.  `_unit_with_currency` now attaches the statement currency to an exact
scale-only unit and normalizes both forms to `USD millions`; it never passes an empty pattern to
`re.sub`.

### Volvo debt: the true table was outside the candidate window

The FY2025 report has 232 physical pages.  The baseline candidates were
`[82, 83, 44, 145, 129, 137, 102, 43, 119, 45, 41, 42]`.  The true note is physical page **118**:

```text
22:2 Maturity
Bond loans and current credit facilities
Year other loans facilities
2027 73,682 10,509 ... 2031 1,119 –
2032 or later 2,310 –
Total 137,234 61,174
22:3 Current bond loans and other loans
...
B/S Bond loans 64,960 45,460
...
B/S Other loans 45,866 58,292
```

Its bare numbered title `22:2 Maturity` matched no locator phrase, whereas page 82's management prose
matched `maturity structure`.  `page_texts` also folds visual year rows 2027–2031 onto one logical
line.  The existing ladder correctly refuses the table: it begins at fiscal+2, is non-current debt
only, and has a parallel unused-credit-facilities column.  The displayed `SEK bn` came from a wrong
summary candidate; `bn` itself is already accepted by `_UNIT` and decimal parsing and was not the
reason values were rejected.  The loan note states amounts in `SEK M`.

The locator now promotes only a numbered `Maturity` block that locally names loans, has multiple
future years, and closes with Total.  Candidates become
`[118, 119, 82, 42, 145, 129, 137, 102, 43, 41, 44]`.  The reader then requires all of these before it
can write: non-current B/S bond + other-loan rows close on the maturity Total; current B/S bond +
other-loan rows exist on the same page; future years are consecutive from fiscal+2 through a final
`or later` row; the unused credit-facility column is ignored; and all four answers close within the
existing ±2 rounding band.

## Reference and residual risk

Reviewed the reference implementation's `src/annual-report/pdf/table-shape.ts` and extraction prompt.
Neither provides this repository's guarded Python reader, so no reference code was copied.

The new deterministic readers are intentionally disclosure-shape specific.  NVIDIA's check remains
false because carrying value and principal maturities differ by a printed issuance-cost adjustment;
Volvo is accepted only because both current/non-current B/S subtotals and the complete maturity ladder
close.  Other unmatched schedules remain null rather than weakening either guard.
