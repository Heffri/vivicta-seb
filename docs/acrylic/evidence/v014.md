## The gap (third and last instance of the v011b pattern)

When a field's own printed row fails an identity check, the repair may join rows *named as part of the field* —
Essity's "Cost of goods sold" + "Items affecting comparability (IAC) – cost of goods sold" close gross profit —
while any other neighbour is refused (Sagax: "Profit before tax + Deferred tax"). Both halves of that gate held the
synonyms verbatim (`{s.lower()}`) while the row labels go through `_clean_label` (digits glue to their neighbours:
"Within 1 year" → `within1year`):

- **own-row detection** (`extract()`, the `_derived_value` call): `_clean_label(_row_label(quote)) in {s.lower() …}`
  — a digit-bearing synonym could never recognize the field's own row, so `own_syns` was silently never armed and
  the join ran **ungated** for exactly those fields (any closing neighbour accepted).
- **the part-row gate** (inside `_derived_value`): `any(x in _clean_label(_row_label(r)) for x in own_syns)` — even
  when armed, a part row named by a digit-bearing synonym ("Within 1 year" → `within1year` never contains
  `"within 1 year"`) was refused.

`debt_maturity`'s 22 synonyms are all digit-bearing (census below), so the protection was dead letter for that
schema; `income_statement`'s 7 shape-changers are digit-free (they differ through `result → profit` and the
currency strip), which is why nothing had shown in that corpus.

## What changed (2 files, +26/−2 in the diff; the behaviour change is 3 lines)

- **`backend/pipeline/extract.py`** (the `_derived_value` call site only) — the synonym set is built once as
  `own_syns = {cl for s in sf.get("synonyms", []) if (cl := _clean_label(s))}` — the exact `_statement_row` shape
  from v012 — and used both for the own-row detection and as the set passed to `_derived_value`. The
  "cleaned away to nothing must not match" guard is preserved by construction: a synonym whose cleaned form is the
  empty string never enters the set (it would be a substring of every label). `_derived_value` itself, `_clean_label`
  and every other caller are untouched.
- **`backend/pipeline/test_confidence.py`** — the case below.

## `scripts/label_regression.py` (new, the repeatable form of the v011b/v012 one-off scripts)

Read-only walk over `data/kb/*/extractions/*.json`: for every field with a `source.quote`, a `raw_label` and a key
inside the matching `backend/schemas/<schema>.json`, four verdicts are compared between a baseline and the current
code — `row_label` (`_row_label`), `label_known` (`_label_known`), `own_row_exact` (the own-row detection, exact
set membership) and `own_syns_contains` (the part-row containment gate, evaluated on the field's own row as the
stand-in part row). Usage:

```
python scripts/label_regression.py                                  # income_statement vs origin/acrylic
python scripts/label_regression.py --schema debt_maturity
python scripts/label_regression.py --schema income_statement --schema debt_maturity --baseline <git ref>
```

`--baseline <git ref>` loads `extract.py` **as of that ref** (`git show`) into a throwaway module inside the
`pipeline` package namespace, so the old code's relative imports resolve to the current `parse`/`locate` — no
inlined stale copies. The old side builds its synonym set verbatim (`{s.lower()}`), the current side cleaned
(`{_clean_label(s), non-empty}`), so the comparison measures exactly the call site's change. Prints identical /
changed / skipped counts, one detail line per changed verdict, and the per-schema synonym census. Read-only:
writes nothing, `data/` untouched.

## Non-regression (income_statement full corpus, the mandated one)

`python scripts/label_regression.py --baseline origin/acrylic` — 101 files, 908 field entries:

| comparison | compared | identical | changed | skipped |
|---|---|---|---|---|
| income_statement, all four verdicts per field | 736 | **735** | **1** | 172 |
| debt_maturity (the only stored file: Ericsson) | 3 | **3** | **0** | 1 |

- Skipped entries have no `source.quote`, no `raw_label` or a key outside the schema — both sides answer by
  construction there (`_clean_label(None)` is `""`, both verdicts false), same skip rule as v011b/v012.
- **The one changed verdict is inert** (ssab_2025, eps_basic, quote `Earnings per share, SEK1) D.6 4.92 6.54`):
  `own_row_exact` old True → new False. The printed label keeps its currency token glued to a footnote marker —
  `SEK1)` has no word boundary after SEK ("K" to "1" are both word characters), so `_clean_label` cannot strip it
  and the cleaned row label stays `earnings per share, sek`. The verbatim set contained that string, so the old
  detection hit; the cleaned set holds `earnings per share` (the synonym side *can* strip its own `, sek`), so the
  new one misses. Three reasons this changes no behaviour: (1) `label_known` — the predicate scoring and every
  other caller use — is **identical on both sides** (prefix match: `earnings per share, sek` starts with
  `earnings per share`); (2) `own_row` is only consumed for fields named in a failing **identity check**, and
  income_statement's three checks (`gross_profit_arith`, `net_profit_arith`, `margin_sanity`) name revenue,
  cost_of_sales, gross_profit, profit_before_tax, income_tax, profit_discontinued, net_profit, operating_profit —
  never `eps_basic`; (3) it is a stored-quote shape, not something this lane's three lines could create.
- debt_maturity 3/0: the stored Ericsson note uses "Total borrowings, current / non-current" labels — no
  digit-synonym row exists in the stored corpus, so the flip this lane makes (bucket rows recognized as their own
  field's row) is only observable on synthetic input, which the red→green case provides.
- Synonym census (current `_clean_label`): income_statement **7** cleaned ≠ verbatim, debt_maturity **22**, cleaned
  to empty **0** — the guard never engages on today's schemas, same numbers as v011b/v012 found.

## Findings (out of this lane's territory, reported not fixed)

The `SEK1)` shape above is a fourth normalization asymmetry, this one *label-side*: `_clean_label` cannot strip a
currency token glued to a footnote marker (`SEK1)`), while it strips the same token from the synonym side. Today it
only shows in an exact-set comparison (`own_row_exact`); a schema synonym printed verbatim as `…, SEK1)` on a page
would also miss `_statement_row`'s exact set (its prefix fallback still catches it). A fix would be in
`_clean_label` territory (e.g. stripping a trailing `)` after a currency token before the boundary check) — not
these three lines, and nothing in the corpus needs it (735/736 identical, the 1 inert).
