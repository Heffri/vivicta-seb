## Decision and scope

Packaged startup now tries the stable loopback sequence `47311` through `47326`. It records the selected value as `backendPort` in the existing per-install `config.json`; an available remembered fallback is tried first on later launches. If every stable value is occupied, only then does the shell use the existing random-free-port path.

The port belongs to the desktop shell rather than the renderer, so no frontend storage change or config migration was made. Keeping the same `http://127.0.0.1:<port>` origin lets the existing `arp-kb-collection` and `acrylic-tone` localStorage keys work unchanged. Settings saves and shell-theme saves write the current backend port back after saving their own settings, so they cannot erase a remembered fallback origin.

## Trade-off

The bounded stable sequence avoids changing a user's origin in normal and occupied-port cases while still allowing an app to start in an unusually busy environment. A bind can theoretically race another process between the availability probe and backend spawn; the existing backend health check remains the startup authority for that pre-existing race.
