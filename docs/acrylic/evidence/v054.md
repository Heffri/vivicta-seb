## What was built

`_quote_retry` (`backend/pipeline/extract.py`), hooked into `extract()` between the model's first
answer and the existing per-field validation. After the main call(s) settle, it collects every field
that returned a value whose `source.quote` **fails `quote_on_page` on the page it cites** (or cites
no page at all). If any exist and the switch is on, **one** follow-up call goes out — never two:

- system: the extraction call's own system prompt, verbatim;
- user: per candidate field, `key | label | your value: <v> | cited page: <n>`, then the cited
  page's own `_page_rows`, one row per numbered line (a field that cited no page gets candidate
  page 1; a page over `QUOTE_RETRY_MAX_ROWS=50` rows is filtered down to rows matching the field's
  value in any printed grouping (`_num_pattern`) or one of its schema synonyms, ±2 rows of context);
  the reply schema (`QUOTE_RETRY_SCHEMA`) is the field structure's own subset: `key`, `value`,
  `source{page, quote}|null`.

The model is asked to copy the printed row character for character as the quote — or set source to
null when no printed row states the figure — and may correct the value to what the row prints.
**Adoption gate:** a field takes the reply only when the new quote verifies on the page it names;
null, missing or still-unverifiable replies keep the original answer, so the retry can never leave
a field worse than the first call alone. Fields v050's `_stated_zero` already proves (a 0 the
report states in words — Creades) are excluded from the candidate list: the sentence is the
provenance, and showing rows could only invite the model to trade a proven 0 for an unprinted row.
No other prompt changed, no second retry, two-pass untouched; with the switch off the code path is
never entered (byte-identical behaviour, asserted by the suite's own off-case).

## Methodology

Targets: every stored seed draw (`uaw-lanes/vivicta-shared/seed{1..4}-kb/<stem>/extractions/
debt_maturity.json`) whose result carries a "quote not found" warning, a "dropped as computed, not
read" warning, or a field at confidence ≤ 0.25. That criterion yields 10 draws / 9 distinct
companies — Cloetta appears in three seeds with identical pages, so it is run once (its final
stored state has no unverifiable field left; its stored warning is historical noise from the
sum-attempt path that the column-derivation mechanism already lands at 1.0). Ratos is *not* a
target despite the work order naming it: its stored result (pass 2 of v048) is all-null with no
quote failure to retry — a retry needs a value with a bad quote to work on, and Ratos has none.
Gentoo likewise: its stored result is the full-confidence read from v045.

**Before = each company's own stored extraction, not rerun** (v045's convention; the stored draws
predate v044/v050, so several baseline fields differ for reasons that are the merged base's, not
this lane's — flagged per company below). After = a standalone in-process harness
(`run_quote_retry.py`, kept in `uaw-lanes/vivicta-glm-16/`, not a deliverable) calling
`locate.candidate_pages()` → `extract.extract()` directly against each company's already-parsed
`pages.jsonl`/`meta.json` — never through uvicorn or the HTTP API, so `kb.save_*` never runs;
`git status data/kb data/reports` is clean. Candidate lists reproduced the stored draws exactly
where the stored warnings quote them. The harness counts every `llm.chat` call by name and masks
owner-identifying paths before anything touches disk (no provider error occurred, so the mask was
never exercised — recorded for completeness).

Per the work order's variance rule: the verdict reads **only the fields where the retry actually
triggered**; first-answer variance and merged-base differences are marked, not scored.

## The one trigger: MEKO — the retry did its job; the text layer couldn't answer it

MEKO's stored 0.25 is the pure quote-shaped failure the work order describes: `due_within_1_year`
= 768, quoted "Total current 768 618 - 6 / liabilities" — the model's own line-splice, not the page.
This run the model again answered 768 (first quote again unverbatim), the retry fired, and the
adoption gate declined whatever came back — because **no verbatim quote for this row exists in the
page text at all**. Page 103 is a two-column-layout casualty: the printed row "Total current
liabilities 768 618 - 6" is torn mid-line by sidebar prose ("Total current 768 618 - 6 *phase-out
during this period and a return to the original cov-* …", with "liabilities" landing three lines
later glued to other sidebar fragments). Verified directly against `seed4-kb/meko_2025/
pages.jsonl`: `quote_on_page("Total current liabilities 768 618 - 6", page)` is falsy, and the
`_page_rows` shown to the model hold only the torn fragments — a model that answers perfectly
still has nothing adoptable to return. This is exactly the work order's anticipated escape hatch
("若首答阶段根本拿不到 `_page_rows` 匹配(比如页面是 v049 那类撕裂页),记下哪几家、等 v049"):
**MEKO p.103 is that page.** The 不变差 guarantee held (original answer kept, 0.25 both sides); the
blocker is `parse.py`'s line-based extraction, out of this lane's territory.

## Why 8 of 9 never triggered — the failure taxonomy moved

The stored draws were selected for quote-shaped failures, but re-drawing them under the current
prompt + base splits the same companies into three classes:

- **value-shaped (4: Ework, Boozt, Ependion, MedCap)** — the model quotes the full printed row
  verbatim (quotes verify), but its bucket figure is a computed sum of finer columns (154732, 104,
  415984, 102.3), dropped by the computed-not-read gates. A row list cannot fix these: the row is
  already in hand; the value is what isn't printed. The retry's collection criterion
  (`quote_on_page` fails) structurally excludes them — per the work order's own mechanism spec.
- **first-answer variance (2: Storytel better, Knowit thinner)** — Storytel quoted verbatim this
  run (0.25→0.9 with no retry); Knowit didn't attempt its buckets at all (computed-drop warnings
  gone, same nulls). Same pages, same schema, different luck — v037's variance warning verbatim.
- **genuinely quote-shaped (2: MEKO triggered, Creades guarded)** — Creades' prose-0 is now
  `_stated_zero`'s business (v050) and the guard kept the retry away from it; MEKO is the one
  honest trigger, and its page has no adoptable row (above).

So the round's answer to "把 0.25/null 抬到 0.9+" is: on this draw, the mechanism never got a
field it could lift — not because adoption is too strict, but because the 0.25 class has mostly
stopped being quote-shaped under the current base, and the one true survivor is blocked one layer
down (parse.py).

## Default verdict: **off**

The work order's rule: default on when improved ≥ 3× worse among triggered fields and no identity
flipped. Triggered fields: 1. Improved: 0. Worse: 0. No identity flipped — the safety half of the
rule holds, but there is no improvement to weigh, and 0 ≥ 3×0 is the rule's intent unmet, not met.
Default **off**, for the record:

1. **Trigger rate 1/9** under the same protocol that produced the stored failures — the quote-not-found
   class this mechanism targets barely reproduces on the current base (see taxonomy above);
2. **the one trigger was unadoptable** for a reason below this mechanism's pay grade (MEKO's torn
   text layer — a v049/`parse.py` outcome, "等 v049");
3. **nothing got worse** — the adoption gate, the null rule and the `_stated_zero` guard all held
   in production, so the switch is safe to flip later without re-proving safety.

Kept: the flag, the offline cases (red→green), the subset schema, the harness. A future lane
should re-draw this evaluation after v049 lands (the only trigger is blocked there) or against a
draw selected for *current* quote-shaped failures rather than stored ones.

## Findings

1. **The 0.25 class has migrated.** Under the current base, most stored "quote not found /
   computed" companies fail on the *value* side (computed sums) with quotes that verify — the
   expensive open lever there is not provenance but HANDOFF's `find_tables()`/column-aware
   `parse.py` (v049), which is also the only thing standing between MEKO and its real 768.
2. **MEKO p.103 is a named v049 casualty** (recorded above with the exact page and row, per the
   work order's "记下哪几家").
3. **The guard composition works**: v050's `_stated_zero` fields are provably safe from this
   mechanism (Creades ran the composition live — 0 kept, check ok, retry suppressed).
4. No provider errors occurred; nothing needed path-masking, and the harness masks before disk
   writes regardless (no owner-identifying string reaches this directory through a warning path).
