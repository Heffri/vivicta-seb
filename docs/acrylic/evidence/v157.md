# v157 — prefer self-proving borrowing-note citations

## Decision and scope

This change adds one final, deterministic provenance pass for `debt_maturity` only.  It does not
change field values, units, periods, raw labels, schemas, locator rules, or stored KB data.  The
supervisor selected the conservative variant after the broader literal rule projected an A-bucket
regression (8 to 15): a replacement row must both print the existing value literally and be a
`_label_known` row **on a page whose title matches the schema keywords**.

The pass is asymmetric and stable:

* A field with no value is ignored.
* A quoted, non-derived citation moves only from a non-note page to that self-proving note row.
  A known-label citation on a non-note page may make the same move; two note-page citations do
  not displace one another.
* A derived/unprinted citation may move only to a literal, known-label, schema-keyword note row.
  `value_derived` is removed only after that literal row is selected.
* Small numeric values use a stricter token boundary, so `0` cannot be justified by `0.8`.
* The final normal `score_field` pass still runs after the source swap, so its provenance evidence
  remains consistent with the selected page.  No value is recalculated.

The emitted warning is deterministic and names the old page, new page, field, and whether the old
source was a balance-sheet/prose source or a derived source.

## Reference check

The UAW tree was inspected before implementation.  `src/annual-report/extract/note-slice.ts`
limits a note slice, and `src/annual-report/extract/parse-and-check.ts` verifies a quote within that
slice.  Neither contains a reusable competing-citation preference rule.  The local adaptation uses
this pipeline's existing `_label_known`, `_schema_keyword_in_title`, `_page_title_blocks`,
`locate.HEADING_CHARS`, `_page_rows`, and `quote_on_page`; no UAW code was copied.

`test_note_citation_preference` now covers:

   with the value unchanged and the exact warning asserted.
2. A Boozt-shaped derived `due_within_1_year`: the literal note row replaces the derived source,
   removes only `value_derived`, and preserves the value.

All assertions are frozen text fixtures, not mutable KB fixtures.

### Why the other seven A rows remain unchanged

Each expected page is in the locator window; the conservative rule declines it for a specific,
observable reason:

| Record | Why no replacement occurs |
| --- | --- |
| `ework_2025.total_debt` | Page 70 has a keyword title, but none of its rows carrying the value is a known `total_debt` synonym. |
| `boozt_2025.total_debt` | Page 108 has neither a schema-keyword title nor a known `total_debt` row (`Total` is not a schema synonym). |
| `fm_mattsson_2025.total_debt` | Page 141 has a keyword title, but its matching `Per 31 December` row is not a known total-debt label. |
| `scandi_standard_2025.due_within_1_year` | Page 102 has no schema-keyword note title and its matching current-leasing row is not a known bucket label. |
| `hexatronic_2025.due_within_1_year` | This is derived/unprinted, but page 114 lacks both the self-proving keyword note title and a known bucket row. |
| `attendo_2025.total_debt` | Page 101 has a keyword title, but its matching `Total`/`Closing balance` rows are not known total-debt synonyms. |
| `powercell_sweden_2025.total_debt` | Page 50 has a known `Total borrowings` row, but lacks a schema-keyword note title; the existing source is also a known row. |
