## The rule (one sentence)

In the bucket-column write path, once the header parse + column-count safety valve has selected the debt row, a
bucket whose every column on that row prints a dash (`–`/`-`) is the report's explicit "no debt is due in this
window" (v036's own nil convention, one level down) — that bucket is written as 0 with evidence
`quote_on_page` + `printed_nil`, raw_label/quote taken from that same row; a bucket the table prints no column
for at all, a cell the row does not print, and rows the candidate walk never selected all keep today's null.

## Why the v076 lane left it, and what closes it now

v076 filled `due_within_1_year` by column order and proved the arithmetic closes (156,409 + 0 + 0 vs 156,410),
but left the dash buckets null because their own column headers ARE printed in the table — so `_check`'s
v041/v058 null-bucket guard (a null bucket whose label is visible in the operands' own table is unproven, not a
zero) refused the zero-fill and the check read `missing: due_1_to_5_years`. Lifting that inside `_check` would
have weakened a guard other companies depend on; the honest place to close the gap is upstream of the check
entirely: a dash is not "unprinted", it is a printed nil. The translation therefore lives only at the
bucket-column write site, and `_check` never sees a null bucket here at all — the value is a real, quoted 0.

## Two gates before a dash says 0

1. **The row must print a total** (`total` slot among the header's keys, carrying a figure) for the buckets to
   close against. A row with no readable total anchors nothing.
2. **The row's own arithmetic must close**: the real (non-dash) buckets summed against that total, within the
   check's own ±2, with the dashes read as 0. Ework: 156,409 vs 156,410, off by 1. A total sitting alone over
   dash columns ("Total 1,596 - - -") proves the opposite of nil buckets — a misparsed row, not a zero-debt
   report — and leaving those dashes null keeps the honest `missing` instead of a manufactured hard failure.

Both gates are computed from the row's own `derived` figures (the same values the `over` valve already judges),
so a dash-zero is never written on a row the page itself does not vouch for. A model answer of 0 that agrees
with a dash column still skips the write (agreement tolerance, unchanged), so a stored 0 keeps its own evidence.
