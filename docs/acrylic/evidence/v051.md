### The fix: `_between_rows`' row-derivation rescue reaches a second, later drop site

**Root cause, traced with a hand-built repro (`_between_rows` called directly, then the whole
`extract()` pipeline, then the failing call site pinned with temporary `print()`s, all removed
before commit):** MedCap's model quoted the two real printed rows concatenated as one string —
`"6 månader eller mindre 54,3 41,8 – – 6 – 12 månader 48,0 19,0 – –"` — not a fabricated arithmetic
expression (the shape v052's own existing test already covers, at `test_confidence.py`'s prior
end-to-end MedCap case). `quote_on_page` verifies this: both rows really are contiguous on the page.
The pipeline's own "recover the full printed row" step (`next(r for r in rows if quote_on_page(
verified, r))`) then finds this 2-row blob is a *suffix* match against the row `"6 – 12 månader..."`
alone (the whole-quote-first, then-shorter-suffixes algorithm in `quote_on_page` — see its own
docstring), silently truncating the field's quote to just the second row. The field survives the
first per-field gate non-null. Once `due_within_1_year=102.3` is itself numeric, it counts toward
`_check`'s own missing-operand detection — which (correctly, per v044/v052's own present-label
refinement) reports `"missing: due_after_5_years"` instead, because `>5år`'s header is printed on
the *other* (contractual) candidate page. The existing `"missing:"`-driven repair loop
(`_between_rows`, the mechanism v052 built) therefore never even looks at `due_within_1_year` — it
only acts on whichever field the check calls "missing", and due_within_1_year no longer is one. The
field reaches a **second**, later, unrelated drop site (the "Sectra: net sales minus goods for
resale" pattern, an older, general "quote_on_page passed but this exact value isn't literally in it
or nearby" gate) with no rescue attached, and is dropped there — same final warning text
(`"...dropped as computed, not read"`) as a plain unverifiable quote, which is why this looked
identical to the already-covered case until traced with real field states.

**Fix (`backend/pipeline/extract.py`, the Sectra-pattern loop):** before that second drop, if the
field participates in an identity check, try the *same* `_between_rows` rescue the first drop site
already uses — with the field's own (about-to-be-dropped) entry excluded from the operand search
first (without this, `_between_rows`' own idx search picks up the field's own truncated single-row
quote as a same-table "operand", making `top` its own row instead of the sibling operand's row, and
the window search then looks in the wrong direction and finds nothing — caught by first getting a
*negative* result with the naive version, then fixing it). No change to `_between_rows` itself, to
`_derived_value`, to `_stated_zero`, or to any other call site — one more entry point into an
existing, already-verified mechanism.

**Verification (no model calls):** hand-built `extract()` replay with the exact raw values above,
baseline (`origin/acrylic`, unmodified) vs. worktree — **red**: `due_within_1_year None@0.0`,
warning `"...dropped as computed, not read"` (baseline, matches the live run exactly); **green**:
`due_within_1_year 102.3@1.0`, evidence `["quote_on_page", "value_derived", ...]`, warning
`"...'6 månader eller mindre 54,3 41,8 – – 6 – 12 månader 48,0 19,0 – –' sums to 102.3 and closes

### zero_if_stated vocabulary gap — 2/10 companies this seed, precisely bounded

Both Vicore Pharma (*"...not exposed to risks related to external loan financing"*) and BioGaia
(*"The group has no external loans."*) are genuine, unambiguous no-debt statements that `_stated_zero`
declines: its gate (e) requires the sentence to contain one of `schema["keywords"]` or
`total_debt["synonyms"]` verbatim, and neither sentence contains any of `"borrowings"`, `"loans and
borrowings"`, `"interest-bearing liabilities"`, `"total loans"`, etc. — only the bare word `"loan(s)"`,
which the schema never lists standalone (by design: `"loans and borrowings"` is a phrase, not a
stem). Confirmed this is the exact reason (not a bug) by reading `_stated_zero`'s own gate order: (a)
opt-in, (b) value==0, (c) digit-free quote, (d) verbatim on page, **(e) subject-naming — fails
here**, (f) negation word (`"not"`/`"no"` are both in the schema's own negation list — this gate
alone would have passed both). Both land on the older, pre-v050 "printed zero nearby" path instead,
capped at 0.25. Not fixed: widening `total_debt`'s own `synonyms` to include a bare `"loan"` stem
would also loosen `_label_known`'s row-matching (a much broader surface — e.g. any row literally
titled "Shareholder loans" or "Related-party loans" would newly count as a recognised total_debt
label), and `_stated_zero`'s own vocabulary gate is not separately parameterised from the label
vocabulary (the work order's territory excludes changing `_stated_zero` itself). Two real companies
in one ten-company seed draw hitting the identical, precisely-named gap is a stronger signal than a
single anecdote — recorded for the group as a candidate for a `_stated_zero`-only, better-isolated
vocabulary parameter (out of this lane's territory to build).
