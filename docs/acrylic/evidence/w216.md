## 3. OCR ships in the package and works on a real image-only report

**Settings shows no language-pack/OCR status indicator.** The work order expected "Settings 能看到
语言包状态"; this does not hold — confirmed by grepping the whole `frontend/src` (no `tessdata`,
`language pack`, or `OCR` string anywhere in `SettingsView`/`ExtractionSettings`) and by the live
Settings → Extraction tab text (`Maturity basis / Two-run merge / Deep search for missing figures`
— no OCR/language field). `GET /api/config` likewise has no OCR key. Not a bug to fix — DEMO.md
itself never claimed a Settings indicator, only that the files ship; this is a work-order premise
that didn't hold, noted rather than silently worked around.

**The functional OCR path does work.** Downloaded Saab's real English FY2025 report directly from
its `meta.json` `source_url` (`storage.mfn.se`-style public link) — 231 pages, image-only (no text
layer), 66,505,758 bytes, **sha256 `4e0724e9…34ba2` matches `data/kb/saab_2025/meta.json` exactly**.
Uploaded it through the downloaded package's Extract → Upload PDF (fresh `--user-data-dir`, fixture
mode). Whole-book classification (`w204`) bounded the OCR pass to **8 pages** (not all 231); the
batch row reached **Done** in **269.4 s** with no `OCRUnavailable`/missing-language error at any
point. `resources/tessdata/{eng,swe}.traineddata` are present in the extracted package at the exact
byte sizes committed in the repo (4,113,088 / 4,167,034 bytes) — bundled, not fetched at runtime.
Screenshots: `w216/ocr-01-picked.png`, `w216/ocr-02-final.png`, `w216/settings-extraction.png`.

(This machine finished Saab in 269 s versus `docs/DEMO.md`'s recorded 506 s for the same report —
noted, not investigated further; still well inside "don't do this live on stage" territory either
way, and not a regression to chase since nothing in this lane's diff touches OCR.)

## 4. Downloaded package vs. a fresh local build — no CI/repo drift

Built locally from this exact checkout (`dfce54f`): `backend/build_exe.py` (PyInstaller,
`backend/dist/backend/backend.exe`, 104 MB onedir) → `frontend/npm run build` → `desktop/scripts/
prepare-resources.js` → `npx electron-builder --dir` (the documented plain "Packaged mode" flow in
`desktop/README.md`, not `release-config.cjs` — that requires `RELEASE_CHANNEL`/`RELEASE_VERSION`
and is CI-only). Result launched cleanly with its own `--user-data-dir`:

| | Downloaded `desktop-main` | Local build (`dfce54f`, plain `--dir`) |
|---|---|---|
| `/api/kb` | 200, 206 entries | 200, 206 entries |
| `/api/config` | `fixture/fixture/false/…` | byte-identical JSON |
| `resources/tessdata/{eng,swe}.traineddata` | 4,113,088 / 4,167,034 bytes | same sizes |

No drift found. One harness caveat, not a product issue: my local `--dir` invocation left
`CSC_IDENTITY_AUTO_DISCOVERY` unset (CI sets it to `false`), so electron-builder ran `signtool.exe`
against whatever is in this shared machine's cert store during the local build only; the CI-built
release itself is built with signing auto-discovery explicitly disabled, matching
`desktop/README.md`'s "does not code-sign anything" limitation. The local exe still launched and
behaved identically, so this didn't affect the comparison, but it means the local build isn't a
100%-identical CI reproduction — noted for whoever repeats this.

## 5. No portable/zip artifact ships anymore — 7-Zip extraction used instead

`desktop/electron-builder.yml` still defines both `nsis` and `portable` targets, but
`.github/workflows/desktop.yml` only ever builds `--win nsis`; the release has exactly 3 assets
(`.exe`, `.blockmap`, `latest.yml`), no portable exe. This matches `37f31aa`'s own commit subject
("publish a **single** self-contained build") and `desktop/README.md`'s "Automatic updates" section,
which now only documents the installer route — this looks intentional, not an oversight, so it is
**not** reported as a problem, just as the reason the common-instructions' "portable/zip, no NSIS
install" guidance no longer has a portable option to use.

Extracted the downloaded `.exe` with the `7za.exe` already cached on this machine at
`%LOCALAPPDATA%\electron-builder\Cache\7zip@1.0.0\...\7za.exe` (NSIS installers built by
electron-builder are themselves 7z archives) — this pulls out the full unpacked app (949 files, 463
folders) with **no installer code ever executed**: nothing written to Program Files, no registry
uninstall entry, no Start Menu/Desktop shortcut, nothing outside this lane's own
`uaw-lanes\w216-release-final\` directory.
