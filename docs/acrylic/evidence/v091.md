## The answer to Kristian's open question

**"Prior year alongside current, or current only?" is now the analyst's choice, per the 09-18 ruling.**
The backend returns the prior fiscal year's own four figures as top-level `prior_year` metadata exactly
when they can be read deterministically from the same table as the current year and reconcile on their
own; the chart shows them beside the current bars behind a "Show prior year (FY2024)" switch (default
off = the exact pre-v091 rendering), and the PPT export gains the matching `FY2023`-style series behind
the same switch (`?prior_year=1`). One sentence for Kristian: *the prior year now rides along whenever
the report's own prior-year column or twin row can be read and its buckets reconcile to its total —
otherwise the view stays current-only rather than guess.*

## The two deterministic reads (both follow the live basis — same table, same total slot)

- **(a) buckets-as-columns** (`_fill_bucket_columns`'s recorded pick): the same-labelled row of the
  prior year's own block on the same page — Tången p.62 stacks whole "31 december 2025"/"31 december
  2024" tables with identical row labels, Ework p.70 stacks "2025"/"2024" blocks — proven prior-year by
  `_bucket_row_prior_year` (v066/v076), lined up with the SAME `col_keys`, read through `_bucket_assign`.
  A bucket whose prior-year cells all print dashes is the report's explicit 0 (v078's convention, one
  year back); a second same-labelled candidate (or none) declines.
- **(b) buckets-as-rows**: the prior-year COLUMN of the very rows that supplied the current values
  (MedCap p.101's "Koncernen Moderbolaget / 2025-12-31 2024-12-31 2025-12-31 2024-12-31" header names
  the Group's prior-year column). Each field admits only when the fiscal-year column of its own quoted
  rows reproduces its current value (the `_column_values` admission), derived quotes (`_between_rows`,
  `_finer_split_rows`) resolve to their contiguous row range, all admitted fields must share one header
  (page, fiscal column, prior column, column count), and the prior column comes from the same
  nearest-run walk `_row_year_column` uses — with `_row_year_column`'s own answer as the divergence
  guard. A date-per-instrument note (Proact) has no year header on its instrument rows, so it never
  admits; a model-only answer has no printed row to mirror.

**The gate** is the schema's own identity on the prior year's EXPLICIT values — the shipped
`require_explicit_values` rule applied to FY-1: the key is written only when `total_debt` and ≥2 buckets
were read and they sum to the total within the check's own ±2. A bucket whose prior-year figure the
table does not print is absent from `fields` and named in `check.detail` (never zero-filled — and a
missing bucket that would have mattered breaks the closure, which is the point). `check` reads like
`_check`'s own output: `"… == total_debt (±2 rounding) | abs((60.8 + 316.7) - 377.6) <= 2
(due_after_5_years: no prior-year figure in this table)"`. Failing any part → no key at all, not null.

## Deviations from the work order's letter (each verified, listed for the supervisor)

1. **The frontend `prior_year` type lives in `types.ts`, not `api.ts`** — the work order names `api.ts`
   "类型:顶层可选 prior_year", but `Extraction` is defined in `frontend/src/types.ts` (api.ts only
   re-imports it). One optional `PriorYear` type added there; `api.ts`'s change is the `pptxUrl` flag.
2. **ResultsView.tsx needed three lines, not one** (a mirrored `useState`, the `onPriorChange` prop on
   `<MaturityChart>`, the flag into `pptxUrl`): the Export PPTX anchor renders its href at render time,
   so the toggle (which lives in MaturityChart per the territory) must notify it — a bare localStorage
   read would serve a stale href. The work order's "仅当…改那一行" clause anticipated this line might
   change; the state plumbing is the minimum that makes it actually react.
3. **MedCap's prior year carries three values, not four** — its carrying table prints no >5y row for
   either year. Under the work order's own explicit-values gate this is the only honest shape; the
   absent bucket is named in `check.detail`. (Tången and Ework carry all four.)
