merged forward once to pick up `origin/ao/vivicta-seb-97/v177-targeted-field-fill` after it landed on

## What changed

**Backend — `GET /api/reports/{report_id}/pages/{n}/locate?quote=`** (zero-model). `page.search_for`
on the verbatim quote first; a citation that never prints as one contiguous run (a wrapped table row)
degrades to its own longest line, then to the longest digit run inside it. `rects` are page-point
boxes, the same top-down space `pages/{n}.png` renders.

A real measurement changed the response shape mid-lane: PyMuPDF reports a match spanning two printed
lines as **two adjacent rects** — exactly the same shape a genuine second, unrelated occurrence would
add two more of (measured directly: a 2-line phrase printed twice returns 4 rects, not 2). Naively
badging "N matches" off `len(rects)` would have made an ordinary two-line-wrapped citation cry "2
matches" every time. The endpoint now also returns `occurrences`, which divides `rects.length` back
out by the searched text's own line count, so a wrapped citation reports `occurrences: 1` (still
drawing 2 rects) and only a truly repeated line reports 2+. The frontend badge reads `occurrences`,
not the rect count.

**Frontend — `results/PageLocateOverlay.tsx`** (new): Image-mode overlay, absolutely positioned over
the `<img>`, drawing every rect scaled by the page's own point size; a "N matches" badge (reading
`occurrences`) when a line is genuinely repeated. Silent on no match / no PDF / a failed request — no
console noise. **`results/StoredPageText.tsx`** (new): the no-PDF saved-text view now scrolls to and
highlights the cited quote's own line (normalized whitespace match against each saved line); a line
printed more than once gets a "1/N ▸" cycler; a quote that never appears verbatim still shows the
full page, with a note. Both are keyed by page+quote from `SourcePanel` so switching fields/pages
resets their state via remount rather than a synchronous reset inside an effect (avoids an
oxlint `set-state-in-effect` warning and a subtler stale-closure edge case).

**OCR marking**: `FieldsTable`'s verification column and `SourcePanel`'s top block both show "From
OCR — check the scanned image" for a field whose `evidence` includes `ocr_text` (the backend has
carried this code since v072/`_run_extract`; nothing in the UI surfaced it before now).

**Component citation links**: each entry in a human-reviewed field's `components` list (v172) now
gets its own "p. N" link, wired through a new `onOpenPage(key, page)` prop on `FieldsTable`/
`ResultsView` that reuses the existing `askPage` override — the same mechanism an Ask citation chip
sets — rather than inventing a second "jump to a page" concept. Known imprecision: `SourcePanel`'s
existing askPage banner text ("Page N, cited in an answer below") is reused verbatim for this case
too, which is not literally true for a component citation; left as-is rather than forking the copy,
since `ask.spec.ts` asserts that exact string and this is a cosmetic nit, not a functional one.

**Fixed a shared e2e fixture bug** (`frontend/e2e/fixtures/make-pdf.ts`): its `T*` line-advance
operator was emitted *after* each line's `Tj`, not before, so a multi-line `pageTexts` entry drew
every line but the first on top of its predecessor — `get_text()` on the generated PDF returned the
two lines concatenated with no separator at all, at one bbox. No existing spec had ever passed a
multi-line `pageTexts` string before this lane, so the bug was latent. Verified with a throwaway
PyMuPDF inspection (`get_text()`/`search_for()` on the generated bytes) before and after the fix.

## Red → green (three separate observations)

- **Endpoint existence**: renamed the route to a dead path, re-ran `test_workbench.py` — the 6 new
  assertions failed with `404 Not Found` at the first `locate()` call. Restored the route name — all
  passed.
- **`occurrences` divide-back-out**: temporarily replaced `occurrences = len(rects) // lines ...`
  with the naive `occurrences = len(rects)` — the two new two-line-citation assertions failed
  (`once['occurrences'] == 1` got `2`). Restored the real computation — passed. This is the change a
  naive first implementation would have shipped with; measuring it directly (rather than assuming
  PyMuPDF returns one rect per logical hit) is why it didn't.
- **e2e, before the `make-pdf.ts` fix**: the "same line twice" page returned 1 rect instead of 2 (the
  T* bug drew the second occurrence's second line on top of its first line, so PyMuPDF's own text
  extraction saw one merged line, not two identical ones) — confirmed and root-caused with a
  standalone PyMuPDF inspection of the generated PDF bytes before touching the fixture. Fixed, full
  suite re-run green.

## Not settled / follow-ups

- The askPage banner copy reused for a component-page jump ("cited in an answer below") is not
  literally accurate for that call site; a real fix means forking the banner text by call site, which
  touches `ask.spec.ts`'s exact-string assertion — left as a cosmetic note, not fixed here.
- Line-matching in `StoredPageText` is whitespace-normalized substring containment, not the same
  regex-based value extraction `highlight.ts` uses; the two intentionally serve different jobs (find
  the *line*, vs. find the *value inside* an already-shown quote) and were kept separate rather than
  unified, to avoid coupling two call sites that may want to diverge later.
- The overlay's "N matches" corner badge is a fixed top-right position regardless of where the boxes
  actually are; fine at 1440px, untested at very narrow widths.
