## BM25

Okapi BM25, pure Python (`collections.Counter`, no new dependency): k1=1.5, b=0.75, Lucene-style non-negative
idf `ln(1 + (N - df + 0.5)/(df + 0.5))`. Tokenisation = the old `_tokens` rules but keeping counts
(`_terms`/`_bag`): digit/letter-edge split, stop words dropped, 7-char prefix stem, **bag not set** (term
frequency now matters). Per-stem in-memory inverted index (`_bm25_cache`: term → [(chunk, tf)], chunk lengths,
the chunk rows), invalidated by pages.jsonl/extractions mtimes exactly like `_vecs` — zero disk files.
**IDF/N/avgdl are computed over the chunks of the stems the query names**, so a two-report Compare is one
corpus, per the work order. Hybrid blend: each signal min-max-normalised over the current candidate pool
(flat signal → 0, no fake spread), 0.6 cosine + 0.4 BM25; the 0.6/0.4 start point is kept as dispatched (see
"Not done" — no offline way to tune the cosine weight). Replaces `0.15 * token share` in the ranking.
Reported hit `score` stays 0..1 in both real states (bm25 mode returns the min-max-normalised score; `ask()`'s
`min(score, 1.0)` clamp kept). The ride-along of the 2 best label-matching extraction facts per report
(`start == -1`, share > 0) is kept in both states; `ask()`'s verbatim-quote citation verification untouched
(tested).

## Offline eval (zero model) — before vs after

Corpus: every committed extraction with `source.page` — 101 `income_statement` stems from `data/kb/` + all 42
`debt_maturity` stems from the four shared seed-KB dirs (the work order said ~40; there are 42) + Ericsson's
`debt_maturity` in `data/kb/` = 43. Query per field: the schema label, plus the first schema synonym that
verbatim occurs on the field's own page (case-insensitive); queries that coincide after tokenisation
("Revenue"/"revenue") are deduplicated; fields with no occurring synonym are skipped as label-only (59 of
income_statement's, 41 of debt_maturity's — debt buckets like "1–5 år" rarely print verbatim).
1145 + 77 queries. **before** = the shipped ranking until now with the cosine term held at 0 (share-only,
same `nlargest` + same ride-along), replicated in the eval script because the real `search()` cannot run
without embeddings; **after** = the shipped `kb.search()` in this env (no `LLM_*` set → same code path as bm25
mode; only the hybrid branch differs). Script: lane scratch dir outside the repo (`uaw-lanes/<lane>/eval_bm25.py`,
path masked per the standing rule); it only ever reads `data/kb` and the seed dirs.

Hit = a chunk from `field.source.page` inside top-k. "any" = any chunk from that page (what /ask's excerpts
surface; production-faithful). "window-only" = page-window chunks only (`start != -1`), isolating page-text
retrieval from fact chunks.

## EMBED_MODEL invalidation

`embeddings.jsonl`'s **first line** is now `{"embed_model": "<model>"}`; `_rows` skips it (chunk rows are the
ones with `"text"`), so the format stays one-JSON-per-line and chunk counts are unchanged. `index()` treats
"file without the meta line" (all pre-existing files) as needing exactly one rebuild, and a recorded model ≠
current `embed_model()` as a full rebuild that also skips the text→vec reuse map (vectors from two models must
never share a cosine space). Changing `EMBED_MODEL` then re-indexing re-embeds everything and rewrites the meta
line. Verified by unit test with a fake deterministic `embed()` (token-hash vectors) — this machine has no
embeddings endpoint, so the hybrid branch's real-embeddings path is exercised **only through the fake**, stated
here per the work order; the call-count assertions prove cache/rebuild behaviour, not vector quality.

## Findings

- **CHUNK/OVERLAP interaction (record-only, per work order)**: page windows split a page into ~800-char
  windows with 100 overlap; for compact statement pages this puts label+figures in one chunk, but for wide
  tables (SAAB's letter-spaced pages, Nelly's vertically-interleaved labels — "N E L LY G R O U P … Räntebärande
  D O Leasingskulder") the printed row and its label can land in *different* windows, and interleave splits
  words at tokenisation ("Räntebärande" survives in Nelly's case only because the vertical letters happen to
  interleave with *other* columns). Smaller windows would raise BM25's label precision but split figures from
  labels more often; not changed here.
- **Fact chunks legitimately dominate top-1 in bm25 mode** (~70pp of the any-vs-window-only gap at hit@1):
  they are short, label-exact, and from the right page — this is the ride-along rule working as designed, now
  as the main ranking instead of an add-on. The verbatim quote is embedded in the fact chunk precisely so
  `ask()`'s citation check still finds it on the page.
- **Swedish questions against English reports score a flat 0** and return cover-page order (stable corpus
  order). Correct but unhelpful; a mixed-language corpus would surface it only as a weak answer, so a future
  "no chunk scored > 0 — try the other language?" warning in `ask()` could be worth a lane.
- **A systematic eval pitfall, caught and fixed before reporting**: schema label "Revenue" and synonym
  "revenue" produce the same query after lowercasing; without dedup the tables double-count identical queries
  (first run: 1413 income-statement queries; after dedup: 1145).
- The stale README claim that `/extract`'s gate "checks only LLM_BASE_URL" (v031-era text, superseded when
  `_llm_configured()` landed) is fixed in passing inside the rewritten embeddings paragraph.
