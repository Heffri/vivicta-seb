# w198 — deterministic full-text field sweep

Branch `ao/vivicta-seb-115/w198-fulltext-sweep`, refreshed from `origin/acrylic` after w196 and
w197 were integrated. The shipped w197 policy remains unchanged: `EXTRACT_SECOND_PASS` is off by
default and must be explicitly set to `1`.

## Change

When an opted-in w197 field retry still leaves a required field null, the pipeline now performs a
zero-model scan across the report's reconstructed `_page_rows`:

- the field vocabulary is the union of schema `synonyms` and `row_synonyms`;
- row labels use the existing `_label_known` normalization, including case, Swedish characters,
  ligatures, result/profit wording, and maturity-window digits;
- a hit must be a reconstructed row with a numeric tail, and one row contributes one hit even if
  several overlapping synonyms match it;
- pages rank by descending hit count and then ascending page number; only the best three pages not
  already tried by the locator retry are supplied to `extract(..., fixed_pages=True)`;
- metadata pages still marked `ocr_pending` are skipped and counted rather than treated as empty
  evidence.

The follow-up still passes the existing quote-on-page, value-in-quote, known-label, and debt-scope
guards at both extraction and write-back. An accepted field carries `second_pass` and
`fulltext_sweep`; a rejected reply remains null. The scan makes no model call itself. The opt-in
can make at most two fixed-page calls for each of w197's maximum three fields. The extraction cache
version is bumped so an earlier opt-in result cannot hide the new path.

## Red / green fixtures

The first targeted run was red with `AttributeError: module 'pipeline.extract' has no attribute
'sweep_pages'`. After implementation, the following six scan cases are green across three named
tests in `pipeline.test_confidence`:

1. AMD-shaped page 72 is found by `Net income` even though a higher-hit page was already tried;
2. uppercase Swedish `RÄNTEBÄRANDE SKULDER` matches `row_synonyms` through normal label cleanup;
3. an `ocr_pending` match is skipped and counted;
4. tried pages are never returned;
5. hit count, page-number tie-break, and the three-page cap are deterministic;
6. after a locator-window null, the selected sweep page is actually passed through the fixed-page
   model seam and accepted only with all existing evidence guards.

The final targeted set also includes all four inherited w197 cases: guarded fill, off-page quote
rejection, optional-null skip, and the three-field/off-switch cap.

## Real validation — Codex Terra

The live harness used `gpt-5.6-terra`, strict schema off, no few-shot data, merge off, and the
carrying debt basis. It read the three shared US PDFs and isolated held-out KB page text without
writing repository data. **13 actual calls** were made, under the 15-call cap.

After merging w196, ordinary one-call income extraction produced:

| report | `net_profit` | source |
| --- | ---: | --- |
| AMD FY2025 | 4,335 USD m | p.72, `Net income ... $ 4,335 $ 1,641 $ 854` |
| NVIDIA FY2026 | 120,067 USD m | p.139, `Net income $ 120,067 $ 72,880 $ 29,760` |
| Intel FY2025 | 26 USD m | p.66, `Net income (loss) 26 (19,233) 1,675` |

This is the intended complement: before w196 was stacked, the scan deterministically ranked AMD
p.72 first (`[72, 75, 76]`) while Intel had no synonym hit because its duplicated text layer still
needed w196's parser repair. With w196, all three are first-pass reads, so no sweep call is needed.

Five held-out null fields were then exercised one field at a time through the w197+w198 seam:

| report / field | scan pages after locator pages | result |
| --- | --- | --- |
| Annehem `due_within_1_year` | 81, 34, 66 | value 498.1 accepted from p.66 |
| INQ `total_debt` | 65 | value 27,889 accepted from p.65 |
| INQ `due_1_to_5_years` | none | remained null |
| Keo Capital `due_1_to_5_years` | none | remained null |
| Xspray Pharma `due_1_to_5_years` | none | remained null |

The two accepted values equal the frozen labels, so the value result is **2 filled / 0 wrong / 3
still null**. Both cite a real matching row on their supplied page, but the frozen labels name a
different page (Annehem p.85 and INQ p.41); exact value-plus-labelled-page scoring is therefore **0
fully correct / 2 page-only deviations / 3 still null**. This distinction is kept explicit rather
than calling an alternate, guard-valid citation a labelled-page hit. The scan did not send those
label pages because both were already locator candidates and the contract excludes pages already
tried.
