## The dominant failure mode: maturity buckets printed as *columns of one row*, not separate rows

4 of 10 companies (Cloetta, Bergman & Beving, XANO Industri, Ework Group) hit the exact same wall.
`extract.py`'s whole repair toolkit — `_derived_value`'s row-summing, `_column_values`'s per-year-column
cross-check, `_between_rows`'s missing-operand fill — is built around **income_statement's shape**: one
row per line item, N *year* columns, verified by making the arithmetic check hold in every column. A
debt-maturity note commonly prints the opposite shape: one row per debt instrument (or one "Total" row),
N *maturity-bucket* columns, one such block **per fiscal year** (not side by side). Concretely:

- `_year_column()`/`_year_run()` look for a `"2024 2025"`-style header to know which column is the fiscal
  year; a bucket table's header is bucket names, not years, so this returns `None` for these pages —
  every check-repair path that depends on it (`_column_values`, `_derived_value`'s "others" argument,
  `_between_rows`) bails out immediately, before it can even attempt anything.
- The schema (`value_convention`) asks the model to *sum* finer bucket splits itself ("a report with finer
  splits (e.g. 1-2y, 2-5y) should have its 1-5y bucket taken as the sum of those columns" — this is HANDOFF's
  own anticipated case). A summed value has no literal quote, so the "every number carries a verified
  quote" rule (non-negotiable) correctly drops it — the model is being asked to do something the
  verification layer can never accept.
- `_between_rows()` (the mechanism that *would* fill a genuinely-missing operand from the rows around it)
  requires the other operands to sit on *different* rows so it can find the rows *between* them; when all
  four bucket fields point at the **same shared row** (Cloetta, XANO), `min(idx) == max(idx)` and it has
  nothing between which to search.

This isn't fixable as a schema tweak (tried none — the schema's `value_convention`/field descriptions
already say the right thing, the model already tries to follow it) and isn't a quick `extract.py` patch
either, without either (a) teaching the row-derivation helpers a second, bucket-column-oriented mode
alongside the year-column one they have now, or (b) HANDOFF's own suggested path: split the schema into
finer bucket fields the model can quote verbatim (e.g. explicit sub-1-5y fields) and derive the
requested buckets in a check/post-processing step instead of asking the model to add. Both are a
genuinely bigger change than one seed's hardening pass, and (b) specifically touches `ppt.py`'s
`BUCKET_ORDER`/`BUCKET_LABELS` (per HANDOFF's own note on the only coupling), which is outside this
lane's territory. Flagging for the group rather than guessing at scope.

**Two-table (carrying vs. contractual) note:** none of the 10 companies show HANDOFF's/v008's aak-style
*wrong-table* selection this seed — the borrowings/carrying-amount table was always the one either
picked (Cloetta, Bergman & Beving, XANO Industri, NCAB, Apotea) or entirely un-candidated (Better
Collective), never a liquidity-risk page winning over a real borrowings page. Ework Group is a partial
exception (used the "undiscounted cash flows" table where a "carrying amount" table existed nearby),
but the two totals happen to be numerically equal there, so it didn't affect the value, only which page
gets credited. Two tables (carrying/contractual): **10/10 didn't visibly mis-pick** — different failure
mode dominates this seed.

## Not fixed, and why (recap)

- **Cloetta, Bergman & Beving, XANO Industri, Ework Group** — the bucket-as-columns architecture gap
  above. Needs an owner/group decision on which of the two directions (teach extract.py a second
  column-orientation, or split the schema + touch `ppt.py`) before any lane should spend calls on it —
  guessing at scope here risks exactly the kind of company-by-company patching the work order bans.
- **Flat Capital** — not a bug. Genuinely no interest-bearing debt at the reporting entity; no note to
  extract.
- **Better Collective** — locator gap already tried and reverted in `v017.md` (bare `maturity`/`maturities`
  keyword, net negative on the full corpus). Not re-attempted.
- **Apotea's `due_within_1_year`** — left at 0.9 on purpose; the only label available (`"Overdraft
  facility"`) names a debt instrument, not a maturity bucket, and generalizing from one company would
  repeat the instrument-vs-bucket-label confusion that's already the dominant problem.

## For the group: which failure type is most common

**Bucket-as-columns (4/10)**, clearly — not locator misses, not missing synonyms, not the aak-style
two-table trap the earlier lanes chased. Suggest the next hardening round either (a) gets an owner
decision on HANDOFF's own fork (schema field split + `ppt.py` touch vs. a new extract.py repair mode) before
spending more seeds on debt_maturity, or (b) is scoped to explicitly exclude bucket-as-columns companies
and keep collecting locator/synonym wins like NCAB/Apotea's, which are cheap, safe, and don't need a
product decision first.
