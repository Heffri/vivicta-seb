## What changed

- `backend/pipeline/extract.py` — `_fill_bucket_columns`: when a valve-passing bucket-column pick's
  parsed header maps fewer than all three bucket windows (no column of its own, no off-grid column
  spanning it whole, model answer null), the missing bucket keeps `value: null` but records
  `evidence: ["absent_in_table"]` and `source: {page, quote: <header row>}`, plus a warning naming
  the header. Bucket-column shape only: the marking lives on the pick no row-shaped or prose
  reading ever produces. `_check`: under `require_explicit_values`, an `absent_in_table` operand
  joins the identity as 0 — the same participation `null_as_zero`/`stated_zeros` get — but only
  while no other operand is still an unanswered null (that one keeps its `missing: <field>`
  verdict; a proven absence must not tip a check missing something else into a pass).
- `backend/pipeline/workbench.py` — the same participation in the review flow: an
  `absent_in_table` bucket no longer holds the reconciliation "unavailable" (it joins as 0), and
  `decorate` stops listing it as a field issue — a reviewer marking it unresolved re-opens it.
- `frontend/src/components/results/verification.ts` — new secondary label **"Not printed in this
  report"** (an explicit absence, not a missed figure and not zero); `types.ts` and `docs/API.md`
  document the evidence code; `frontend/e2e/tests/verification.spec.ts` asserts the label/variant.
- `frontend/src/components/results/MaturityChart.tsx` — the dashed empty slot is labelled
  **"not printed"** (aria-label and tooltip say it too); never a zero bar.

Untouched on purpose: schema vocabularies, locate, data/, every row-shaped and prose path, and the
review UI's own components (only the queue's judgment input changed, in `workbench.py`).

Red case built on a real page: Ependion's contracted-terms maturity table (p.155) prints
`Within 12 months / Between 1 and 2 years / Between 2 and 3 years / Total` — no after-five-years
column exists. The stored `data/kb/ependion_2025` extraction is the red state verbatim:
`due_after_5_years` null with empty evidence, check `missing: due_after_5_years`.

- Red: with `backend/pipeline/extract.py` + `workbench.py` checked out from `origin/acrylic`, the
  new test fails at `assert absent["evidence"] == ["absent_in_table"]` (got `[]`), and
  `backend/test_workbench.py` fails at `assert all(c['passed'] and c['status'] != 'unavailable')`
  (got `status: unavailable, Missing explicit values: due_after_5_years`).
- Green: with the branch's own code both pass — value stays null, evidence is
  `["absent_in_table"]`, source quotes the header row `Between 2 and 3 years Total`, the warning
  reads `due_after_5_years: the maturity table on page 1 prints no column for this window
  ('Between 2 and 3 years Total'); not printed in this report`, and the identity passes as
  `167546 + 415984 + 0 == 583531` within the check's own ±2.
- The test's further cases pin the boundaries: a printed dash column keeps v078's rules (no 0
  without the row's own arithmetic, no `absent_in_table`); with another operand still an
  unanswered null the verdict stays `missing: <that field>`; a row-per-bucket note (no column
  header to cite) is never marked.

## e2e kb.spec failures are pre-existing (checked, not assumed)

The 6 failures are the `kb.spec.ts` smoke tests (filter "atlas" → Open, Wallenberg collection
switch, no-PDF open; both tones). They fail at `expect(heading /reports/)` — the regex only
matches the *loaded* heading ("206 reports · …"), and `GET /api/kb` now takes ~2.6 s warm / ~12.5 s
cold for 206 stems (it re-reads every stem's meta twice per call), which with the rest of the
page-load sequence exceeds the test's 5 s budget on this machine.

Proven pre-existing: a detached worktree at the pristine `origin/acrylic` with its own backend and
dev server fails the exact same tests (the single-test run reproduced 2 failed / 1 passed, the
backend log shows the same multi-second `/api/kb`), and an isolated run against a 1-entry KB fails
them for the matching reason (no atlas row / no Wallenberg set / no "no PDF" row there). v165's
diff touches neither `app.py`/`kb.py` nor `KbView`; the fix belongs to whoever owns the KB route
or that spec (cache the entry list, or await the loaded heading in the test).
