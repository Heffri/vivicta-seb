merged forward to `origin/acrylic` `eced695` before delivery (that merge carries v148's sol/terra
evidence and one new stored extraction: sdiptech's `due_within_1_year`, which is why the bucket is
**39 rows / 28 companies at dispatch and 38 / 27 on the delivered tree** — sdiptech left A because

every observation reads stored KBs, `eval/labels.csv` and `pages.jsonl` offline.

Changed only this evidence file, its `v150/breakdown-debt_maturity.md` artifact (the tool's own
output on the delivered tree), and nothing else. **No `extract.py` change: the work order's premise
— that some of the 39 nulls are guards having dropped the label value — is overturned by the row
audit. All 7 guard/repair actions in these rows' warning trails rejected values that are NOT the
label values; the narrowest-exception search found nothing a relaxation could rescue without

Method: `scripts/eval_breakdown.py --stored-kb data/kb --section debt_maturity` gives the A bucket
(stored null on a scored miss). For each row this lane then read the stored extraction's full
warning trail, the label's own `labels.csv` annotation, and the actual `pages.jsonl` page texts of
the label page, the pass-1 window and the value's pages. Buckets:

- **M** — model did not answer: no discard record for the key in the warnings. Sub-split:
  **M-model** (the label value, or the prose/dash fact the label reads, is printed on the window
  the model was shown — it still answered null) vs **M-select** (label page is a candidate the
  pass-1 window never showed) vs **M-locator** (label page is not a candidate at all).
- **G** — a scope guard refused a page fill naming this key (v103 undiscounted / v111 non-debt /
  parent). Judged: was the refused value the label value?
- **R** — a repair was rejected: `column reading … declined/rejected` valves or v144's unclosed-row
  drop. Judged: was the rejected reading the label value?
- **S** — label convention: the label value is never printed as one figure (a sum of printed rows,
  or a prior-year/coincidental digit match) or only exists on the balance sheet in a shape the
  debt-note machinery does not read.

## Guard verdicts — why no exception is provable, and none was made

The work order asked for the narrowest relaxation wherever a guard dropped the label value, proven
by replay. The row audit found **no such row**:

- **G rows** (#8, 17, 38): each refusal names a fill whose figure differs from the label value
  (13,825 vs 13,439; 87 vs 192; 2 vs 67). Two of the three refused figures are values the label
  notes explicitly warn about (salix's 87 is v082's documented contract-liabilities misread;
  momentum's parent rows are v111's founding case). Relaxing v103/v111 here would write wrong
  values; the true pages were either never candidates (#8) or never selected (#38), and #17's true
  row was already on the shown page — the model just missed it.
- **R rows** (#23, 25, 26, 36): every rejected reading differs from the label value (3/2 vs 5;
  45,414/555,370 vs 135,382; 141,152/555,370 vs 32,052; 85,151 vs 3,741). The v103 undiscounted
  refusal, the over-valve and v144's unclosed-row gate each rejected exactly the mis-scoped reads
  they were built for (RVRC p.110, Acast p.65/p.68, MTG's torn lease row). In all four the label's
  true source is a page the candidate set never contains (#23 p.95, #25/#26 p.67, #36 p.118's BS
  subtotals / non-candidate p.148), so no column-reader relaxation can reach it either.

Zero guard changes therefore ship. `replay_check --section debt_maturity --baseline origin/acrylic`
over `data/kb` + the 17 shared seed KBs: **320 companies, 320 same, 0 changed, 113 not_replayable
(pre-existing)** — byte-identical totals before and after the delivery merge, as expected for a
lane whose only writes are documentation.

## Recommendations

1. **v146 (page selection): 23 of the 39 rows never had the label's page in the pass-1 window** —
   18 M-select + 5 M-locator. Sixteen of those 23 label pages ARE in the deterministic candidate
   set and were simply outranked (e.g. ovzon picked the undiscounted profile over the carrying
   note; viva_wine's selection failure fell back onto the page the label itself declines). A
   pass-1 that prefers carrying-amount wording over "non-discounted / contractual / nominal"
   wording on equal keyword evidence is the single largest lever here.
2. **v148 (model): 7 rows had the fact on the shown window** (6 after the sdiptech fix): three are
   prose facts (svolder's unused credit line, ratos' "amounted to SEK 4,126m"), one a dash-nil the
   model left null (byggmastare "år 4 -"), three literal table figures (ctt 35.5, bioinvent 1,157,
   oresund 4,002). A prompt/second-pass nudge toward "a stated nil or a prose total is an answer"
   addresses these without touching any guard.
3. **Repair gaps recorded, out of this lane's territory** (both are M rows, so no exception was
   provable): bico #28 — v110's subtotal-pair walk dies on the torn 4-column header whose orphan
   fragment years read as a 2-column run; ctt #5 — the bucket-column reader's header matcher has no
   way to rejoin a torn header ("Within 1" / "Later than" split across `_page_rows` lines). Both
   pages are otherwise clean, selected, and carry the label values.
4. **Re-publish: nothing to re-publish for score.** Replay is 0-changed on all 18 KB copies; the
   only rescued row (sdiptech) was already re-published by v148 on `acrylic` before this merge.
