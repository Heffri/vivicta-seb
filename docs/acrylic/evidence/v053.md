# v053 — `scripts/replay_check.py`: the stored-extraction replay (baseline vs worktree `extract.py`) as one repeatable script, zero model calls

Lane `ao/vivicta-glm-15/v053-replay-check`, off `origin/acrylic` (merge `9497e12`). **Zero model
calls**: page texts, stored field answers and schemas are all local files; nothing touched any LLM
provider, `data/kb`, `extract.py` or the schemas (read-only replay of what is already on disk).

## Why

v044, v050 and v052 each hand-wrote a one-off "feed the stored KB fields back through `extract()`,
compare before/after" script (30–60 min each, none committed), and every future extract.py/schema
lane would write another. This lane commits the one script those replays converged on, in the shape
`scripts/label_regression.py` already established for baseline-vs-worktree double runs; supervisor
acceptance can run the same command.

## Usage

    python scripts/replay_check.py                                    # income_statement, data/kb, old = origin/acrylic
    python scripts/replay_check.py --section debt_maturity --baseline e3bbcf1 \
        --kb <shared>/seed4-kb --only creades_2025 --out replay.md

`--kb` (repeatable, default `data/kb`), `--section` (repeatable, default `income_statement`),
`--baseline <git-ref>` (default `origin/acrylic`), `--only stem1,stem2`, `--out <file>` (UTF-8/LF
report, paste-ready). Every KB directory is walked read-only; a stem present in several `--kb` dirs
replays once per directory and each row names its source directory. Baseline code and schemas load
via `git show <ref>:...` into a throwaway `pipeline._replay_baseline_extract` module — the same
mechanism as `scripts/label_regression.py` — so both sides run the *schema as of that ref* too (the
schema is part of the code state being compared; v050 changed both).

## What gets fed back, and how pages are derived

- **Model answer** = the stored fields cut back to the model-side shape `extract()` consumes:
  `key/label/value/unit/period/raw_label/source`; the post-processing-added `confidence`/`evidence`
  are stripped (extract() derives both itself). `call_llm` is replaced on both modules with a stub
  returning `{"fields": <that list>}` — the `x.call_llm = lambda ...` pattern
  `pipeline/test_confidence.py` uses.
- **Fresh deep copy per call**: extract() mutates the model answer's `source` dicts in place
  (`src["quote"] = verified`), so a shared list would make the second run replay the first run's
  post-processing instead of the change under test. This was not hypothetical — the first green run
  caught exactly this as 4 phantom CHANGED companies (essity/noba_bank/traton/wihlborgs, warnings
  count only) before the copy went in.
- **Candidate pages** (extract()'s `pages` argument), first rule that fits: a top-level
  `pages`/`candidate_pages` int list in the stored json (no stored file carries one today); else the
  candidate list recorded in a `two_pass: ... selected from candidates [...]` warning — what the
  original run received as `pages`; else the deduped sorted set of the stored fields' `source.page`.
  Seven companies have neither record (all-null run, empty warnings) and are not replayable rather
  than replayed against an invented window.
- `EXTRACT_TWO_PASS` is forced off (one stub call, no pass-1 noise) and `FEWSHOT=0` (the rendered
  prompt is discarded by the stub). `report_meta` = stem/company/fiscal_year/currency from
  `meta.json`; page texts from the same directory's `pages.jsonl`, split on `"\n"` not
  `splitlines()` — page text may hold U+2028, which `splitlines()` breaks apart
  (`pipeline.kb._pages` is the only reader these files were written for).

## What is compared

Per field: `value` (by `repr`, so 5 vs 5.0 shows), `confidence`, the `evidence` set; per check:
`passed` + `detail` up to the first `" | "` (the `missing: <field>` prefix, or the check's own text);
plus the warnings count. CHANGED companies print per-field/per-check before → after lines; totals
line counts companies / same / changed / not_replayable, and every not-replayable stem is listed
with its reason (`no <section>`, `no meta.json`, `no pages.jsonl`, `unrecognized shape`, `no
candidate pages derivable`).

## Known limitations

1. **Stored fields are post-processing output, not raw model output.** A field the original run
   dropped (quote not on page, computed-then-dropped, sub-total unwound) is stored `null` with no
   source and replays as null on both sides: the replay bounds what a change does to *what is on
   disk*, and cannot re-enact the original run's model behaviour or revive dropped fields. This is
   exactly what hid v050's Creades flip from replay (self-check b).
2. **The replay window is the recorded candidates' first two pages** (two-pass off), which for a
   two-pass run whose page selection was not its first two candidates differs from the original
   run's window — equally on both sides; no comparison against stored values is made, so this never
   biases old-vs-new, it only limits fidelity to the original run.
3. **Same-stem replays across seed dirs are not independent** — the seeds deliberately overlap
   (40 distinct draws of 42 rows, v050's census); totals count rows, not distinct companies.
4. Warning *count* is compared, not warning text: a wording-only warning change on an otherwise
   identical run would pass silently. (Value/confidence/evidence/checks are exact.)
