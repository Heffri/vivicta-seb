## What is implemented

`_balance_sheet_tie(texts, fiscal_year, total, schema)`:

- uses only `locate.balance_sheet_page`, `_page_rows`, `_row_year_column`, and
  `_row_amounts` on the selected consolidated balance-sheet page;
- accepts at most four `total_debt.row_synonyms` rows whose named fiscal-year cells
  add to a non-null total within the existing two-unit band;
- records the selected labels and whether the selected proof includes lease rows,
  preferring an otherwise-valid non-lease proof;
- for a null total, is deliberately narrower: exactly one explicit current and one
  explicit non-current non-lease row is required, and their contiguous page span
  becomes the `value_derived` source;
- declines the null fill when a note-reference tail makes the current/non-current
  amount ambiguous. Ratos's `16, 25, 26 912` otherwise reads as 26,912 in the
  shared general parser; this lane does not manufacture a 33,914 total from it.

The helper is applied in all three requested places:

1. `score_field` adds zero-weight `bs_tie` evidence and appends
   `ties to BS: <row labels>` to the raw label. It never overwrites a non-null
   model value.
2. `merge._pick` resolves an otherwise same-state, non-null conflict only when
   exactly one total carries `bs_tie`; otherwise the existing safe-null rule stays.
3. A null `total_debt` receives only the strict current-plus-non-current derived
   value described above.

## Offline survey before shipping

The 105 stored `debt_maturity` reports were surveyed using the same page and row
helpers, with no model call:

| Measure | Result |
| --- | ---: |
| Balance-sheet page located | 78 / 105 |
| Stored non-null total | 91 / 105 |
| Existing total tied to balance-sheet rows | **24 / 105** (24 / 91 non-null totals) |
| Selected proof excludes leases | 13 / 24 |
| Selected proof includes leases | 11 / 24 |
| Null totals eligible for strict two-row fill | **1 / 14** |

The 24 tied existing totals are: Attendo, BioInvent International, Boozt, Byggmax,
Cloetta, Ericsson, Fagerhult, Hexatronic, Instalco, KABE, Karnov, MEKO, Momentum,
NCAB, Nederman Holding, Net Insight, Nobia, RaySearch Laboratories, Rejlers, Salix,
Sdiptech, Svedbergs, Volati, and XVIVO Perfusion. The lease-inclusive subset is
BioInvent International, Boozt, Byggmax, KABE, MEKO, Nederman Holding, Net Insight,
RaySearch Laboratories, Salix, Volati, and XVIVO Perfusion. The one strict null-fill
candidate is Dynavox (828.8 + 67.5 = 896.3).

Among the 67 stored non-null totals that did **not** tie, 65 match their value label
and 2 do not (Bergman & Beving and Better Collective). Thus failure to tie is not a
replacement error classifier: it mostly means the balance sheet cannot prove this
particular debt scope. This is why the implementation records a positive tie as
independent evidence but never replaces a non-null answer.

- **Baseline red:** with the model stub returning all nulls, the frozen Dynavox
  balance-sheet excerpt left `total_debt` null on `origin/acrylic`; the contract
  assertion expecting 896.3 failed.
- **Green:** the same input produces 896.3 with `value_derived` and `bs_tie`, and a

- **KABE:** the four real Swedish rows select the lease-inclusive 50 proof.
- **Net Insight:** the two lease rows select the 39,415 proof.
- **Cavotec:** its balance-sheet components do not close on the stored 23,702;
  `_balance_sheet_tie` correctly returns no proof.
- **Ericsson:** its non-lease current/non-current borrowings close on 32,703, and
  `score_field` records both `bs_tie` and the exact row-label explanation.
- **Counterexample red → green:** the inherited helper would derive Ratos's unsafe
  33,914 from the ambiguous note-reference tail. The new permanent frozen excerpt
  proves the helper now declines that null fill.

  same-state conflict (81,489 versus 39,415). Marking only the 39,415 field with
  `bs_tie` selects run 2; without that marker, the existing conflict rule publishes
  null.
