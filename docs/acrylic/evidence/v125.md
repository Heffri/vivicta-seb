## The defect

Viscaria (`data/kb/gruvaktiebolaget_viscaria_2025`), stored wrong in `seed-rerun-v118-kb` and in
v118's own two passes: the model answered Note 22's own printed figures — `Total current liabilities
661.8 2.5 659.2 -` (p.110) for w1y and `Total interest-bearing liabilities 677.8 22.2 670.2 15.5`
(p.110) for the total; both are the label's values. `_fill_bucket_columns` then walked
p.100 — the liquidity note's **undiscounted per-instrument** table (`Maturity analysis`, "The
amounts reflect the agreed undiscounted cash flows..."), whose `Lease liabilities` row is a
`row_synonyms` candidate (v088 first recorded the shape) — read the 2025 lease row
`Lease liabilities 0.7 2.2 3.0 2.6 -` by its column order, and overwrote w1y with 2.2.

Why the v103/v111 wrong-table guard does not fire here: markers are matched on the **title block**
only (`_scope_zone`'s short digit-free rows above the body). The table's own title line is the bare
"Maturity analysis" (no marker word), and the one line that says "undiscounted" is the ~250-char
prose sentence below it — too long for the title block by v103's own rule. So the table reads
scope `unknown` and the fill proceeds. The work order's verdict stands: a repair that overrides the
note's own sub-total needs a rule of its own.

## The rule (the narrowest one: three conditions, all required)

At the disagree branch's write site — before `"{current} disagrees with the maturity table"`
overwrites a **numeric** model answer — the answer is kept when (`_model_own_printed`):

- **(a)** the value is printed verbatim on a row of this walk's own candidate window
  (`pages[:2]` + the cited pages, the same set the fill walks), and
- **(b)** that row's label is a known synonym of the field (`_label_known`) or a sub-total/total
  shape — Total/Totalt/Summa via `_BARE_TOTAL`, plus the current-portion wording the schema's own
  w1y synonyms already carry (`current`, `kortfristig*`; no new vocabulary invented), and
- **(c)** that row is not in the table the column-order read came from: another page, or the same
  page with a table boundary strictly between the two rows (`_table_break_between`: a digit-free
  line — title/prose/wrapped heading — or a row naming maturity buckets of its own, the stacked
  column-header shape). Contiguous data rows are one table.

Kept answers record `"{key}: kept the model's own {current} -- printed on page {p} as {row!r};
column-order read {value} from {rows[idx]!r} not applied"`. A bucket the model left **null** still
fills: the rule protects an answered value, not a missing one.

### Why the three conditions hold for Viscaria — and not for the repairs that must keep working

- **Viscaria w1y, the fired case:** (a) 661.8 is printed verbatim on
  `Total current liabilities 661.8 2.5 659.2 -`, inside the walk window (the model cited that
  page); (b) the row's label is a sub-total shape — bare "Total" (and "current"); (c) the read's
  source row `Lease liabilities 0.7 2.2 3.0 2.6 -` is on p.100 while the printed row is on p.110 —
  different pages, different tables (undiscounted per-instrument note vs the carrying current/
  non-current note).
- **v068 Ework / prior-year-column type:** the model's wrong value sits in the very table the
  repair re-reads — the cited row IS the read row or a data row of the same contiguous block, so
  (c) fails and the column order keeps winning.
- **v052 MedCap / paired-columns type:** the model's wrong value is printed on the very row the
  repair re-reads — (c) same-row fails; and (b) fails too (the row's label
  "Förfallotidpunkt för upplåning..." is no total/sub-total shape). Double-protected.
- **Cloetta's committed disagree case** (the suite's "22 disagrees with the maturity table"
  assertion): the model cites `Total 197 22 1,377 9 1,605` and the repair reads that same row's
  columns — (c) same-row, no boundary — so the override stands; the assertion is green unchanged.
- **(b) alone is not enough** — a counter kept in the suite: the model citing Viscaria's
  `Shareholder loans - 708.0 - - -` (printed, but neither a w1y synonym nor a total-shaped label)
  is still overridden by the column read. Those three conjuncts are exactly what separates "the
  model read its own table's printed sub-total" from "the model's value is merely printed
  somewhere".
