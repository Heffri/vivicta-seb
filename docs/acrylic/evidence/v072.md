## What the fresh pages say; schema decision

No schema edit was safe, so this branch deliberately changes **no schema or
pipeline code**.

| Company / shape | Evidence | Why no schema change |
|---|---|---|
| HANZA — split first year | p.132 prints `33` for <6 months and `27` for 6–12 months, with 60 only as their sum. | Existing vocabulary reaches the right table. Preserving a computed, not-literally-printed 60 needs extract-layer `value_derived`/provenance work, not another synonym. |
| Stillfront — component maturity rows | p.109 separates contingent consideration, bonds, credit institutions and leases; the model proposed non-literal aggregates and the provenance guard dropped them. | The missing work is a general component-row sum with a basis guard, not a label alias. |

| Sdiptech — carrying subtotals vs contractual schedule | p.110 prints non-current 4,049 and current 446, while its repayment schedule is contractual rather than the carrying total. | Needs a guarded sum-of-subtotals / basis-aware extraction rule; a schema word cannot select the right total. |
| Meren — locator false positive | selected pp.32–33 are risk-factor prose. Its financial-liability maturity schedule on p.82 includes estimated interest, while debt is 330 on p.16. | `financial liabilities` would find the contractual/interest-inclusive schedule, again the wrong basis. |
| KABE — wrong disclosure class | p.93 is a financial-debt movement table; p.94 is interest-risk prose. | A total-debt synonym would make this wrong-table path more attractive; no safe vocabulary lever. |

## Duplicate-call incident and future-driver rule

The first seed driver was interrupted by the host timeout after the fetch had
already reached the server. Its in-flight `/extract` continued server-side after
the client vanished; a restarted driver reissued the first part of the seed.
Stillfront, Meren, HANZA and Sdiptech consequently each received two complete
pairs of `/extract` requests. The later pair overwrote Sdiptech's initial saved
response, so this evidence retains only the final durable pass artifacts.

Backend route accounting is the source of the call count:

- duplicated four companies: 4 `/extract` routes each × two-pass = **32 Codex calls**;
- normal completed companies Green Landscaping, KABE and Nederman: 2 routes each
  × two-pass = **12 Codex calls**;
- Öresund had no candidate pages and no model call; Cynca failed during fetch.

**Total: 44/50 Codex calls.** Weekly Codex usage was **72% → 74%**. The run
stopped under the supervisor's hard-cap ruling rather than replacing the two
unavailable reports, leaving the intentional sample at seven completed pairs.

**Driver rule for the next round:** after issuing `/extract`, wait for its response
(or reuse an already saved pass response) before retrying or restarting; server
work is not cancelled merely because the client/driver is interrupted, and
reissuing it is billable duplicate work.
