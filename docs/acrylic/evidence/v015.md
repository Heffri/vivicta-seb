## 4. Upload third-face title wrap + 1280 recheck

`upload/Face.tsx`'s header (`label` + optional `hint`) was one `flex items-baseline gap-2` row with both as
plain children; when the row's hypothetical width didn't fit (the Dropzone face is the narrowest of the three,
`1fr` vs `1.1fr`, and its hint "parsed locally, nothing leaves this machine" is the longest of the three), flex
shrank the label's anonymous text-node item below its own word width, wrapping "UPLOAD" and "PDF" onto separate
lines (`v002/empty-dark.png`, reproduced fresh at 1440 before touching anything —
`baseline-upload-1440-dark.png` in the lane scratch dir, not committed).

Fix: wrapped `label` in its own `shrink-0 whitespace-nowrap` span (never shrinks, never wraps internally) and
added `flex-wrap` to the header row, so if the hint doesn't fit next to the now-fixed-width label, the *hint*
drops to its own second line instead of the title breaking mid-word — exactly the work order's "let the
description move to a second line, title stays on one line" option. No other Face caller regresses: the row
still renders on one line whenever both pieces fit (Directory search, Cached reports), so this only changes
behaviour at the width where it was already broken.

1280 recheck: with the fix in place, all three faces (rail expanded + `1.1fr_1.1fr_1fr`) still fit cleanly at
1280 — "UPLOAD PDF" stays one line and its hint now fits on one line too at that width (it didn't before the
fix: baseline 1280 also showed the same two-line break). No overlap, no crushed columns, so the 1280–1439
"move the third face to the next row" fallback wasn't needed. `upload-1440-dark.png`, `upload-1280-dark.png`.
