## What was built

All three of v043's own "for the group" leads (docs/acrylic/evidence/v043.md), each independently
toggleable, still behind the same `EXTRACT_TWO_PASS=1` (default **off**):

1. **Longer, cleaner pass-1 snippet.** `PAGE_SELECT_SNIPPET` 400 → 1200 chars, and it is no longer a raw
   head-of-page cut: `_select_pages` now runs `locate.strip_boilerplate(texts)` first (the same running-
   header/footer stripping `locate.candidate_pages`'s own scoring already gets), a new `_page_snippet`
   drops bare page-number lines too, then — from *beyond* that 1200-char head — appends any line
   containing a schema keyword, prefixed with its line number (capped at `PAGE_SELECT_KEYWORD_LINES=20`
   per candidate). Apotea's page 113 (v043's own root-cause: a repeated front-matter breadcrumb pushes
   "29. Borrowings" past a flat 400-char cut) is the case this targets directly.
2. **A forced companion page.** Pass-1 must now name two pages — primary (must be one of the shown
   candidates) and companion (default primary+1, or primary-1 when the model says the table's heading
   sits on the page before; the companion itself does not have to have been a shown candidate). A
   single-page reply is no longer accepted at face value: it is repaired with the default companion,
   never treated as an illegal/failed pick. v043 found two-pass was silently losing the companion page
   single-pass always got for free (`locate.candidate_pages` forces `pages[0]+1` into position 2
   unconditionally, whether or not it scored) — v043 named this "lost companion page" as the explanation
   for at least 6 of its 13 regressions.
3. **The schema's own steer, reused verbatim.** Pass-1's prompt now interpolates `schema["description"]`
   — for `debt_maturity` this is the exact carrying-amount-vs-contractual-cash-flow sentence
   (`"Read the carrying-amount table — the one whose total ties to interest-bearing borrowings on the
   balance sheet"`) pass-2's own system prompt already gets via `SYSTEM_PROMPT_TEMPLATE`. Reusing the
   field verbatim (not writing new copy) keeps this schema-generic rather than a `debt_maturity`-only
   hack: any schema whose `description` carries a two-table disambiguation gets the same steer in pass 1
   with no further wiring.

All three fixes live inside `_select_pages`/`_page_snippet`/the `PAGE_SELECT_*` constants only — no change
to `extract()`'s own call site, `locate.py`, any schema file, the single-pass path, the column-vector
mechanism, or check evaluation (v044 landed separately, mid-session, on exactly that last one — see
Interaction with v044 below). Flag off: `_select_pages` is never called, byte-identical to before
`test_confidence.py`'s own first sub-case confirms this, unchanged from v043).

## Methodology

Same as v043's own: the 30 (seed, company) draws are v035/v037/v041/v043's own seed-1/2/3 lists (10 each).
**Before is each seed's own cached `extractions/debt_maturity.json`, not rerun.** After was produced by a
standalone offline harness (`run_two_pass.py`, kept in `uaw-lanes/v045-two-pass-v2/`, not a deliverable),
calling `locate.candidate_pages()` → `extract.extract()` directly, in-process, against each company's
already-parsed `pages.jsonl`/`meta.json` in the seed-kb caches — never through `uvicorn`/the HTTP API/
`random_check.py`, so `kb.save_extraction`'s overwrite risk never applies. `git status --short data/kb
data/reports` is empty for this entire lane.

30/30 candidate lists reproduced v043's own tables exactly (verified before spending any call budget).
29/30 pass-1 calls returned a legal pick; Boozt's did not (see its row) and fell back to the single-pass
window, the same recovery path v043's own illegal-pick case exercises. **Every company cost 2 codex calls
except the 6 whose pass-2 window widened**(`2 * nonnull(raw) < len(schema["fields"])` retry, `extract.py`'s
own pre-existing logic) or hit a timeout-retry, 3 calls each: Bergman & Beving, Better Collective, Catella,
Alligo, Academedia, Coor Service Mgmt — a wider window firing far more often than v043's own "0/30" is
itself a direct, expected consequence of fix 2 (pass-1's reply is now *always* a 2-page window, so the
`len(attempt) == 2` guard on the widen-retry is reachable for every two-pass company, not only the ones
that happened to return 2 pages under v043's looser rule). Total: 30-company run **69 calls**; a 1-call
smoke test before it (this document's own methodology check, not part of the 30) + a 2-company × 2-call
stability rerun (Apotea, Catella — see below) = **74 codex calls**, under the ~80 cap throughout.
**`provider-usage.py`'s weekly-usage reading was not available from this worker session** (the script
referenced in the work order/LESSONS.md is not reachable from this AO worker's environment — no
`codex`-CLI subcommand or local file surfaced an equivalent percentage either, checked before spending any
budget); call *count* above is exact (this lane's own harness counts every `llm.chat` invocation), only the
weekly-percentage reading is unavailable here.

Two of the 3 companies v043 dug into fully (Apotea, Catella — the clearest page-selection recoveries, see
below) were independently rerun once more to confirm stability before writing them up: both reproduced
byte-identical (same two pages selected, same fields, same confidences) — see `*.rerun.debt_maturity.json`
in this directory.

## Notable cases, read against the real page text (not just checks/confidence)

- **Better Collective** (page 161): `"Debt to credit institutions 259,946 259,946 306,005 10,551 295,454 0"`
  — a real, printed row, quote-verified, with a plausible multi-column loan-note shape (carrying/nominal/
  bucket columns); `raw_label` doesn't exactly match a listed `total_debt` synonym ("Debt to credit
  institutions" vs "total borrowings" etc.), which is why `label_known` is the one evidence bit missing
  from its 0.9. Not independently verified beyond quote-on-page (no PDF access from this offline harness,
  same constraint v043 and v044 both operated under) — flagged as a strong, real find, not claimed as
  certainly the schema's intended row.
- **Gentoo Media** (page 88): `"Total loans and borrowings 111,798 96,627"` for `total_debt` and, a
  *different*, correctly-labelled row, `"Borrowings, current 111,798 7,151"` for `due_within_1_year` — the
  two numbers matching (111,798 = 111,798) is not a duplication bug, it means Gentoo Media's entire
  borrowings balance is due within a year this fiscal year (`"Borrowings, current"` is the IFRS
  current/non-current split synonym `3410948` added to this schema specifically for this company). Both
  rows `label_known`, both `1.0`. v041 had already flagged Gentoo Media as the single highest call-to-call
  variance case across all three prior rounds; this round's two-pass window happens to land cleanly.
- **Nelly Group** (page 89): before's `due_within_1_year` (287.1@1.0) is v037's own documented wrong
  answer — a `_derived_value` bug (out of this lane's territory, unfixed) that combined a current and
  non-current lease row into one number under the wrong label; v037 named 36.2 as the real figure. This
  round's `due_within_1_year` reads `"Kortfristiga 36,2 35,7"` — 36.2, exactly v037's own independently-
  documented true value — while `total_debt` still reads the same 287.1 lease-total row as before. The
  identity check now fails (36.2 ≠ 287.1, no bucket breakdown beyond the current portion is printed) and
  both fields' confidence drops to 0.5 as a direct, correct consequence — the check's own cap on an
  operand whose sibling doesn't reconcile, not evidence the new figure is wrong. Counted as **improved**
  on the fact that matters (which number is actually printed under which label), not the confidence score.
- **Bergman & Beving** (new — not one of v043's 13): pass-1's primary pick (120) is correct, matching
  before. Its forced companion defaulted to +1 (121), a page that was never itself a candidate (score too
  low) and — per the warnings — supplied two numbers (1765, 21) that don't reconcile with total_debt
  either, while `due_within_1_year`'s own real value (476, present in before) is now displaced: the model's
  own new answer for it (548) isn't printed on either page 120 or 121 and gets correctly dropped as
  "computed, not read". Net: 2 non-null-but-failing fields before, 3 non-null-but-still-failing fields
  after, with the one previously-real bucket lost — read as **worse**, and the clearest real cost this
  round's fix 2 has on the 30: the default-to-+1 heuristic isn't always the right side, and there is no
  candidate-list membership check left to catch it once a companion is allowed off-list.
- **Acast** (page 65-66, same pages before and after): before's three numbers are a documented,
  internally-nonsensical bucket-column misread (v037/v040) that the column-repair safety valve (v040,
  "Acast" case in `_fill_bucket_columns`) explicitly refuses to touch. This round the model's own pass-2
  answer is null across the board — the warnings show the *same* safety valve firing on the *same* rejected
  column reading, but this time with nothing for it to fall back to. Counted as **worse** by the strict
  "0 usable buckets either way, and before at least had a real if inconsistent number" reading — but by
  v043's own stated value system ("a confidently wrong, checks-passing partial number" is worse than an
  honest null), this is arguably a safer failure than either this company's own "before" or v043's own
  two-pass attempt (135382@0.9, a third, different, also-wrong number). Not claimed as a win; recorded
  honestly as a different, arguably-less-dangerous flavor of not finding the answer.
- **Coor Service Mgmt**: the one regression that reproduces for an unrelated reason. Pass-2's first call
  (window [160,161]) hit a genuine 120s `codex exec` timeout (see the stored warning, full command line and
  all); `extract()`'s own pre-existing timeout-retry (`len(attempt) > 1 and pages` → retry on `pages[:1]`)
  then tried page 159 alone — the *original* candidate ranking's own top-1, not two-pass's own [160,161]
  pick — and page 159 doesn't hold the real total (page 157 does, per before). This is latency variance
  (codex CLI, not this lane's logic) interacting with a pre-existing retry path that predates this lane and
  is out of its territory; noted as a real, reproduced-once observation, not chased further. A future lane
  could consider retrying on two-pass's own selection rather than `pages[:1]` when two-pass picked the
  window that timed out.
- **Boozt**: pass-1 returned an illegal pick for the first time in either round (candidates
  `[121,122,98,139,108]`) — not logged verbatim by this harness (only the pass/fail outcome, matching
