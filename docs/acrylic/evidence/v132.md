## Headline: the 18-point gap is not 66 citation defects — 55 of the 66 rows have no citation at all

Every row scored value-right/page-wrong (66) was classified into the work order's buckets, plus one
bucket the work order's premise did not anticipate:

| bucket | n | what it is |
|---|---|---|
| **N** | **55** | label `expected_value` is `null` and the pipeline **correctly** answers null — there is no
number, so the pipeline stores no citation, `got_page=None`, and `page_match` scores **False** because
the label still asserts an `expected_page`. A scoring/label convention artefact, **not** a wrong citation.
All 56 `null` label rows carry `expected_page` ("not reported", "no maturity table on the page"); 55 of
them are answered null correctly and all 55 land here. |
| **A** | 8 | the same number is printed on **both** pages; the pipeline cites one, the label the other.
Every one is a quote-verified, page-true citation of a *different occurrence* of the same figure. |
| **B** | 1 | the pipeline page does **not** print the number — the citation names the page the number was
**derived** on (`value_derived` evidence), i.e. by design for a derived value, but it is the only real
"number not on the cited page" row in the corpus. |
| **C** | 1 | number printed on the pipeline page but not on the label page, pages one apart. |
| **D** | 1 | number printed on the pipeline page only, 15 pages from the label page (both pages state the
same zero in different sentences). |

**值错页对** (the other problem class — value read off the wrong row/column of a correctly-cited page):

page the cited row is not on. Every `pages[0]`-class write site (`extract.py:2795`, `:2985`, `:3062`,

derivation page with `value_derived` evidence — that is the mechanism working as documented, and the
underlying defect there is off-grid column alignment, not the page write. **No extract.py change is
warranted on this evidence; the v126/v131 hot-file lanes are untouched.**

## Recommendations (measured, not applied)

1. **The big lever is the N bucket, and it costs zero code.** `eval/run.py:50` (`page_match`) scores
   False when a `null` label row carries `expected_page` and the pipeline answers null with no citation
   — 55 rows, 17% of the denominator, all "wrong" by construction. Suggestion: return `None`
   (unscored, `-`) when the label value is null **and** got is None — there is no page to be right
   about — or blank `expected_page` on null rows at the next label pass. Metric effect: 209/327
   (63.9%) → 209/272 (**76.8%**) with no pipeline change, and the metric then measures what the
   product promises (a *present* number's citation is true).
2. **A bucket (8 rows): the label convention and the pipeline's citation policy disagree; both are
   page-true.** Labels anchor the canonical borrowings note row (the notes say so explicitly); the
   pipeline cites whichever verified occurrence it read — statement spread, another note's closing
   balance, lease-table carrying column, management-review prose. Suggestion (labels unchanged): score
   page correctness as *provenance truth* — `page_ok=True` when the value is verbatim printed on the
   cited page **and** the quote verifies there (both already computed offline by
   `scripts/page_miss.py`) — or keep page-equality and accept ~8 permanent misses as a known,
   documented divergence, not defects.
3. **B bucket (1 row), for whoever owns extract.py after v126/v131:** the real defect is that p121's
   off-grid header (`five to nine years` / `after nine years`, PDF-wrapped to "nie") was not caught by
   the v095 off-grid valve (`_offgrid_hits`, `extract.py:2186-2202`), so the row's 5-9y/9y+ columns
   landed on the 1/5-year grid and w1y closed the identity as a residual. Two-part suggestion:
   (a) teach `_bucket_header`'s synonym scan the `5-9/9+` wording so the row declines honestly —
   **but note this flips a currently value-right row to null**, a value-metric regression that needs
   the owner's call, not a mechanical fix; (b) provenance upgrade with no value change: at the derive
   write sites (`extract.py:1223-1224`, `:1375-1376`, `:2300-2305`, `:3078-3079`), when the derived
   value is verbatim printed with a known label synonym on another cited candidate page, cite that row
   instead (the `_model_own_printed` pattern at `extract.py:2291-2296`, one level up). Boozt w1y would
   then cite p108's `Short-term liability 104 97`.
4. **C/D buckets (2 rows): nothing to fix.** In both, the pipeline's citation is the page that prints
   the number; the label anchored a page that does not print it (humana) or prints the same fact in a
   digit-less sentence (flat_capital). Covered by recommendation 2's provenance-truth scoring.
5. **Quote-drift (2 rows):** re-validate stored extractions against the current parser's page text
   during the next `kb build`, or store the parser version per entry (the meta.json parser key from
   LESSONS 27 already distinguishes them) so `quote_on_page` failures on old entries are detectable
   offline.

## Ceiling, if B+C were all fixed

B+C = 2 rows → page hit-rate at most 211/327 = **64.5%** (+0.6pt). The metric's real headroom is the
N bucket's convention fix (recommendation 1): 76.8% without touching the pipeline, 77.6% with both.
