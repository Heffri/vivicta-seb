## Driver rule for this round (why the call count below is trustworthy)

The dispatch-required rule — no short client timeout on `/extract`, reuse a
saved pass result instead of resending — was built into a small driver script
(`uaw-lanes\v082\driver.py`, not part of the repo): before calling `/extract`
for a `(stem, pass)` pair it checks whether
`docs/acrylic/evidence/v082/<stem>.pass<N>.debt_maturity.json` already exists
on disk, and only calls the backend if it does not; every response is written
to that exact path immediately on return. It was run under the harness's own
background-task mode (no wall-clock ceiling on the wait), and the `urllib`
timeout is 600s per call, comfortably above the observed 22–141s per route.

It was needed: the first run crashed the **backend** (not the driver) after
six companies had fetched cleanly — `UnicodeEncodeError` in `app.py`'s
`print(f"[fetch] ...")`, because this machine's console codepage is GBK and
one company's name/URL carried a non-GBK character. That is an `app.py`
issue, out of this round's territory, so it was **not patched**; the backend
was restarted with `PYTHONUTF8=1`/`PYTHONIOENCODING=utf-8` forced on its own
process only (an operational launch flag, no repo file touched) and the
driver's own JSON-body parser was hardened to not itself crash on a non-JSON
error response. The crash happened entirely inside the **fetch** phase,
before any `/extract` call was issued for any company — **zero Codex calls
were lost**, unlike v072's duplicate-call incident (LESSONS 37): the restarted
driver re-ran `pick_companies()` from scratch (cheap — fetch is idempotent,
same seed reproduces the same draw order) and then found no
`pass{1,2}.debt_maturity.json` files yet, so it proceeded to extract all ten
companies cleanly with no resends.

## Schema decision: two investigated, both rejected with evidence

No schema commit this round — both candidate fixes below were built, tested
against the real page with **zero model calls** (the v073/v076/v078 method:
`call_llm` stubbed to replay the stored pass answer through `extract()`,
compared before/after), and rejected because neither produces a demonstrated
win on any of this round's ten companies. `backend/schemas/debt_maturity.json`
is therefore byte-identical to the dispatch baseline
(`git diff 2fa7b97 -- backend/pipeline/extract.py backend/schemas/debt_maturity.json backend/pipeline/parse.py`
is empty).

### Findings 1 — Tången: a genuine, closeable table, blocked one layer below schema

Tången p.62 prints (2025 column; KSEK):

```
Mindre än 12 månader
Mellan 1 och 2 år
Mellan 3 och 5 år
Senare än 5 år Summa
Lån Kreditinstitut 141 734 137 898 251 081 57 486 588 199
```

141,734 + (137,898+251,081) + 57,486 = 588,199, exactly — a real,
closeable bucket-column table. Two of its four header phrases
(`mindre än 12 månader`, `mellan 1 och 2 år`) are missing from
`due_within_1_year`/`due_1_to_5_years`'s `header_synonyms`. Adding them
(tested in a scratch schema copy) makes no difference, because the row never
reaches `_bucket_header` at all: `_bucket_total_row`'s own candidacy gate
requires the row's label to match `total_debt`'s synonyms, a bare
Total/Summa word, or the private module-level `_DEBT_ROW_SYNONYMS` list in
`extract.py` (`"borrowing"`, `"upplåning"`, `"räntebärande skulder"`, ...,
none of which prefix-matches `"lån kreditinstitut"`). `_DEBT_ROW_SYNONYMS`
is not schema — it is a hardcoded list inside the file this round is not
allowed to touch. **Not fixable within this round's territory**; flagged for
the group as a concrete, general (not company-specific) `extract.py`
candidate for a future round: recognise `"lån"` (loan/loans) alongside the
existing English/Swedish debt-row words, or accept any row whose *header*
clears the bucket-count valve regardless of the row's own label.

### Findings 2 — Instalco: the same block, plus a separate `_row_amounts` question

Instalco p.128's own liquidity note has the same shape and the same block:
`"Liabilities to credit institutions – – 3,209 – 3,209 3,122"` under a header
of `Within 6 months / 6–12 months / 1–5 years / Later than 5 years / Total
contractual cash flows / Carrying amount` — a dash-bucket row (the v078
shape) whose own label again fails `_DEBT_ROW_SYNONYMS` the same way.

The table's grand `Total 1,151 160 3,583 37 4,931 4,802` row two lines below
*does* clear the label gate (bare "Total"), and the header above it already
carries three of the four bucket words the current schema knows
(`6–12 months`, `1–5 years`, `later than 5 years`) plus both v076 words
(`carrying amount`, a substring-match on `total contractual`) — confirmed
live: `_bucket_header` on that row returns a col_keys list seeded from
`total:carrying`, i.e. the v076 mechanism genuinely fires on this page. It
still does not fill, and adding the missing fourth word (`within 6 months`)
to a scratch schema copy and re-running `extract()` on the real page
(zero model calls) changes **nothing** — confirmed empirically, not assumed.
Traced one level further: `_row_amounts` on the Total row's own text
(`'Total 1,151 160 3,583 37 4,931 4,802'`) returns `[1151, 160, 3583, 4931,
4802]` — **the `37` (the Later-than-5-years figure) is silently dropped**,
independent of anything this round touched. That is a `_row_amounts`
tokenizer question, not a header-synonym gap, and out of this round's
territory (`parse.py`/`extract.py`). Flagged as-is, not chased further, since
resolving it would mean editing forbidden files; the schema-only lever was
confirmed to be the wrong lever here before it was abandoned, not assumed to
be.
