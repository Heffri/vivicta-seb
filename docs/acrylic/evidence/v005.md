## Found & fixed (not in the original brief)

Sticky table header didn't actually stick on the first pass — verified by scripted scroll, not by assumption
(screenshot before/after in my own check, not part of the evidence set). Root cause: `ui/table.tsx`'s own
`Table` wrapper div is hardcoded `overflow-x-auto` with no way to override it from a consumer — and per CSS,
setting only `overflow-x` forces `overflow-y` to compute to `auto` too, which makes that div (not `<main>`) the
nearest ancestor scroll container for anything sticky inside it. Since that div has no bounded height of its own,
it never actually scrolls, so a `sticky` thead inside it never sticks to anything the user can see scroll.
Fixed without touching `ui/table.tsx` (out of territory) by reaching into its `data-slot="table-container"` hook
from my own `Card` className: `[&_[data-slot=table-container]]:max-h-[70vh] [&_[data-slot=table-container]]:overflow-y-auto`.
This also improves on the brief a little: the KB view now genuinely fits "one screen" — title/description/filter
stay fixed, only the row area scrolls internally with its own sticky header, rather than the whole page growing
to fit 102 rows.

## Candidates for `ui/`

- **`Input`** — no text-input primitive exists. Built the filter box inline in `KbView.tsx`, styled to match
  `SelectTrigger`'s existing border/bg/focus classes by hand. Fine for one input; a second one anywhere else in
  the app should probably prompt lifting this into `ui/input.tsx` instead of copy-pasting the recipe again.
- **`Checkbox`** — no checkbox primitive; used a bare `<input type=checkbox accent-ring>`. Works and matches the
  brand hue, but has none of `Badge`/`Button`'s glass treatment (no `--glass-hi` inset edge, no focus ring
  styling beyond the browser default).
- **`Table`'s sticky-header gap** — see "Found & fixed" above. This isn't a missing primitive so much as a real
  limitation in the existing one: `ui/table.tsx`'s wrapper div is unconditionally `overflow-x-auto` with no
  className passthrough, which silently defeats `position: sticky` headers for *any* table that scrolls inside
  a bounded box, not just this one. A `containerClassName` prop (or dropping the hardcoded `overflow-x-auto` in
  favor of letting consumers opt in) would let the next sticky-header table skip the arbitrary-selector
  workaround I used here.
