## Mechanism (`backend/pipeline/extract.py`, additions only)

- **`_bucket_span(label) -> (lo_months, hi_months) | None`** — interval GEOMETRY, not
  vocabulary: ranges (`0–6 months`, `6 – 12 månader`, `1 – 5 år`), `between A and B unit`
  (+ `mellan … och …`), `later than A unit but within B unit(s)`, `less than/under/mindre än/<`,
  `A unit or less/eller mindre`, `within/inom A unit`, `more than/over/later than/after/mer än/
  senare än/efter/över/> A unit`, `A unit or more/eller mer`; digits or the small number words
  real tables print ("Within one year"). Unbounded upper = inf. Not units, deliberately: bare
  `y`/`yr` (Stillfront's duration labels "Repayment within 2–5 yr." — a component label, not a
  maturity interval) and day wording (`-30 dgr` — XANO's day/month columns are the subtotal-
  column mechanism's territory, v078). Unparseable → None, never a guess.
- **`_span_bucket(span)`** — whole-span attribution per the schema's own `value_convention`:
  [0,12] → within1y, [12,60] → 1–5y, [60,∞) → >5y; a span crossing a boundary (`3–7 years` =
  [36,84], or `>1 year` = [12,∞)) → None → **the whole derivation is abandoned**, the same
  don't-guess rule as `_maturity_bucket`'s "straddle" (v073).
- **`_finer_split_rows(...)`**, one call site in `extract()` right after `_fill_bucket_columns`
  (bucket-row shape beside the bucket-column reader), structured on `_date_bucket_derive`:
  - *Scope*: anchored on `total_debt`'s own verified quote row; the walk collects the
    contiguous interval-labelled rows directly ABOVE it and stops at the first row that names
    no interval — Rusta's own right-of-use table above and parent-company table below are never
    reached. Amounts from the fiscal-year column: `_row_year_column` on the total's own row,
    else page-level `_year_column` (Rusta's own maturity header "30 Apr 2026 30 Apr 2025" is
    not a `_year_run`; the page-level run is the P&L table's "2025/26 2024/25" below it). Every
    interval row must print exactly the header's column count, else the walk stops.
  - *Adoption gate*: only when the three bucket sums close `maturity_sums_to_total` within
    `_check`'s own ±2 (Rusta: 6,623 ≈ 6,624 — the identity, not any label vocabulary, decides;
    the prior-year column would sum 975+3,062+2,633 = 6,670 and fails it). A bucket the table
    prints no row for contributes 0 to the gate (the table's own rows-sum-to-total arithmetic)
    but is never WRITTEN — null stays null under `require_explicit_values`, honestly "missing".
  - *Writes*: only buckets with **≥2** sibling rows (a single row is that row's literal figure —
    the existing single-row paths' territory, no new behaviour); a field whose current value
    already matches its sum (±2) keeps the model's own evidence; a disagreeing value is
    replaced with a warning naming it. Quote = the sibling rows joined in print order (verified
    `quote_on_page`), raw_label = labels joined " + " (v051's convention), page = the table's
    own page, evidence `quote_on_page` + `value_derived` (never both with `value_in_quote`).
- **No schema edit** — v088's schema decision 3 stands: `0-6 months`/`7-12 months` in
  `due_within_1_year.synonyms` would leak into `_bucket_synonym_hits` and change
  `_bucket_header`'s read; this parser shares nothing with that vocabulary. No change to
  `_between_rows`, `_statement_row`, `_check`, `_row_amounts`, `_year_column`, `_fill_bucket_
  columns` or any other function's semantics; no parse.py, frontend, or app.py change.
