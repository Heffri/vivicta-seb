## Backend

- `search()`: in **bm25 mode only**, if every candidate's raw BM25 score is 0 — no query term matched any
  chunk — return `[]` where the old code returned cover-page order (stable corpus order, per v034's
  finding). Hybrid mode is untouched: cosine still has a signal when the words differ, and the min-max
  blend is unchanged there. Fixture mode never reaches `search()` (`/api/ask` serves the canned answer
  before `kb.ask`, unchanged).
- `ask()`: zero hits → **`llm.chat` is not called**; the Answer is the fixed sentence
  "No passage in the selected report(s) matches the question's terms — try the report's own wording or
  another language.", `citations: []`, `warnings: ["retrieval: no matching excerpt (bm25 all-zero); model
  not called"]`, `model` as before. The shape is exactly the documented `Answer`, so `/api/ask` and
  `docs/API.md` needed no change (the work order's "若响应形状有变" clause does not trigger).

## Tests — red → green

Two new sections in `pipeline/test_kb.py` (suite now 10 sections):

- `test_bm25_all_zero_returns_no_hits`: the v034 finding reproduced as an assertion — "hur mycket
  kostade kaffet" against the mixed corpus must return `[]` in bm25 mode; the same query in hybrid mode
  (fake `embed` giving every chunk cosine 1.0 with the query) must still return hits, proving the gate
  is bm25-only.
- `test_ask_empty_retrieval_skips_model`: `llm.chat` monkeypatched to a counting spy — zero-hit question
  makes **0** calls, returns the fixed answer with the warning; a matching question ("what was net sales

  still calls" check, which would have really invoked codex and was therefore not run.


Green after: `python -m pipeline.test_kb` all 10 sections ok (`kb self-check ok`), and the other four
suites green: `test_confidence`, `test_parse`, `test_llm` (codex + claude), `test_paths`.
