## Findings

1. **The union merge is only as good as its tiebreak under pass instability.** viva_wine is the
   round's clean demonstration: the two passes disagreed (1002 loans-only vs 1203 note total), both
   identity checks failed, and v133's documented tie (higher confidence → run1's 0.9 beat run2's
   0.85) kept the wrong one. run2 alone scores 1/2 — the publishable record exists precisely
   because the work order keeps per-run copies. ericsson's run2 (w1y null after selecting [95,96])
   is the same instability absorbed correctly.
2. **Pass-1 page selection is the round's dominant fresh defect** (bts, cavotec — both passes,
   wrong page, plausible-looking totals; bts's label page ranked #10/10, cavotec's #1 and still not
   selected). This is the v124 core metric shape again: in-window is not selected. bts/cavotec are
   also the only two union regressions vs stored — kept stored, they cost nothing this round.
3. **modern_times is a pipeline-stable miss, not noise**: the fresh runs reproduced the stored
   85151/155/37/33 byte-for-byte, via the same column-order repair overriding the model's own
   3487. Whatever publishes here, eval improves only when the repair's table-guard learns the
   p.142 gross table (the v118-finding-2 family).
4. **Scope slips repeat systematically** (dustin 3055 incl. finance leases; momentum 622 incl.
   leases): the same wrong values as v135's documented stored misses, now from fresh runs — these
   are convention violations the schema/prompt does not yet prevent, not random model noise.
5. **Report-internal disputes reproduce** (volati 3246 vs 3245; green 2491 vs 2495): the model
   consistently takes the roll-forward/closing row, the labels take the note subtotal pair / BS sum
   — the eval's two dispute cases behaved exactly as v135 recorded.
