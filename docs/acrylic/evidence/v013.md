## 改了什么

**`backend/pipeline/parse.py`**(唯一的行为改动;`PARSER_VERSION` 2 → 3):

1. `page_text()` 现在分三路:
   - **列序文本层**(连续 ≥12 个纯数字行,Arion Bank 形状)→ 照旧走 `_lines_from_words`(词级重建,行为不变);
   - **检测到拆散行**(新 `_split_rows`:一行只有字母、紧接着一行只有数字)→ **新 `_merge_baselines`**:从 `get_text("dict")` 按块重建——同一块内基线重合(容差 = 两条线高的较大者的一半)的行左右拼成一行;**块之间的先后顺序原样保留**,所以散文段落的行序、段内结构不受影响;
   - **两者都不满足的页**(纯散文页)→ 原样返回 `get_text()` 的字节,一个字符都不动。
2. 块内合并后仍剩拆散行(标签和数字分属**不同块**)→ 才退到词级全页重建 `_lines_from_words`,且仅当它确实合上更多行时才采用(词级会把并排的两张表合成一行,AQ 形状,只在有收益时付出这个代价)。
3. `find_tables()` 没有用:块级/词级合并已把拆散率打到 ~0.2%(下表),引入表识别反而多一层需要防误判的机制。

`PARSER_VERSION = 3`:`kb.save_report` 会在下次重新注册 PDF 时自动重写 pages.jsonl——本单**没有**把它跑在任何 KB 目录上,`data/kb` 一字未动(见门)。

**`backend/pipeline/test_parse.py`**(新,`python -m pipeline.test_parse`):合成页(一页 = 一段散文 + 一行被文本层拆成 4 行的表)断言行合并后为一行、散文两行原样在前、`_split_rows` 归零、行上读下的 quote 仍过 `quote_on_page`;纯散文页逐字节等于 `get_text()`;列序页(先 12 行数字后 12 行标签)仍走词级重建且数字落到标签行上。

**`scripts/parse_check.py`**(新,离线对比脚本,三种模式):默认 = 拆散率(每份 PDF 用 `locate.candidate_pages` 取 debt_maturity / income_statement 各前 2 页,数"字母行紧接数字行"的对,比率 = 每 100 非空行的拆散数);`--quotes` = 引用回归;`--locate` = 定位器前后对比。

## 建议(留给小组)

1. **列序判定可以并入统一入口**:`_numeric_run ≥ 12` 和新的 `_split_rows` 是同一缺陷的两种形状(整页列序 vs 逐行拆散),现在分两路处理;若后续要动 parse.py,可考虑让列序页也先试块内合并、再退词级,少一层特殊路径。
2. **上游收益可以量化**:HANDOFF 说行合并"helps both keyword locating and verbatim quote matching"。quote 一半已证(76/76 保持);locating 一半可以在 debt_maturity hardening 时观察:注释页的行结构变干净后,`_row_amounts`/`_statement_row`(extract.py)在 debt note 上的命中率应能直接看到变化——本单没跑模型,量不到。
3. **OCR 兜底**仍是 parse.py docstring 里的下一件事(`page.get_textpage_ocr()`);本单的检测器只对文本层有效,扫描页两个门(列序/拆散)都不会触发。
4. `\x07` 一类控制字符能从词级重建中顺带消失(见上),但散文页不走重建、保留原样;若 RAG 端曾被这类字符干扰,可在 kb chunking 侧统一清洗(不在本单领地)。
