## Method

Followed v105's process with this round's own deltas (work order §"与 v105 的不同"): the company set
is the 18 KB stems that have a stored `debt_maturity` extraction but no label rows — acast,
arctic_paper, bico, bts, cavotec, dustin, elanders, enity_holding, ericsson, green_landscaping,
hansa_biopharma, mildef, modern_times, momentum, nobia, orron_energy, viva_wine, volati. Read
v105 + v099 + v094 + v057 + their evidence in full first, then `common.md`, `reporting.md`,

whole of `eval/labels.csv` (231 debt rows / 87 companies — none of the 18 overlaps; duplicate guard
asserted in the append script), and `v110.md`/`v131.md` (no-total-row → total = the note's two
section subtotals, labelable with notes) and `v090.md` (bank ruling). `modern_times_2025` is the
FY2025 report (v122 rebuild, 184 pages) and was labelled as such.

Then **every value below was read by me from the real page text** (`data/kb/<stem>/pages.jsonl`;
the PDF for arctic_paper exists only as the separate S.A. statements, see Finding 2; ericsson has
no PDF in the shared reports dir — its pages.jsonl is the source). Three layout-sensitive pages
were additionally rendered from the PDF and read as images: `modern_times` p.118 (two-column
balance-sheet scramble — confirms the bold subtotals 3,323 / 418 and that contingent consideration
and put/call sit under *non interest-bearing*), `nobia` p.131 (Note 28's column order is
**2024 first**, 2025 column = 2,983), `volati` p.177 (Note 17's two section subtotals 3,053 / 192
and note 18's roll-forward closing 3,246 both confirmed). No value is written that is not printed
on a page I read — or a sum/section-total of printed rows the schema's own finer-split rule
sanctions (bico's and volati's subtotal pairs; green_landscaping's BS lines and note 24 rows;
bts's year rows; mildef's short-term section rows), each closing exactly.

Conventions carried over from v057/v094/v099/v105: values **as printed, native unit** (TSEK /
PLN '000 / SEK m / KSEK / TEUR / MSEK / MEUR per report); current/non-current-only reports get
`total_debt` + `due_within_1_year` only; undiscounted/contractual/gross maturity tables are never
used for values; printed dash rows are 0 where the row's own arithmetic closes, never nulls
(v078/v128); leases follow the report's own note scope — included only where the report's own
note includes them (mildef, modern_times, volati), excluded where the report classifies them as a
separate line (acast gets leases because they are the *only* interest-bearing debt — the Flerie/
Byggmästare precedent); `null` labels use the literal `null` string.

## Findings (premise-level, for the record)

1. **Modern Times — the report's own "Total borrowings 5,146" is not the schema's total_debt.**
   Note 16's net-debt table (p.141) prints `Total borrowings 5,146` = liabilities to financial
   institutions 3,499 + leases 253 + put-and-call option liability 250 + contingent consideration
   1,145. But the balance sheet (p.118, image-verified) classifies contingent consideration and
   put/call under **Non interest-bearing liabilities**, and prints its own interest-bearing
   subtotals 3,323 (non-current) + 418 (current) = 3,741 = fin inst 3,488 + leases 253 exactly.
   The schema's tie-breaker ("must be a carrying amount that reconciles to interest-bearing
   borrowings on the balance sheet") picks the BS subtotals; the net-debt table is an APM
   aggregation (it also carries an 11-unit internal quirk: 3,499 there vs 3,488 on the BS). The
   stored answer's 85,151 appears nowhere in the report; its buckets 155/37/33 are the **2024
   comparative** lease row of p.142's gross table.
2. **Arctic Paper's PDF is the separate (S.A.) statements only** — the consolidated report is a
   separate publication (p.25: posted separately). The borrowings note 4.7.1 therefore includes
   cash-pooling liabilities to subsidiaries (185,048 of the 219,487 current), which consolidate
   away in the group accounts the KB does not hold. Labels are per the report in the KB; the
   stored answer's total 251,209 is right with the wrong page (p.75, the undiscounted liquidity
   note's carrying column — value ✓, page ✗).
3. **Ericsson's per-instrument table does not reconcile to its own note total**: notes/bonds
   20,446 + bilateral/syndicated 9,139 = 29,585 carrying vs Note F4's non-current 29,165 (gap 420;
   subsidiaries' borrowings 0.3bn are current). No group bucket table exists anywhere, so 1-5y /
   >5y stay unlabelled — the stored answer's 1-5y 29,165 (whole non-current) is contradicted by
   the printed 2031 maturities (1,726 + 1,014 carrying, >5y) on the same page.
4. **Volati prints two disagreeing "totals"**: note 18's financing roll-forward closes 3,246 while
   note 17's two section subtotals sum to 3,245 (image-verified both) — a 1-unit report-internal
   inconsistency. The label takes note 17's own subtotal pair (the note titled "Interest-bearing
   liabilities"); the stored answer took 3,246 and now scores value ✗ / page ✓ — the eval's
   first 1-unit case, worth keeping exactly as it is.
5. **Nobia's Note 28 prints the full maturity structure with dash buckets** — `Within 1 year -` /
   `Longer than 5 years -` close against the Total (0+2,983+0 = 2,983), so both are 0 per the
   v078/v128 dash ruling; the column order is 2024-first (image-verified) and the stored answer
   already reads the correct 2025 column — one of the round's clean ✓✓✓✓ companies (with bts and
   orron).
