## Bugs filed (sent immediately on discovery)

- **BUG-1 (P2)** — KB Embeddings column: 44/206 entries stuck `building` forever → frontend
  polls the whole KB every ~2–3 s indefinitely; one listing measured 2.0–2.3 s during the storm.
  Root shape: `KbView.tsx` polls while any `status === 'building'`; backend reports
  lock-contention as `building` ("Report update in progress"), so the poll's own concurrency
  keeps the condition alive.
- **BUG-2 (P2)** — KB collection choice (and light/dark tone) silently reset on every app
  restart. The choice IS written to localStorage (verified live and on disk), but the packaged
  backend binds a **random port per launch** → new origin every run → per-origin storage never
  reused. Verified across a graceful close + relaunch. Demo-day note: re-do the "switch to All"
  step after any restart.
- **BUG-3 (P1)** — fixture-mode upload of real text-layer PDFs (atlas_copco, apotea) fails
  reproducibly as "Scanned PDF needs OCR language files… Run python scripts/setup_ocr.py";
  the advice is unreachable in the packaged app (no scripts/, no OCR packs bundled). Same batch:
  karnell/ependion/cloetta succeed.

## Notes and caveats

- All numbers above are fixture-mode, zero model calls. No `data/` file was modified. The only
  user-data mutation was the QA's own review entries, the uploaded test PDFs, and one seeded
  `karnell_2025.pdf` for the page-image checks — all inside the lane's scratch user-data-dir.
- Interim vs final: BUG-3's root cause (why the candidate pages read empty for those two PDFs)
  is for the fixing lane; this lane reproduced and evidenced it.
- Automation artifacts excluded from findings: Playwright intercepts downloads (verified via
  download events + `saveAs`), one renderer crash from a 45 MB CDP file transfer (not reachable
  through the real file dialog), and transient screenshot stalls during the BUG-1 polling storm.
