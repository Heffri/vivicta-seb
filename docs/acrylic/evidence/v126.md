## Why the work order's literal "consecutive run" cannot fire here — and what replaces it

The five "Repayment within 2–5 yr." rows are NOT consecutive anywhere — not as printed (they
close five different component blocks, separated by those blocks' `Repayment after more than
5 yr.` / `Non-current liability` / `Current liability` / `Total …` rows) and not as `_page_rows`
slices the glued page (row map above: between the contingent 620-row and the bond-loan 2,835-row
sit the `Total 5,887 7,053` row and two `Repayment after more than 5 yr.` rows — a Total row and
another bucket's rows, exactly what the work order's run definition forbids). The model's own sum
crosses component blocks; no run-scan can ever reproduce it. So the binding constraint that makes
the sum PROVABLE is not run adjacency but **window membership of every summand plus the column
gate**, and that is what this lane implements:

- every row of ONE page whose label parses entirely inside the field's bucket window
  (`_row_bucket_span` -> `_span_bucket`, the v096 geometry) is a summand; at least two required;
- the column is the one where the note's own total row — total_debt's own verified quote, on the
  same page — ties to the verified total (`Total 5,887 7,053`, column 1). The prior-year column
  never substitutes (its 2–5y sum is 6,128);
- the family's sum in that column must equal the model's value (±2 or ±0.5%);
- the v103/v111 wrong-table guard is anchored at total_debt's row first: a refused scope declines
  the derivation with its warning, as `_finer_split_rows` does.

Total rows never join a family (a total word before the window wording refuses the row), rows of
another window never join (their geometry maps elsewhere), and rows whose wording is not at the
figure edge never join ("Current liability (overdraft facilities) – –" is a different
classification — an alpha tail says so). Everything that still fails drops exactly as before.

**Window parsing, not vocabulary** (v088's rule): "Repayment within 2–5 yr." / "Repayment after
more than 5 yr." parse ONLY behind the `repayment` prefix (`_REPAY_ROW`), so bare `yr`/`y` stays
a non-unit in `_bucket_span` and the v096 unit-table assertion (`_bucket_span("Repayment within
2–5 yr.") is None`) stands untouched; "Current liability" maps to the 1-year window by the v110
current-word family with a negative lookbehind that keeps "Non-current liability" out. No schema
word list grows; the column scanner reads none of this.

## Mechanism (`backend/pipeline/extract.py`, additions only)

- `_row_bucket_span(row)` — (window, wording) for a row whose repayment-timing wording sits at or
  inside it: `_bucket_span(_row_label(row))` for clean interval rows, else the LAST
  repayment/current wording whose tail is amounts-only, refused when a total word precedes it;
- `_REPAY_ROW` / `_CURRENT_ROW` / `_TOTAL_ROW_WORD` / `_wording_months` — the wording grammar;
- `_close(a, b)` — the work order's tolerance, ±2 absolute or ±0.5%;
- `_window_row_sum(...)` — the scan above; returns (quote, raw_label, n, first, last, page) or None;
- ONE call site, in the second computed-not-read branch AFTER `_between_rows` fails and before
  the drop (the identity-gated rescue stays first and narrower; fields dropped at the FIRST site
  — off-page quote, no printed figure anywhere — are untouched, which is why MedCap's fabricated
  quote still goes to v052's null-operand fill and Rusta's off-page 975 still goes to v096).
- Write-back mirrors `_between_rows`' branch: value kept, `period` = fiscal year, `raw_label` =
  the summands' wordings joined " + " (v051 convention), `source.quote` = the family rows joined
  when that quote verifies verbatim on the page (Rusta-style contiguous runs) else the family's
  first printed row (Stillfront's scattered blocks — the work order's "拼接(或第一行)"),
  evidence `["quote_on_page", "value_derived"]`, warning
  `"{key}: {value} is the sum of {n} rows on page {p} inside its window ({first!r} … {last!r}); kept as value_derived"`.

## Counter-examples (permanent cases, `pipeline/test_confidence.py`)

A model value equal to a sum the page does NOT prove stays null, warning `dropped as computed,
not read`, and no `kept as value_derived` warning — on a synthetic two-page note (p.1: Bond A
100/90, Bond B 50/40, `Total Repayment within 2–5 yr. 200 190`, `Total 150 999`; p.2: Bond C
60/55):

- **350** = 100 + 50 + **200 (the Total row's figure)**: the total row never completes the family;
- **130** = 90 + 40, the **prior-year column**: the column gate reads only the total-tying column;
- **210** = 100 + 50 + **60 (p.2's row)**: another page's rows never join (and p.2 has no total
  row to tie a column to);
- **464** = mixing in figures of **another window** (and of a `>5y` row the page does not even
  print): other windows' rows are never summands;
- **710** off a page with **no current rows at all**: no family, no rescue.

Unit assertions pin `_row_bucket_span`'s accept/refuse table (interval rows unchanged, glued
Stillfront wordings, the overdraft-facilities alpha tail, the total-word refusal, "Total within
1 year" refused by the grammar, "Non-current liability" refused by the lookbehind) and `_close`.

## Quote provenance, one subtlety

When the family rows are contiguous the joined quote is kept verbatim whenever it verifies modulo
the dash/whitespace normalization `quote_on_page` itself applies (MedCap's two Swedish rows — the
replay output byte-matches the old pipeline's join); a bare suffix match is NOT the join's
provenance, so Stillfront's scattered blocks quote the family's first printed row.
