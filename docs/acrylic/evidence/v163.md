# v163 — whole-KB CSV and per-company PowerPoint deck

## Delivered behavior

- `GET /api/kb/export.csv?section=debt_maturity&collection=all|wallenberg&q=` reads the saved KB extraction files directly: no PDF registration and no model invocation. It writes one downstream row per matching company, retaining the documented CSV columns and adding `stem`, all three maturity amounts, `review_status`, `human_review`, and `ready`.
- `GET /api/kb/export.pptx` applies exactly the same section, collection, and text-filter selection. The deck begins with a summary table (`company`, total, `<1y`, `1–5y`, `>5y`, identity, review), then appends the existing one-company slide for every saved extraction.
- `pipeline/ppt.py` now has `add_slide()` and `build_deck()` while `build_pptx()` retains the established single-slide export layout.
- The Knowledge base header has a compact **Export all** disclosure beside Compare. Its CSV and PPTX links are normal browser downloads and preserve the page's current collection and filter. Existing per-report download anchors were retained; the desktop shell has no separate renderer download interception.
- A non-ASCII filter is allowed in the URL but cannot be copied raw into a response header filename. The filename suffix is ASCII-safe, while the export continues to use the original filter for matching.
