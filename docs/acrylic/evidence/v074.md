## Four sources, cheapest first

```
POST /api/reports/fetch { company, year, country?, hint? }        (any name; /api/companies untouched)
└─ fetch.fetch_report
   ├─ 1  MFN company feeds → release attachments (Cision included) + stub-notice → issuer-site harvest
   ├─ 2  Nasdaq Nordic "Annual Financial Report" notice attachments
   ├─ 3  web: issuer-page crawl + DuckDuckGo filetype:pdf
   └─ 4  ONLY when 1–3 produced nothing usable AND provider ∈ {codex, claude}   (v074, new)
         llm.web_lookup() → `codex --search exec …` | `claude -p --tools WebSearch …`
         ≤3 candidate URLs → BAD_URL filter (+ decoded twin) → the SAME download + validation
         first survivor registers: source_url = model's link, note "model search (<provider>)",
         tags ["fetched", "foreign"]; file lands in paths.reports_dir() like every other fetch
```

Model unavailable or unparseable reply → the usual 404 shape with a `detail` that says what happened;
a cached report short-circuits everything (no model, ever).

## Premise checks against the real CLIs (zero calls)

- `codex exec --search` **does not exist** (clap rejects it). `--search` is a *top-level* flag:
  `codex --search exec …` parses on 0.153.4 and enables the native Responses `web_search` tool with no
  per-call approval. `codex features list` has no stable web-search feature flag, so the flag is the
  supported route; `_codex_chat` gained a `search=False` param that prepends it.
- `claude --help` (2.1.270): `--tools` takes an explicit allowlist — `chat()`'s `""` disables *all*
  tools; `web_lookup` passes `WebSearch`, and that allowlist is the whole difference.
- The work order's fallback plan ("model gives an IR page URL, backend crawls it") was not needed:
  the model returns direct PDF links that download fine (Shell's being the one unusable pair, below).

### Findings

- **Models return percent-encoded URLs, and some CDNs 400 on them.** Siemens' asset API serves
  `uuid:…` (raw colon, 200) and rejects `uuid%3A…` (400). `_model_candidates` now emits the decoded
  twin right after each candidate (a free second download attempt); that one change turned Siemens
  from a failure into the biggest report of the set. Unit-covered in `test_fetch.py`.
- **Nestlé's best official hit is the 67-page *Annual Review*** — year-matched, on nestle.com, passes
  the existing validation chain (its cover says "Annual Review", which neither NOT_REPORT nor IS_AR
  singles out) — but it is the summary volume, not the ~200-page full report. Tightening the page
  floor per issuer is extract/validation-layer territory, deliberately not touched here.
- **Shell is the honest failure** (2 searches, both same URL): its stable annual-report PDF is not
  surfaced by web search — only the expiring AEM stream link. The untried fallback is the work
  order's backup plan (fetch the IR page, harvest stable links server-side).

## Failure shapes (unchanged contract, clearer detail)

```json
HTTP 404
{ "detail": "no annual report found for Shell 2025",
  "tried": ["https://www.shell.com/.../shell-annual-report-2025.pdf"] }
```

A model search that *errored* (vs. found nothing) adds the reason, e.g.
`"detail": "no annual report found for X 2025; model search (codex) failed: codex exec exited 1: 429 …"`.
With no CLI provider the fourth level never runs and the 404 is byte-identical to before.
