## Why

GitHub issue #4 (24 h without response; owner's ruling: "if he doesn't reply, we add it"): since
09-18 the KB tab requests `collection_name=wallenberg` and so lists only the 11 Wallenberg-sphere
reports, while `data/kb` also holds the Mid Cap hardening extractions (85+ with stored
`debt_maturity`) reachable everywhere except the KB tab. Requested shape: expose the query
parameter as a segmented control, Wallenberg default, nothing else changes.

## What changed

`api.ts` — `getKb(collection: 'wallenberg' | 'all' = 'wallenberg')`, the parameter interpolated
into `collection_name`. The old signature was a hard-coded `wallenberg` URL; the default keeps
every existing caller on the same request.

`KbView.tsx`:

- **State + persistence** — `collection: 'wallenberg' | 'all'`, initialized from localStorage
  `arp-kb-collection` (`loadCollection()`, same try/catch shape as ResultsView's `loadViewer`;
  anything but `'all'` reads as the default). `switchCollection` writes the key back; private-mode
  failures just mean the choice doesn't stick.
- **Refetch** — the mount effect split in two: `getKb(collection)` keyed on `[collection]`
  (switching re-requests; the previous list stays rendered until the new one lands — no flash of
  "Loading…"), and a once-only effect for `getSchemas`/`getConfig`/`getLibrary`, which don't depend
  on the collection.
- **Selection cleared on switch** — `setSelected(new Set())`, so a stem selected in one collection
  can't sit invisible in the other and silently join the next Compare. `setError(null)` too, so a
  failed previous fetch doesn't linger over a working switch. Filter box, "With PDF only",
  Open and Compare behavior untouched (all operate on `entries`, which is whatever the current
  collection returned).
- **Control** — the existing `Segmented` primitive (`ui/segmented.tsx`, `role="group"`,
  `aria-pressed` per option), labeled "Collection", options `Wallenberg` / `All`, placed in the
  controls row directly left of the "With PDF only" checkbox — the work order's "next to it, same
  primitive kind".
- **Header count** — `"n reports · m with PDF"` → `"n reports · Wallenberg collection"` /
  `"n reports · all saved reports"` (the work order's count text, verbatim). Flag for the
  supervisor: this retires v019's "· m with PDF" suffix from the header; the number is still
  visible via "With PDF only" (the `x / y` filter count) and per-row badges. The eyebrow above
  dropped its now-hardcoded-wrong "Wallenberg collection ·" prefix and reads just "Knowledge
  base" (matching the Results/Compare eyebrows) — the collection's name now lives in the count
  line where the switch decides it.

## Red → green

**Red, before any frontend change** (two observations, one per tone, same run): the new e2e case
`kb: collection switch Wallenberg -> All -> back` failed in dark **and** light at the click on the
"All" option — `getByRole('group', { name: 'Collection' })` matched nothing. The preceding assert
of the default state (11 rows) passed, i.e. exactly the pre-lane behavior was red on the missing
control.

**After the implementation**, three successive test-side fixes (each run's error is quoted from
the Playwright context file, not reconstructed):

1. `getByRole('button', { name: 'All' })` strict-mode violation — substring matching made it
   resolve to "Wallenberg" too; both option lookups got `exact: true`.
2. `Expected: >= 190, Received: 11` — the heading's collection label flips with state at click
   time, so asserting on it didn't wait for the refetch; the row count was read mid-flight. The
   gate is now `expect.poll(() => rows.count()).toBeGreaterThan(11)` before the ≥ 190 assert.
3. After `page.reload()` the app lands on the default Extract tab (rail selection isn't
   persisted), whose own headings match `/reports/` — strict violation. The test clicks the
   Knowledge base tab again before reading the header.

**Green**: full suite `npm run e2e` — **28 passed** (26 pre-existing + the 2 new, dark + light;
26→28, none skipped), against the lane dev server. The reload leg also proves the localStorage
persistence: after reload the header reads "…· all saved reports" from `arp-kb-collection`, not
from in-page state.
