## The "only relax digit recognition" clause — checked, not used

The territory brief allowed touching `sweep_pages`'s digit test in three specific ways (Swedish
thousands-space grouping, parenthesized negatives, a bare dash standing in for zero) if a row
needed it. Every one of the 12 rows above was checked against all three shapes on its real page
text: none applies. Where a row already carries the value in its own tail (#2, #3, #8, #10, and the
data rows in #5–#7, #9, #11), the tail already contains an ordinary digit — Swedish space-grouping
and parenthesized negatives never defeated `re.search(r"\d", tail)`, which only asks "is there a
digit anywhere in the tail," not "can this be parsed as one number." Where a row's tail is empty
(the header-only lines in #1, #5–#7, #9, #11), it is genuinely blank — no dash, no digit, nothing —
so a dash-as-zero relaxation would not help either. No row in this batch is blocked by a number-
format problem; every remaining miss is a row/column structure problem instead. `extract.py`'s
`sweep_pages` was therefore left untouched: adding a digit-format relaxation with no real row to
justify it would be an unfounded code change with no fixture behind it, not a fix.

## Structural gaps, in one paragraph each

**Column-major ladder tables (#5–#7, tangen p.62; similarly shaped rows likely exist elsewhere in
the corpus).** `_page_rows` reconstructs a page top-to-bottom, one label + its own trailing numbers
per row (documented as "lossy for column-major layouts" in its own docstring). A table whose bucket
names are printed as their own header lines, with every instrument's numbers on a single following
data row, defeats this by design: the label that names the bucket and the digits that carry its
value are never in the same reconstructed row. `total_debt` already reaches this page because its
vocabulary matches the **data row's own label** ("Lån Kreditinstitut") directly — the bucket fields
have no equivalent, because a bucket's own name ("within 1 year") is never how a debt instrument's
row is itself labelled. Bridging a header-only row to a later data row is a change to the matching
function's shape, not its wordlist, so it sits outside this lane's territory.

**Duplicate bare labels split only by a heading (#9 rvrc p.95, #11 acast p.67).** Two physically
separate rows print the identical short label ("Lease liabilities" / "Current"), and only a
`Current liabilities` / `Non-current liabilities` (or `Lease liabilities` \[current\] / \[non-current\])
section heading above each — itself a separate, digit-free row — says which is which. No wordlist
addition can disambiguate two rows that read exactly the same; the field-specific version of the
qualifier (bare "current"/"non-current") is exactly the shape the schema already avoids elsewhere,
because it would match unrelated current/non-current splits on every other note in the corpus
(inventory, tax assets, provisions, ...) and inflate `sweep_pages` hit counts arbitrarily.
