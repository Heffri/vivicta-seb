## The 1 schema commit

**`due_within_1_year` synonym `"borrowings, current"`** (Gentoo Media). The report prints exactly one
borrowings line anywhere in the whole document — `"Borrowings, current 119,218 - - - 119,218 111,798"`
(p.92's liquidity note; the last column, 111,798, is the carrying amount, the earlier ones are the
undiscounted contractual cash-flow buckets) — cross-checked against p.89's financing-activities
roll-forward (`"Borrowings, current and non-current ... 111,798"`) and p.92's own accounting-policy note
("classified as current liabilities unless the Group has a right to defer settlement... for at least
twelve months"): there is no non-current borrowings row anywhere, so `total_debt` and
`due_within_1_year` are legitimately the same figure, same row. "Current" meaning "due within 12
months" is a universal IFRS balance-sheet convention, not a company-specific phrasing, so unlike a bare
one-word synonym this generalizes safely: verified offline
(`_label_known("Borrowings, current", due_within_1_year_field) == True`) and via a corpus-wide scan of
every stored `raw_label` in `data/kb/*/extractions/*.json` (100+ companies) — **exactly one existing
hit, Gentoo Media's own**, so the synonym cannot relabel any other field's row anywhere in the corpus.
`total_debt` was deliberately left alone (no synonym added there): granting it `label_known` from the
same phrase would also fire on a *different* company where a "Borrowings, current" row is genuinely
only the current *portion* of a larger total — that would mask a real wrong-total bug behind a false
1.0, the same risk class v037 already hit and reverted (Ework's bare "interest-bearing liabilities").

**Why it's a partial win, not a full fix**: replay (`--only Gentoo Knowit Cloetta`, 3 calls, one per
company) confirmed no regression (Knowit, Cloetta byte-identical) and confirmed the synonym fires
correctly offline, but the live replay call itself landed on yet a *third* row for Gentoo Media — p.89's
roll-forward note (`total_debt` still 111798, but `due_within_1_year` null again, this time missing
`page_is_statement` too since p.89 isn't in the top-2 candidates). Three calls, three different sourced
rows for the same two fields (p.92's row in pass 1, p.92's row again but `due_within_1_year` unattempted
in pass 2, p.89's row in the replay) — this is model recall variance the schema cannot fully close: the
fix raises confidence to 1.0 whenever the model *does* attribute `due_within_1_year` to the `"Borrowings,
current"` row (proven offline and in pass 1's own numbers), but can't make the model attempt that field
every time. Documented plainly rather than claimed as a full fix, per v037's own precedent.

## Not fixed, precisely diagnosed (this seed's real findings for the group)

### MedCap — new general gap: a repeated fiscal-year header (Group\|Parent columns) defeats every row-derivation repair, not just the bucket-as-columns one

Page 101 has a normal **row-per-bucket** table (not the v036/v040 bucket-as-columns shape):

```
Förfallotidpunkt för upplåning Koncernen Moderbolaget
MSEK 2025-12-31 2024-12-31 2025-12-31 2024-12-31
6 månader eller mindre 54,3 41,8 – –
6 – 12 månader 48,0 19,0 – –
1 – 5 år 616,5 316,7 – –
Totalt 718,7 377,6 – –
```

The model correctly read `due_1_to_5_years` (616.5) and `total_debt` (718.7) verbatim, and *correctly
computed* `due_within_1_year` = 54.3 + 48.0 = 102.3 (exactly right — the schema's own instruction to sum
finer first-year splits, just row-wise instead of column-wise) — but supplied a fabricated quote for it
that isn't on the page, so the pipeline correctly dropped it as "printed on none of pages, computed not
read." The reason **no existing repair can rescue it**, verified offline: the page's own year header
reads `["2025-12-31","2024-12-31","2025-12-31","2024-12-31"]` — the fiscal year appears **twice**
(Koncernen \| Moderbolaget columns, the same shape `_segment_column` already exists to handle
*elsewhere*), so `_year_column()` returns `None` (`run.count(str(fiscal_year)) == 1` fails). Every
row-summing repair that could otherwise prove `102.3 = 54.3 + 48.0` (`_derived_value`, `_between_rows`)
requires `_year_column`'s header first and bails out immediately without it. This is a **new**,
general (not company-specific) architecture gap distinct from v035/v036's bucket-as-columns finding —
a Group\|Parent (or any repeated-year) header on a debt-maturity page, not a bucket-header shape.
**Not fixed here**: extending `_derived_value`/`_between_rows` to accept a `_segment_column`-style
repeated header would touch code shared with `income_statement` and needs a full income_statement
regression pass this lane's budget doesn't cover — flagging for the group with the exact mechanism and
repro above, same posture as v035/v036/v037's own architecture-gap write-ups, rather than guessing at
scope.

### Ependion — same root-cause family as Acast/XANO/Ework: a two-column PDF layout scrambles the bucket header

Page 155 has a real bucket-as-columns table — `"Borrowing 167,546 35,636 380,348 583,531"` under a
header of `"Within 12 months / Between 1 and 2 years / Between 2 and 3 years / Total"` — and its total
(583,531) exactly matches the carrying-amount comparison table elsewhere on the same page, so this is
genuinely the right, reconciling table (no two-basis problem here, unlike Morrow Bank/Hansa above). The
model correctly computed `due_1_to_5_years` = 35,636 + 380,348 = 415,984 (again, exactly right, again
with no real quote) — dropped for the same reason as MedCap's row above. But **this one isn't a
`_year_column` gap** — verified offline against the raw page text: a sidebar TOC column is glued by
`parse.py`'s line-based extraction onto the same physical lines as the note's own header, splitting
`"Within 12 months"` / `"Between 1 and 2 years"` / `"Between 2 and 3 years"` across three separate,
non-adjacent `_page_rows` fragments (`"Between Between"`, `"Within 12 1 and 2 and"`, `"months 2 years 3
years Total"`) — none of which contains a complete phrase any schema synonym could match, and the
spelled-out `"Between X and Y years"` wording doesn't exist in the schema at all yet regardless (only
digit forms like `"1-2 years"`). This is the **same root-cause family** already diagnosed for Acast
(v037/v040: a two-column line-merge) and XANO/Ework (v036: a header wrapping across `_page_rows`
lines) — a `parse.py`-level column-major reconstruction (HANDOFF's own "Next for a teammate" item, and
already the fix `docs/CONFIDENCE.md` documents for Arion Bank's fully-scrambled pages) would likely
fix this whole family at once. **Not fixed here**: explicitly out of this round's territory
(`parse.py` untouched per boundary; the header-matching mechanism itself is v036/v040's, also excluded
this round). `total_debt`/`due_within_1_year` stay capped at 0.5 as a *downstream* consequence — the
`maturity_sums_to_total` check fails hard (not "missing") because `null_as_zero` treats the genuinely-
present-but-unread `due_1_to_5_years` as a real 0, so no schema fix could lift either field's confidence
even without the parser gap (see the null_as_zero finding below).

### Morrow Bank, Hansa Biopharma — carrying total correctly picked, no reconciling bucket source exists

Both hit HANDOFF's own "two tables" anticipated risk **the other way round from aak/v008**: the model
correctly prefers the carrying-amount table for `total_debt`, but the *only* table with a maturity-bucket
breakdown is on the undiscounted/contractual basis, and its total doesn't reconcile to the carrying
figure (Morrow Bank: 468.7 vs 265.0; Hansa: nominal 1,247,926 vs carrying 927,403 — not even close, this
loan's contractual repayment is roughly double its amortized carrying value per its own note). No schema
wording can manufacture a carrying-basis bucket split the report never prints — recording the shape, not
hard-fixing, per this round's own instruction. Hansa Biopharma additionally has a **locator miss**
(the real FY2025 version of its bucket table is on p.64, one page outside the `[65,66]` candidate
window — p.65 only shows the FY2024 comparative) but fixing that wouldn't help either, since p.64's
table is on the same non-reconciling contractual basis. Morrow Bank is explicitly HANDOFF-deprioritized
(Financials); its `total_debt` = "Subordinated loans" is plausibly the right bank-specific concept
(the bank's own borrowed capital instrument, as opposed to customer deposits) but that's a policy
judgment call, not something to encode as a general synonym — a bare "subordinated loans" synonym would
misfire at any industrial where that phrase names only one debt tranche among several, not the whole
total (the same over-generalization risk v037 already hit and reverted for Ework).

### VEF — real debt, wrong shape; Svolder — confirmed not a bug

**VEF** genuinely carries interest-bearing debt (SEK 500m sustainability bonds issued 2023, net SEK
240m outstanding after a partial redemption and VEF's own buy-back) — confirmed via a full-report
keyword scan (`bond|matur|förfall|räntebärande|interest-bearing|borrowing`, 43 pages) after the
default 2-page candidate window `[20,21]` turned up nothing but an **out-of-scope interest-coupon**
cash-flow schedule (`"Contracted cash flows due to borrowings refer to coupon payments... a floating
coupon of 3m Stibor + 650 bps"` — interest, not principal, explicitly descoped by both HANDOFF and the
schema). The real debt figures live in two separate roll-forward notes instead of one maturity table —
Group Note 13 (p.23, non-current portion, roll-forward format: opening balance, redemptions, reclassified
to short-term, closing balance) and a companion current-liabilities note (p.14-equivalent) — with no
single "total borrowings" line anywhere that sums them. This is a locator miss *and* a genuinely messy
source shape (the model would have to add two unlabelled note totals together with no printed sum to
verify against); not chased further given the effort/risk against this round's budget — recording the
shape. **Svolder**: confirmed not a bug by the same full-report scan technique — **zero** hits for any
debt-related keyword across all 88 pages; the only leverage-related content is p.18's own statement that
its 500 MSEK credit facility was **unused** at the balance sheet date. Matches Flat Capital's
already-established "not a bug" precedent (this same company, from v035, re-confirmed this seed).

## For the group

1. **A repeated/segmented fiscal-year header (Group\|Parent) is a distinct architecture gap from
   bucket-as-columns**, hit for the first time this seed (MedCap) — `_year_column` returning `None`
   silently disables every row-derivation repair (`_derived_value`, `_between_rows`) on such a page, not
   just the bucket-column mechanism. Worth its own scoped lane if it recurs (needs a full
   income_statement regression pass, since the fix would touch shared code).
2. **The two-column-PDF-layout family (Acast, XANO, Ework, now Ependion) keeps recurring** and is
   arguably the single highest-value fix left: a `parse.py`-level column-major reconstruction (already on
   HANDOFF's and `parse.py`'s own "Next for a teammate" list, and the exact fix `docs/CONFIDENCE.md`
   documents for Arion Bank) would likely resolve this whole cluster at once, rather than one company at
   a time.
3. **`null_as_zero`'s known limitation (already flagged in the schema's own comment) bit twice this
   seed** (MedCap, Ependion): a bucket that is genuinely printed but not yet successfully extracted is
   indistinguishable, to the check, from a bucket the report never prints — both read as 0, and the
   former then **fails the check outright** (capping confidence at 0.5) instead of reading as "missing."
   In both cases this seed, the model had already computed the *correct* value and only lacked a
   verifiable quote — a two-bug combination (a repair gap **and** this scoring conflation) worth the
   group's attention together, since fixing only one wouldn't fully resolve either company.
4. **Model recall variance is real and asymmetric**: Gentoo Media's `due_within_1_year` swung from a
   correct 0.9→(would be 1.0 with this lane's fix) down to null, across three calls with the *same*
   schema and the *same* cached page text — reconfirming v037's finding with a fresh example. Worth
   budgeting n≥3 trials (not 2) before trusting a specific field's confidence delta on this model, per
   v037's own suggestion — this round's 2-run rule caught the variance but a 2-run majority isn't defined
   when both runs disagree with a 1-1 split, only when they agree.
5. **Financials (Morrow Bank) confirm HANDOFF's own deprioritization is warranted**: "which liability
   line counts as a bank's total debt" is a product/policy question (deposits vs. subordinated capital
   instruments), not a parser bug — no general, safe fix exists without an owner ruling analogous to the
   carrying-vs-contractual one already made in v028.
