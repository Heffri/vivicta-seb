## Bucket rule (translated from ppt.py, verbatim)

`backend/pipeline/ppt.py` decides chart-vs-table with:

```python
by_key = {f["key"]: f for f in x["fields"]}
buckets = [k for k in BUCKET_ORDER if k in by_key and by_key[k]["value"] is not None]
if buckets: _debt_chart(...)   # else table
```

`MaturityChart` translates that literally: map fields by key, keep `BUCKET_ORDER` keys whose field
exists with `value !== null`, render the card iff that list is non-empty — **field keys, never the
section name** (a section renamed "note_20_x" with bucket keys still gets the chart; an hypothetical
section literally named "debt_maturity" without bucket keys would not). `BUCKET_ORDER` /
`BUCKET_LABELS` are copied verbatim from `ppt.py` with a "change it there first" comment — HANDOFF:
"update BUCKET_ORDER / BUCKET_LABELS in ppt.py — that is the only coupling". Every bucket gets a slot
even when null (null buckets are the normal case per HANDOFF — Ericsson has no >5y row).

**Identity check:** the card header shows `Total debt <value> <currency>` and `buckets sum = total
✓/✗` from the schema's identity check — looked up by name `maturity_sums_to_total`, never recomputed
client-side. Contract gap: the API's `Check` (docs/API.md / types.ts) drops the schema's
`identity: true` flag, so name lookup is the only way to find it; if the schema renames the check, the
constant in MaturityChart.tsx must follow. Check missing → the indicator is omitted, card still renders.

## Chart structure (pure SVG, zero dependencies)

- Card `Maturity profile`, header action row: total + check indicator (✓ `text-success` / ✗
  `text-danger`, `title` = the backend's check `detail`, e.g. `missing: due_after_5_years`).
- One SVG (`viewBox 0 0 640 300`, `w-full max-w-3xl mx-auto` — scales down to ≤900 px, stays ≤768 px
  wide on desktop): three slots in `BUCKET_ORDER`, one hit target per band.
- Marks per the dataviz spec: columns capped at 24 px with a 4 px rounded data-end and square
  baseline (path helper), hairline **solid** recessive gridlines (`--line-0`, baseline `--line-2`),
  clean y-ticks via a nice-step rounder (29 165 → step 10 000, top 40 000), unit = `extraction.currency`
  top-left, tick labels `tabular-nums` + `fmtValue`, bucket labels below the baseline in `--fg-2`,
  value on every cap in `--fg-1` (three columns — direct labels + the adjacent FieldsTable carry all
  values, so no tooltip is gating anything; each bar also has a native `<title>`).
- **Colors, token only:** bar fill `var(--primary)` (the glass sticker, never a flat accent); hover or
  selected one step brighter via `color-mix(in srgb, var(--ring) 45%, var(--primary))`; failure state
  lives on the check line (`--danger`), not the marks. Both tones screenshot-verified.
- **Null bucket:** dashed empty stub on the baseline + `—` (never a 0-height bar); a real `0` bucket
  renders as `0` on the baseline with no stub — the two states are contrasted in the screenshots.
- **Interaction:** clicking a column calls the same `onSelect` the table rows use, so v003's selection
  machinery drives the Source panel to that field's page; columns are `role="button"`, `tabIndex=0`,
  Enter/Space work, `aria-pressed` mirrors the table's selection, hit target = whole band.

Placement: the card mounts as a full-width second grid row (`xl:col-span-2`), below table+source,
above checks+ask. Consequence of the "ResultsView.tsx: mount point only" rule — reflowing v003's
table|source row was out of scope. At 1280+ the chart starts below the fold of a 900 px screen; see
Suggestions.

## Suggestions for the group

- **Lift the bucket rule into the contract.** `ppt.py`'s `due_*` presence rule, `BUCKET_ORDER` /
  `BUCKET_LABELS` and the identity check's name now live in two places (ppt.py, MaturityChart.tsx).
  The schema JSON is the natural single source: mark bucket fields (e.g. `"role": "bucket", "order": n`)
  and serve it through `GET /api/schemas` — then both consumers derive from the schema and HANDOFF's
  "only coupling" note disappears.
- **Expose `identity` on checks in docs/API.md** (the schema has it; the extraction drops it). The UI
  should not have to know a check's name to find "the" identity result.
- **Chart placement is one mount away from above the fold.** If the merger wants the chart as the
  hero (it mirrors the PPTX slide), moving the mount above the grid in ResultsView.tsx is a two-line
  change; this lane kept it below table+source because the work order scoped ResultsView edits to a
  mount point and v003's row order is another lane's contract.
- The embedded PDF viewer rendering blank inside very tall viewports is a Chromium quirk, not
  verified as an app bug; the Image viewer is unaffected.
