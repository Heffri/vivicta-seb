## What the gap actually was (the structure differed from the residual note)

Two defects, both in `_statement_row`'s direct helpers; either alone makes a printed bucket row unfindable:

1. **The exact-match set was verbatim** (`syn = {s.lower() ...}` compared against `_clean_label(_row_label(r))`).
   The label side is cleaned (digits glue to their neighbours: `Within 1 year` → `within1year`), the synonym side
   was not, so an exact hit was impossible for every digit-bearing synonym — 22 of debt_maturity's synonyms, 7 of
   income_statement's (same 7 v011b listed). The prefix fallback knew the labels since v011b, but it gives up when
   two rows share the prefix (`1-5 years` and `1-5 years, of which fixed rate …`), and the exact path is the
   designated tiebreaker.
2. **`_row_label` cut the label off before the matcher ever saw it.** It split at the first space-digit, so a row
   printed `Within 1 year 3 538 4 100` yielded the label `Within`, `Inom 1 år …` → `Inom`, `< 1 år …` → `<`.
   Even with the exact set fixed, neither the exact path nor the v011b prefix path can match a two-thirds label.
   (v011b's end-to-end Ericsson fixture never noticed: its page has a single-year header, so the null-fill /
   statement-row path never runs there, and the model-supplied `raw_label` bypasses `_row_label`.)

End-to-end before the fix (model answers nothing; note prints `Total borrowings 32 703 34 500 / Within 1 year
3 538 4 100 / 1-5 years 29 165 30 000 / 1-5 years, of which fixed rate 10 000 9 000`): only `total_debt` fills,
both bucket rows stay null, and the identity check fails with `missing: due_within_1_year`.

## What changed (2 files, +35/−4)

- **`backend/pipeline/extract.py`, `_row_label`** — the amounts start at the first number that is *not* followed
  by a lowercase word. `Within 1 year 3 538 4 100` → `Within 1 year` (the `1` goes on being used by the label);
  `14 4.74 8.32 MSEK` and `8, 9, 10, 11, 12 1,051 969` still cut before the number (a digit, an uppercase unit or
  a note column is not a label word). Every pre-existing output is unchanged — see the regression below.
- **`backend/pipeline/extract.py`, `_statement_row`** — the exact-match set is built from `_clean_label(s)` (the
  v011b shape), with the same guard as `_label_known`: a synonym that cleans away to nothing cannot enter the set
  (it would match every labelless row). The fallback branch is untouched.
- **`backend/pipeline/test_confidence.py`** — the cases below.

## Known limits (not hidden)

- `_row_label`'s label-word rule is lowercase-based: a row printed `… 11,77 kr` (lowercase currency after the
  amounts) would keep `kr` in its label. Prefix matching still finds such rows; only the exact-set hit is lost.
  No stored quote has this shape (739/739 identical).
- The heuristic keeps whole `Between 1 and 5 years` style labels regardless of case in the leading word; an
  uppercase continuation (`Within 1 Year`) would cut at the digit. Not seen in the corpus.

## Findings (out of this lane's territory, reported not fixed)

**The verbatim-synonym pattern survives in one more place**: `extract.py` around the `_derived_value` call
(`own_syns` for the sum-repair: `_clean_label(_row_label(...)) in {x.lower() for x in sf.get("synonyms", [])}`)
compares cleaned labels against verbatim synonyms, and passes that verbatim set into `_derived_value`. Same
one-line treatment as v011b/v012 would apply, but that is `extract()`'s repair block, not `_statement_row`'s
territory; digit-bearing synonyms are the ones it silently never matches (income_statement's synonyms are
digit-free apart from the 7 listed, so it has been invisible there).
