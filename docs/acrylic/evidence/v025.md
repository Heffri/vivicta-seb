## What changed

- **`frontend/src/components/ask/renderAnswer.ts`** (new): pure function, `renderAnswer(markdown) =>
  AnswerBlock[]`. Splits on blank lines into paragraph/list blocks (`-`/`*`/`1.` markers; a block is
  a list only if every line in it matches a marker, otherwise it's a paragraph), then a single
  linear inline scan per block for `**bold**`, `` `code` ``, and `[Company p.N]` citation refs
  (leftmost match wins via one combined regex; bold content is parsed recursively, code is verbatim).
  Anything else — headings, tables, links, unmatched `**`/`` ` `` — passes through as plain text
  nodes, per the work order's "most minimal" scope. No React import, no DOM: text in, plain-data node
  tree out.
- **`frontend/src/components/ask/renderAnswer.test.ts`** (new): 8 `node:test` cases (plain paragraph,
  blank-line paragraph split, bold, inline code, unordered list, ordered list, the exact fixture
  sentence, a company name containing `&`). Runs directly — `node --test
  src/components/ask/renderAnswer.test.ts` — no ts-node/tsx/vitest. Carries `// @ts-nocheck` (see
  "Not done" below for why) so it doesn't fail `tsc -b`; Vite's module graph never imports it (nothing
  in the app does), so it never reaches the production bundle either.
- **`frontend/src/components/ask/AnswerText.tsx`** (new): the only export is `AnswerText({ text,
  citations, onCitation })`. Turns `renderAnswer`'s node tree into real React elements (`<p>`/`<ul>`/
  `<ol>`/`<li>`/`<strong>`/`<code>`, no `dangerouslySetInnerHTML`). Citation nodes render as a
  `CitationChip` — a `Badge` in the exact same visual style as the pre-existing "below the answer"
  citation-chips row (`variant="outline"`, `render={<button/>}`, same hover classes) — and reuse that
  row's click contract: `onCitation ? onCitation(report_id, page) : window.open(pdfUrl(report_id,
  page), '_blank', 'noopener')`.
- **`frontend/src/components/AskPanel.tsx`**: one import added, one line swapped — the answer `<p>`
  that used to do `t.answer.answer.replaceAll('**', '')` now renders `<AnswerText text={t.answer.answer}
  citations={t.answer.citations} onCitation={onCitation} />`. The stale comment above it (which
  described the old plain-text approach) is removed. Nothing else in the file changed: the below-list
  citation chips, warnings row, `submit`, the KB-warm-up effect, and `EXAMPLES` are byte-for-byte the
  same as before. Full diff is 3 lines added, 2 removed.

## Citation-chip company matching (a real gap the work order flagged, handled)

The fixture answer's inline text is `[Nordic Industrials p.64]`, but `answer.citations[0].company` is
`"Nordic Industrials AB (fictional fixture)"` — not the same string. A plain exact match after
`answer.citations` would leave the chip permanently unmatched/inert for the very fixture the
acceptance flow tests. The backend already has this exact problem for its own `citations[]`
reconciliation against the model's self-reported company names (`pipeline/kb.py`'s `ask()`:
`_norm_name` + substring-containment-either-direction + "only one report loaded, so use it" as a last
resort), so `CitationChip`'s `matchCitation` mirrors that same three-tier strategy: normalized-exact →
substring either way → the sole citation if there's only one in the whole answer. Confirmed live
(see screenshots): `[Nordic Industrials p.64]` resolves to the fixture's one citation and renders
`Nordic Industrials AB (fictional fixture) · p.64` (the matched citation's own company string, for
byte-for-byte consistency with the pre-existing below-list chip's label). When nothing matches at
all, the chip still renders (per the work order) but as a plain (non-button) `Badge` with
`aria-disabled` + a `title` explaining why, not wired to any click handler — not exercised live since
the fixture always has exactly one citation, but covered by the "no match falls back to the
single-citation case" logic path and by reading the code.

## Not done / known gaps

- `renderAnswer.test.ts` carries `// @ts-nocheck` because `tsconfig.app.json`'s `types` array
  (`["vite/client"]`) doesn't include `"node"`, so `tsc -b` can't resolve `node:test`/`node:assert`
  module declarations from this file — out of territory to change (shared config, not in this lane's
  allow-list, other lanes concurrently on `acrylic`). The implementation files
  (`renderAnswer.ts`, `AnswerText.tsx`) are fully typed with no suppression; only the standalone test
  file is affected, and it never enters the app bundle.
- No headings, tables, or link syntax — explicitly out of scope per the work order. A literal
  markdown link `[text](url)` would pass through unparsed as plain text (safe: it doesn't collide
  with the citation regex, which requires the specific `p.<N>` suffix inside the brackets).
- List items don't support soft-wrapped continuation lines (a non-marker line inside an
  otherwise-all-marker block would currently make the whole block fall back to being treated as one
  paragraph rather than a list) — not exercised by the fixture, kept simple per "most minimal
  implementation."
- Didn't touch `AskView.tsx`, other views, `ui/*`, `index.css`, `api.ts`, `types.ts`, or the backend,
  per territory. No new dependencies.
