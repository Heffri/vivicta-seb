# w209 — Saab no-candidate/OCR packaging recovery

## Findings and fixes

### (a) Why `lib-saab_2025` had no candidates

The two Saab KB records were not crossed. They are different, matching 231-page editions:

- `saab_2025` is the English PDF and has **0/231 pages with any native text**; its committed
  `pages.jsonl` is correspondingly all blank.
- `saab_2025_sv` is the Swedish PDF and has readable saved text on **231/231 pages**.
- The English PDF has no PDF outline. Bounded registration OCR could read pages 1–8, but those
  front pages alone still produced `debt_maturity` candidates `[]`. Every later page remained
  `ocr_pending`, so the old on-demand path had no text from which to nominate the first pending
  page. This was the bounded-OCR chicken-and-egg case, not a `lib-`/KB read-path mix-up.

`backend/app.py` now factors candidate location into `locate_report_pages()`. If a fully blank
edition has no candidate but has pending OCR pages, an exact saved translation pair (`stem` and
`stem_sv`) with the same fiscal year and page count may nominate the first four page numbers.
Only those pages of the requested edition are OCR'd; the locator is then rerun on the requested
edition's own text. Swedish text therefore never becomes English evidence.

On the real English PDF, with zero model calls, the result moved from `[]` to
**`[194, 195, 154]`**. English OCR page 194 reads Note 29 and prints total interest-bearing
liabilities **MSEK 9,785**, current interest-bearing liabilities **MSEK 1,310**, due in one to five
years **MSEK 4,892**, and due after five years **MSEK 3,583**; the identity closes exactly:
`1,310 + 4,892 + 3,583 = 9,785`.

The regression also proves an ordinary KB-only report still gets nonempty candidates directly
from saved `pages.jsonl` without a PDF.

### (b) Language lookup and packaged resources

The installed failing app had complete `eng`/`swe` files under writable
`userData/data/tessdata`, but no `resources/tessdata`. The shell nevertheless synthesized
`TESSDATA_PREFIX=resources/tessdata`. Because an explicit environment path wins, that nonexistent
package location hid the valid writable copy.

The fix has two layers:

1. `desktop/main.js` sets an automatic packaged `TESSDATA_PREFIX` only after both requested
   language files are present. Otherwise it leaves the variable unset, allowing the frozen
   backend's package-then-writable-data lookup to continue. A genuinely user-supplied override
   remains authoritative.
2. `pipeline.paths.tessdata_dir()` accepts the automatic packaged directory only when every
   language named by `OCR_LANGUAGE` is present, then falls through to writable data. Its direct
   frozen-path regression covers an empty package directory, a complete data directory, a
   complete package directory, and an explicit override.

Packaging itself was already correctly wired by w204:
`prepare-resources.js` stages/downloads `eng.traineddata`, `swe.traineddata`, and the license, and
`electron-builder.yml` copies `build-resources/tessdata` to `resources/tessdata`. The rebuilt app
was inspected and contains `eng.traineddata` (**4,113,088 bytes**) and `swe.traineddata`
(**4,167,034 bytes**) in that location.

### (c) Refresh tool

The shared `refresh-app.ps1` copied `frontend-dist`, `backend`, and `data`, but omitted the separately
staged `tessdata` resource. It now refreshes `tessdata` as a fourth resource and documents it in the
header. This tool lives outside the repository, so the persistent shared-tool edit is not part of
the Git commit; the packaged acceptance below ran through that updated script and printed
`refreshed resources\tessdata`.

## Reference and remaining boundary

The UAW `demo` tree was searched before implementation for Windows resource/packaging patterns. It
has relevant general packaging evidence and `process.resourcesPath` usage, but no OCR/tessdata
implementation to copy; this change extends this repository's w204 resource pipeline.

The translation bridge is intentionally exact and bounded: only `_sv` twins with equal year and
page count qualify, and only four ranked pages are attempted. A scan with no outline and no saved
translation still needs the existing explicit full-OCR path; this change does not silently OCR an
entire annual report.

Baseline was `origin/acrylic` at `abf5355`; current `origin/acrylic` (`d92aa05`) was merged without
conflicts before delivery. The final app refresh was repeated after the only post-acceptance code
advance (frontend-only); the last upstream advance contained documentation only.
