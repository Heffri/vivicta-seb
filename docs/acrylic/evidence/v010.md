## 1. Empty / error / loading states — the inventory and what changed

Target spec (work order): loading = spinner + one sentence; empty = one sentence + next step; error = the
danger block, with collapsible details. Extract's faces keep compact paddings (`px-3 py-2 text-xs`) where
they sit in form rows — the block *recipe* (danger border/tint/text, `role="alert"`) is shared everywhere.

| View | State | Before | After |
|---|---|---|---|
| Extract | run in progress | spinner inside the Extract button + plain `text-xs` progress line | spinner in button + `LoadingLine` (spinner + sentence) |
| Extract | sections fetch failed | bare red `text-danger` line under the select | `ErrorBlock` (compact) — same copy, next step kept |
| Extract | library fetch failed | muted one-liner "Report cache unavailable (…)" — an error dressed as text | `ErrorBlock` (compact) |
| Extract | directory fetch failed | muted one-liner "Company directory unavailable(…)" (404 case deliberately quiet) | `ErrorBlock` (compact), both cases — an unavailable path is an error even when it's the known missing route |
| Extract | every report failed | full-bleed danger strip + tried-URL `<details>` | neutral hairline zone + `ErrorBlock` with the tried details inside — the same block the other views show |
| Extract | empties | "Nothing cached yet — pick a company…, or drop a PDF."; list "No matches." | unchanged — already the spec (sentence + next step) |
| Results | loading / view error | n/a — mounted only with an extraction in hand | n/a (unchanged); the page-preview placeholder is a media fallback, not a view error surface |

## 4. Extract three-face layout at 1440

Observation first (the work order allows overturning it): in the v002 screenshot the three faces are
*already* equal height — the grid stretches them — and the action bar is already flush below them. The
visible blank is (a) inside the cached face, whose single card leaves its face half empty, and (b) the
viewport remainder below the whole pane. What could honestly be improved without redoing anything:

- Directory search's list cap raised at ≥1280 (`max-h-64` → `min-[1280px]:max-h-80`): the widest face
  shows ~10 companies instead of ~8, the pane grows into the viewport's free space (bottom edge ≈710 px
  of 900 instead of ≈645), and the other two faces' leftover shrinks with it.
- The cached card grid now fills its face at ≥1280 (`flex-1 min-h-0`, same `max-h-72` cap retained —
  dropping the cap entirely would let a 100-entry library blow the row height up) with `content-start`
  so cards keep their own height instead of stretching. Below 1280 nothing changes.

The residual blank in the cached face with a one-entry library is data volume, not layout: the card
packs at the top of a taller scroll region and the hairlines run full height. `extract-{dark,light}.png`
show the result.

## 5. KB open without a PDF (409) — next step in the error block

`open()` records whether any leg failed with status 409 (the backend's "PDF no longer cached" — it needs
the PDF in `data/reports/` to re-register). When so, the error block gains one line pointing at existing
functionality: "Next step: fetch the PDF from the Extract tab's Directory search, then open it here
again." No backend change; other error shapes render without the line. Verified live by opening 4C Group
(no PDF on disk) — `kb-409-{dark,light}.png`.
