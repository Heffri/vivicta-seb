## 1. 平局分支的准确定义(工单问句:是"conf 相等"还是"check 同态 + conf 相等"?)

三组数据里两边都非空的字段实例共 **150** 个(v129 master 103+11+1、v136 20+4、v141 10+1+1 按
分支计)。按 `merge._pick` 的判定顺序分支:

| 分支 | 定义 | 字段数 |
|---|---|---|
| check | identity check 状态不同(一过一不过) | 1(v141 alligo total,conf 0.9=0.9 但 run2 check 过 —— **conf 相等不一定是平局,check 永远优先**) |
| conf | check 同态,conf 不等 | 16 |
| **tie** | **check 同态 且 conf 相等** | **133(v129 103 / v136 20 / v141 10)** |

即:现行实现里平局分支 = "check 都过/都不过 + conf 相等",conf 相等只是必要条件。

## 4. `decisions[key]` 文案写明规则名(工单第 3 条)

union 模式与 majority 的 3-way fallback 现在统一为 `<结果> (<一致?:> <规则名: 理由>)`,规则名
四种:`union: only non-null` / `union: check passed` / `union: higher conf` / `union: tie ->
run2|null`:

- `run1 (union: only non-null)` / `run2 (union: only non-null)`;`null (union: both null)`
- `run1|run2 (agree: union: check passed)` / `(conflict: union: check passed)`
- `run1|run2 (agree|conflict: union: higher conf)`(原 "higher confidence" 缩短,语义同)
- 一致平局:`run2 (agree: union: tie -> run2)`;**冲突平局:`null (conflict: union: tie -> null)`**
- majority fallback 同形,前缀 `3-way split -> union:`(如 `null (conflict: 3-way split ->
  union: tie -> null)`);majority 投票文案(`run1 (majority: run1+stored)` 等)原样不动;
  `matches_stored` 的 `run1 (matches stored)` 原样不动。
- 置 null 的字段用 extract() 自己的丢弃形状(`value/unit/period/raw_label/source` 全空、
  `confidence 0.0`、`evidence []`,保留 key/label)—— 与 extract 内部 "dropped as computed"
  的置空习惯一致,`recheck()` 对它不需要任何特判。
