## What changed

- **`CompareView.tsx`**: first column ("Field") is now `sticky left-0` (with a matching `bg-card` /
  `bg-muted/50` per row-type so scrolled columns don't show through) so field names stay visible while
  scrolling a wide matrix. Each report column header is now a small `<Card size="sm">` tile (name, FY,
  checks badge) instead of a bare button. The checks badge and the "failed to extract" badge now use the
  real `Badge` `success`/`danger` variants instead of hardcoded `emerald-*`/`red-*` Tailwind classes; the
  per-report error cell (when a report failed to extract) now reads `text-danger` instead of
  `text-destructive` — it's a data-status message, not a destructive action, per `DESIGN.md`'s own
  distinction between the two tokens. Everything else (row hover — already free via `ui/table.tsx`'s
  existing `hover:bg-muted/50`, `TableFooter`'s Details/CSV actions, the embedded `AskPanel`, horizontal
  scroll via `Card`'s `overflow-x-auto`) is unchanged markup/behavior, restyled only.
- **`AskPanel.tsx`**: citation chips get a stronger hover state (`hover:border-ring hover:bg-accent
  hover:text-accent-foreground`, was just `hover:bg-muted`); the warning row now uses `text-warning`
  instead of hardcoded `text-amber-700/80`; the failed-turn error line uses `text-danger` instead of
  `text-destructive` (same data-status reasoning as above). Example questions are now `Badge`
  "chips" (`variant="outline"`, `render={<button/>}`, same pattern the citation chips already used) instead
  of `Button`s. No change to `submit`, the index-warm-up `useEffect`, `EXAMPLES`, `replaceAll('**', '')`, or
  any prop/signature.
- **`AskView.tsx`** (new): the Ask tab's header (kicker "Ask", report name/count heading, one-line
  description) + `<AskPanel reports={reports} />` — this is the exact JSX block that used to live inline in
  `App.tsx`'s `tab === 'ask'` branch, moved verbatim into its own component per the work order.
- **`App.tsx`**: one block changed, nothing else — see diff below.

## Data + how it was tested

- Copied the shared real report into this worktree: `data/reports/atlas_copco_2025.pdf` (174 pages, sha
  matches `data/kb/atlas_copco_2025/meta.json`).
- Generated a 70-page fixture PDF with PyMuPDF (`data/reports/nordic_industrials_fixture.pdf`, script kept
  in this lane's temp dir, not committed): page 64 prints the exact quotes from
  `backend/fixtures/sample_extraction.json` (revenue/cost of sales/.../net profit), page 65 prints the EPS
  quote — so the fixture's citations open a page that actually shows the cited text instead of a blank
  filler page.
- Ran the app against a dedicated backend/frontend pair on this session's ports (`8006`/`5206`, per
  `common.md`'s "端口与截图" section) using the shared `vite.lane.config.mts` proxy override, so testing
  never touched the shared `:8000`/`:5173` other lanes were using.
- `ao browser` wasn't tried this round (the shared Playwright helper was already the documented first
  choice by the time this lane reached testing); drove the app with a custom Playwright script per lane
  (`uaw-lanes/v004-compare-ask/shot-main.mjs`, `shot-failed.mjs`, system Edge via `channel: 'msedge'`, zero
  downloads) instead of the shared `shot.mjs` DSL, because the flows needed precise, unambiguous locators
  (role=checkbox matched by its wrapping `<label>`'s accessible name, `title`-attribute matching for the
  Rail's icon-only buttons at ≤900px, role=button scoped to `<nav>` to avoid matching the *other*
  same-labelled "Ask" button that's always present-but-disabled inside the embedded `AskPanel`) that
  `shot.mjs`'s text-fuzzy `click`/`clicknth` steps kept resolving ambiguously against (e.g. `getByText('p.64')`
  matched the answer paragraph's own inline citation text before the actual citation chip).
- Verified the full acceptance flow end to end, including the parts that aren't screenshots:
  `POST /extract` on both the cached Atlas Copco entry and the uploaded fixture return the identical
  canned extraction (fixture mode ignores `report_id`/section content, as expected — "内容相同,没关系");
  `/ask`'s fixture answer carries the `p.64` citation; clicking that citation from **Compare's embedded**
  `AskPanel` (the one with `onCitation` wired) does jump the app to the Results tab (confirmed via
  `aria-current="page"` on the Rail's Results button, and the Results heading showing the right report) —
  the standalone Ask tab's `AskPanel` has no `onCitation` (unchanged from before this lane touched it), so
  a citation click there still opens the PDF in a new tab, which is the pre-existing, intentional fallback.
- After every test run, restored the two tracked KB files that `register_library`/`kb.save_report`
  rewrite as a side effect of opening Atlas Copco (`data/kb/atlas_copco_2025/{meta.json,pages.jsonl}` —
  same mechanism v001's evidence already flagged): `git status` was clean before the final commit.
