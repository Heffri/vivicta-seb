## 1. Wallpaper rework (`--wallpaper`, both tones)

v001 copied UAW's *no-OS-material fallback* (a single dim radial over an almost-black linear). In a browser that
fallback is the permanent state, so it was carrying too little colour: the window read as flat grey. v006 keeps
the one-material rule (still only `.glass` on the shell blurs) and gives the ground a real composition:

| Token | Before (v001, UAW fallback verbatim) | After (v006) |
|---|---|---|
| `--wallpaper` dark | `radial(120% 90% at 50% -20%, #2a3350, transparent 60%)` over `linear(160deg, #11131b, #0a0a0d 60%)` | `radial(90% 75% at 14% 0%, rgb(56 96 178/26%), transparent 62%)` + `radial(75% 65% at 88% 100%, rgb(112 78 190/30%), transparent 60%)` over `linear(168deg, #1b2444 0%, #131830 45%, #0a0a12 100%)` — deep blue → indigo → near black, soft blue glow top-left, soft violet glow bottom-right |
| `--wallpaper` light | `radial(#cfd9f0 …)` over `linear(160deg, #eef0f6, #e2e5ee 60%)` | `radial(rgb(168 190 235/40%) …)` + `radial(rgb(196 178 228/28%) …)` over `linear(168deg, #f7f3e9 0%, #ececf6 45%, #e6e6f2 100%)` — creamy white → pale blue-violet, same two-glow construction |

Glow alphas were not freehand: they are capped so the *resolved* glass ground (88–90% `--bg-0` over the
wallpaper's brightest/darkest point) keeps v001's text-contrast ladder — see §2. Screenshots `extract-dark.png` /
`extract-light.png` show the result.

## 3. Interaction states (additive; no props/exports/variant names touched)

- **Focus ring** — Button, SelectTrigger and Badge(-as-link) replace `focus-visible:border-ring ring-3 ring-ring/50`
  with `focus-visible:outline-2 outline-solid outline-offset-2 outline-ring`: a 2px solid accent outline with a
  2px offset whose gap shows the glass (Windows-11 style; a box-shadow ring with offset needed a solid offset
  fill, wrong on translucent glass). Verified settled computed style after Tab-focus:
  `outline solid 2px rgb(122 162 247) offset 2px` (dark accent). Note for whoever debugs this next:
  `transition-colors` in Tailwind 4 includes `outline-color`, so computed reads race a ~150ms transition from the
  base layer's `outline-ring/50` — wait before asserting.
- **Hover/active ladder** — outline/ghost buttons keep `hover:bg-muted` (`--bg-2`) and gain `active:bg-card`
  (`--bg-3`), one step up; `default` (primary) hover now uses a new **`--primary-hover`** token (dark
  `color-mix(in srgb, #7aa2f7 29%, var(--bg-0))`, light `color-mix(in srgb, #2b5cb4 24%, transparent)`) instead
  of `bg-primary/80`, which diluted the wash instead of raising the accent share the way UAW's own
  `.btn.primary:hover` does (dark 21→29%, light 16→24%). destructive hover was already a 10%→20% step; link and
  secondary unchanged.
- **Disabled** — `disabled:opacity-50 disabled:pointer-events-none` already in place on Button/SelectTrigger and
  inside the 40–50% spec; verified live: KB header `Compare` at opacity 0.5 + `disabled` before selection, 1.0 +
  enabled after two checks.
- **Select** — trigger gains `data-popup-open:bg-muted` (open = one step up, matching the outline button's
  `aria-expanded:` pattern; verified trigger bg rgba(32,32,39,.62) = `--bg-2` while open); items gain
  `data-highlighted:bg-accent data-highlighted:text-accent-foreground` and a persistent
  `data-selected:bg-accent/50 data-selected:text-accent-foreground` next to the existing check indicator
  (verified: first item bg rgba(48,48,57,.58) = `--bg-3`, `data-selected` + `data-highlighted` present).
  Disabled trigger/items keep their existing 50% + no-pointer treatment.
- **Table rows** — `TableRow` gains `aria-selected:bg-muted` so the ARIA-selected state matches the existing
  `data-[state=selected]:bg-muted`; verified identical resolved backgrounds when set either way, on a plain row,
  in both tones (dark rgba(32,32,39,.62), light rgba(0,0,0,.04)). Row hover verified changing live (KbView
  overlays its own accent hover on top of the primitive's `hover:bg-muted/50`; views are not my territory).
- **Scrollbar** — no change needed: `::-webkit-scrollbar-thumb` / `scrollbar-color` already ride `--line-2`,
  which is tone-aware; verified visually in both tones (`kb-*.png`, the 102-row table scrolls).

## 4. Table container hook

`Table` now takes optional `containerClassName?: string`, merged into the `table-container` wrapper div via the
same `cn` as everything else; default output byte-identical (`"relative w-full overflow-x-auto"` when absent).
Rationale recorded in DESIGN.md: the hardcoded `overflow-x-auto` forces `overflow-y: auto`, making the wrapper
the nearest scroll container and silently defeating sticky headers in bounded boxes (v005's workaround was an
arbitrary `[data-slot]` selector from outside). No view was switched over — views are not my territory; the
hook exists so the next one can.

Tooling notes for the next lane (all hit and worked around here):

- `shot.mjs`'s `--tonekey` defaults to `tone`, which this app never reads — pass `--tonekey acrylic-tone` or the
  tone silently stays dark (my first "light" shot was dark).
- The work order's `click=Select 4C Group` cannot work in `shot.mjs`: those checkboxes have role `checkbox`
  (not `button`) and only an aria-label (no text), and `shot.mjs` tries exactly those two locators. Used
  `getByLabel(...).check()` in the lane-local script instead.
- Base UI's `SelectTrigger` sets `aria-labelledby` (accessible name = the current value), so
  `getByRole('button', { name: 'Fiscal year' })` matches nothing even though the trigger has `aria-label` —
  locate by attribute selector.
