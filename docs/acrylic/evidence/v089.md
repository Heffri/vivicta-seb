## The switch

- `pipeline/extract.py` gains `debt_basis()`: env `DEBT_BASIS`, anything but `undiscounted` (or the
  alias `contractual`) reads `carrying` — a typo can never silently flip the basis. Read per `extract()`
  call, exactly where `EXTRACT_TWO_PASS` is read; default off-path is one string compare.
- Prompt: `system_prompt` picks `description_undiscounted` (schema top level and `total_debt`) when the
  basis is `undiscounted`, through a two-line `_basis_text` helper; the carrying prompt is byte-identical
  to every earlier round's (the schema's `description` is untouched). The undiscounted wording names the
  liquidity-risk table as the one to read, and `total_debt`'s variant says the total is the contractual
  cash-flow total (future interest included, typically higher than carrying, deliberately *not*
  reconciling to the balance sheet on this basis).
- Total slot: `_bucket_synonym_hits` tags by basis — under `undiscounted` the two word groups swap, so
  `ignore_header_synonyms` wording (v076's "total undiscounted / total contractual / …") fills the
  `total:carrying` **total-slot tag** and the carrying `header_synonyms` become `_ignore`. The tag name
  is kept (one comment now says it means "the basis total slot, whatever wording fills it") and zero
  downstream logic changes: `_bucket_header`'s has-carry preference and bare-Total demotion, the v085
  contiguous-run fallback, the column-count valve, `_bucket_assign`'s `_ignore` skip are all
  basis-symmetric already. `basis` threads `extract()` → `_fill_bucket_columns` → `_bucket_total_row` →
  `_bucket_header` → `_bucket_synonym_hits` as defaulted kwargs. The over valve and the dash-to-0 gate
  compare against the slot's own figure — the identity's basis by construction, no `_check` change.
- Result metadata: every extraction now carries top-level `"basis": debt_basis()`; `/api/config` mirrors
  the live value as `maturity_basis`.
- Desktop: `settings.js` gains `maturityBasis` (DEFAULTS `carrying`, sanitize allow-lists the two
  values, anything else falls back) and `envForConfig` sets `DEBT_BASIS` for **every** non-fixture
  provider — unlike two-pass this is model-independent, so Ollama passes it through too. `main.js`'s two
  two-pass log lines now also print `basis:`.
- Frontend: `SettingsView` gains `MaturityBasisSelect` (same base-ui Select as the model picker, options
  "Carrying amount (default)" / "Contractual undiscounted"), on all four provider cards next to the
  two-pass control; `StatusRow` shows `basis carrying amount | contractual undiscounted` from
  `/api/config`, so the plain-browser mirror shows it too (that endpoint now carries the field —
  unlike two-pass, which is why v047 had to hide it there). `ResultsView` prints `basis: contractual
  undiscounted` / `basis: carrying amount` in the header meta line whenever the extraction carries a
  `basis` (older stored extractions and other sections show nothing, exactly as before).
