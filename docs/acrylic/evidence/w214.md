# w214 — OCR language packs committed to the repository

## What changed

`data/tessdata/eng.traineddata` (**4,113,088 bytes**), `data/tessdata/swe.traineddata`
(**4,167,034 bytes**) and `data/tessdata/LICENSE` (**11,358 bytes**, canonical Apache-2.0 text,
sha-256 `cfc7749b…d30`) are now committed — 8.3 MB total, from `tesseract-ocr/tessdata_fast`
(Apache-2.0). A clone has the language packs PyMuPDF OCR needs with no download step. Sizes match
the packaged copies w204/w209 recorded byte-for-byte.

`.gitignore`'s blanket `data/tessdata/` became a precise whitelist: `data/tessdata/*` plus
negations for `*.traineddata` and `LICENSE`. Verified with `git check-ignore`: a planted
`junk.txt` and a leftover `.tmp` stay ignored; exactly the three intended files became addable.

`scripts/setup_ocr.py` is now idempotent: present files print
`<path>: already present, nothing to download` and it exits in 0.09 s with no network. The
download branch is preserved (repair installs, extra languages) and was re-verified in a
scratch-dir sandbox: empty root → all three downloaded, second run → idempotent messages.

## Lookup order and packaging

- `pipeline.paths.tessdata_dir()` needed no code change: in a source checkout its writable-data
  candidate *is* the repository's committed `data/tessdata` (dev resolution printed exactly that
  path), and the frozen candidate covers the installer's `resources/tessdata` — the w209
  override → package → writable order is untouched, only a docstring sentence notes that the
  writable copy is now the repo's own.
- `desktop/scripts/prepare-resources.js` already copied a local `data/tessdata` when present and
  only fell back to the network otherwise; with the files committed that copy path is now the
  normal path on every machine, so the w204 comment was updated (repo copy: offline and
  deterministic; download: fallback for a damaged checkout). Staging logic itself unchanged.
- `desktop/packaging.test.js` gained a guard that the three files exist in the checkout, so
  packaging can never silently fall back to the network on a clone missing them.
- `.github/workflows/desktop.yml`'s `python ../scripts/setup_ocr.py` step is now a no-op by
  idempotency and is left in place as a bootstrap fallback; CI packaging uses the committed copy.
