## 3. Real bug found: the packaged app crashed on launch — `settings.js` was never added to `electron-builder.yml`'s `files:` allowlist

Built the **first** `npm run dist` (before touching any packaging config, to establish a genuine red
baseline per LESSONS #15) and double-click-launched the resulting portable exe with an isolated
`--user-data-dir`. It crashed immediately with a native error dialog. `dialog.showErrorBox`'s window
title is always the generic "Error" on Windows (v029 §6.4's finding, confirmed again here) and this
dialog is a modern TaskDialog, not a classic `MessageBox` — `EnumChildWindows` + `WM_GETTEXT` (v029's
own technique) came back empty (TaskDialogs render their content through DirectUI compositing, not
child HWNDs with gettext-able text). Read the real message with UI Automation instead
(`System.Windows.Automation`, walking the accessible tree for `Name` properties):

```
A JavaScript error occurred in the main process
Uncaught Exception:
Error: Cannot find module './settings'
Require stack:
- ...\resources\app.asar\main.js
```

Root cause: `desktop/main.js` has done `const settings = require('./settings')` since v033 landed
(`desktop/settings.js`, new file), but `electron-builder.yml`'s `files:` allowlist —
written in v029, before `settings.js` existed — was never updated:

```yaml
files:
  - main.js
  - preload.js
  - icons/icon.ico   # settings.js missing here
  - package.json
```

electron-builder only stages listed files into `app.asar`; `main.js` shipped, `settings.js` did not,
so every packaged build since v033 merged — **including the 0.1.0 exes already sitting in
`vivicta-shared\dist\` before this lane ran** (dated today 13:26, i.e. after v033/v038/v039 were all
already on `acrylic`) — would crash on first launch for anyone who actually double-clicked them. v033's
own evidence only exercised dev mode (CDP against `electron .`), never rebuilt or re-launched the
packaged exe, so this regression had no lane catching it until now — exactly the gap this packaging
lane exists to close (LESSONS #12: "夹具在" ≠ "修复落地", extended here to "上一次打包能跑" ≠ "这次打包能跑").

**Fix** (within this lane's explicitly permitted territory): added the one missing line —

```yaml
files:
  - main.js
  - preload.js
  - settings.js
  - icons/icon.ico
  - package.json
```

Rebuilt (`npm run dist`, §1 second row) and re-ran the full double-click acceptance pass (§4) — no
crash, every check green. nsis and portable targets both package from the same staged `app.asar`
contents, so this fix covers both outputs even though (per the work order) only the portable exe was
actually launched — not re-verified separately for nsis, consistent with v029 §8's own reasoning for
not installing the nsis build.
