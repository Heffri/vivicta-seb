`<1 year` and `1-3 years` are bucket words; `>3 years` ([36 months, ∞)) is off the schema's 1/5-year

`maturity_sums_to_total` now carries `require_explicit_values: true` (the 09-18 team ruling), so those
nulls are "missing", not zeros — any fix has to produce explicit values.

## Rule 1 — off-grid boundary columns (commit `ba20176`)

`_offgrid_hits` scans an amount-free header row for maturity-window wording no bucket word claimed
(`>N years` / `over N years` / `N-M years` / `mer än N år` …) whose bounds in months are not the grid
points {0, 12, 60} — Karnell's `>3 years` → tag `offgrid:36-|>3 years`. `_bucket_header` counts the
tag as a column of its own (4 keys vs 4 amounts: alignment restored) but never as one of the ≥2
distinct bucket keys its valve requires, and `_bucket_assign` skips it like `_ignore`. Two things an
off-grid column can still prove, both in `_fill_bucket_columns`:

- **Its nil** (v078's dash, one level up): no debt is due in that window at all, so every bucket the
  window covers outright is a 0 — `>3 years` printing "-" makes `due_after_5_years` (whose whole
  window [60, ∞) it spans) the report's explicit 0, written `value_derived` (the dash sits in a
  column of the table's own naming, not the bucket's own column, so not `printed_nil`). Gated by
  v078's own arithmetic closure — the zeros join the sum, and `43.5 + 353.7 + 0 == 397.2` is itself
  the proof of the 0. Unproven, the covered bucket keeps its null.
- **Its value** is an honest decline: the split across the straddled boundary is a guess no check can
  arbitrate. The warning names it: `'>3 years' 173 straddles the 5-year boundary`.

Guards: a phrase a bucket word already matched ("1-3 years", "> 5 years" via `_BUCKET_BOUNDARY`) and
any on-grid phrase ("mer än 5 år" IS `due_after_5_years`' own window) are left entirely to today's
reading; data rows print amounts, so they never contribute header columns (the bare-Total rule, v060).

## Rule 2 — a debt-scoped row outranks a bare table Total (commit `8dbda1e`)

`_bucket_total_row` returned total-worded and bare Total/Totalt/Summa rows ahead of debt-row
candidates, so the first row tried was the table's whole-scope total the moment any lever opened the
header. Rows named by the total field's own wording (`proper`) or by `row_synonyms` (`candidates`)
now outrank bare table totals (`bare`); with only bare rows, order and behaviour are exactly today's.
This is the code-layer half of v088's own conclusion — no schema key can express "this Total is the
wrong scope", so the scope decision belongs to candidate order.

columns remain unnecessary and (per v088's Rusta trap) still need the full-corpus replay gate.
