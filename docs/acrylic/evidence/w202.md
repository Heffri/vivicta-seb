# w202 — roster companies without standalone reports

## Plan

1. Trace the Investor URL through discovery, candidate confirmation and issuer validation.
2. Give curated private holdings parent-report metadata and stop them before every standalone-report path.
3. Open the saved parent result directly from the directory, land its source pane on the portfolio page, and expose the same relation in Company map.
4. Cover the boundary with backend and browser tests, then run the required regression gates.

## Root-cause trace

The reported suspicion holds at the product boundary: a parent PDF can be accepted as the child report when the child is named often enough in the opening pages. The generic issuer check is intentionally textual (`backend/pipeline/fetch.py:700-723`), so the dedicated regression builds an Investor-shaped PDF that passes `_validate(..., "Sarnova", 2025)` before demonstrating that the new guard prevents its use.

The URL was **not** manufactured by the old local candidate lookup. The pre-change lookup was a roster-identity match; the current saved-first replacement is even narrower: `_local_candidates` accepts only exact normalized names or an exact identifier (`backend/pipeline/fetch.py:260-281`). It cannot map Sarnova to a cached Investor record. The viable URL chain is instead:

1. `_model_discover` retains a model-returned candidate URL (`backend/pipeline/fetch.py:287-315`);
2. the confirmation card calls `onUseCandidate` (`frontend/src/components/upload/CompanySearch.tsx:213`);
3. `useCandidate` forwards `c.url` into `/fetch` (`frontend/src/components/UploadView.tsx:219-226`);
4. `fetch_report` tries that confirmed URL before its other discovery sources (`backend/pipeline/fetch.py:1017`).

The fix stops the incorrect interpretation rather than making the issuer validator guess an ownership graph: `NO_STANDALONE_REPORTS` records 13 curated members, `discover` returns their parent-report fact with no web call, and both the API and pipeline fetch boundary reject an attempted standalone download. The UI opens `investor_2025` through the saved-KB path and passes the relevant page (41) to Results; it does not call discover, fetch, or extract. The Company map reads `reported_members` from the KB listing.

I also searched the supplied UAW tree for roster/parent-report behavior. No reusable implementation was present; `annual-report-panel.tsx` is progress-panel UI only, so no UAW code was copied.

## Red → green coverage

Before the metadata overlay, the isolated company-directory assertion failed: the Sarnova row had only its normal roster fields and `cached_years`, with none of `no_standalone_report`, parent-report metadata, or `report_page`.

After the change:

- `backend/test_collection.py` verifies the exact Sarnova API row, page lookup, all ten Investor portfolio members in `reported_members`, no AI discovery, and a 409 standalone-fetch refusal.
- `backend/pipeline/test_fetch.py` proves a parent report can satisfy the prior text validation condition, then verifies the private-holding guard makes no URL/model/feed request.
- `frontend/e2e/tests/collection-corners.spec.ts` clicks the Sarnova directory row and verifies Investor AB / Page 41 while asserting zero discover, fetch, and extract requests.
- `frontend/e2e/tests/ask.spec.ts` now asserts the neutral linked-report source label; a parent portfolio page must not claim it was cited by an Ask answer.
