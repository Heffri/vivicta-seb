# v050 — extract.py: accept a report-stated prose no-debt sentence as total_debt 0 (schema opt-in), offline red/green

Lane `ao/vivicta-glm-12/v050-zero-debt`, off `origin/acrylic` (`e3bbcf1`, still its tip at merge
time). **Zero model calls**: every observation below is the deterministic post-processing
(`extract()`) fed constructed or stored field answers — nothing touched any LLM provider. Page
texts come read-only from the shared seed KB directories (`seed1-4-kb`).

## Why (the work order's premise, confirmed by reproduction)

v048 (seed 4) recorded Creades: the model, after the description change, answered `total_debt = 0`
quoting p.61's *"Investmentföretaget har varken räntebärande skulder eller kundfordringar"* — a
sentence with zero digits — and the pipeline dropped it:
`total_debt: 0 is printed on none of pages [61, 62]; dropped as computed, not read`. Reproduced
exactly on the baseline: `quote_on_page` requires at least one number token in the matched span
(unchanged here, per territory), so a prose negation can never verify, and `_value_in_quote(0, ...)`
finds no standalone printed 0 on pp.61–62. General shape (investment companies, net-cash
companies), not a Creades special case.

## The rule (as implemented, `extract.py`)

New `_stated_zero(field, sf, schema, texts)` — every gate must hold:

- (a) the field's own schema object opts in: `"zero_if_stated"`. Naming follows the existing
  check-level `null_as_zero` precedent (a schema switch permitting exactly one lenient reading,
  read at exactly one place);
- (b) the value is exactly 0;
- (c) the quote carries **no digit at all** — a numeric quote is the existing gates' business
  (`quote_on_page`, `repair_value`, the printed-zero checks), never this one;
- (d) the quote sits **verbatim** on the cited `source.page`, whitespace/NBSP-insensitive, via
  `parse.normalize_ws` substring match — a small local helper; `quote_on_page` itself untouched;
- (e) the quote names the field's subject: a schema `keywords` entry or one of the field's
  `synonyms` occurs in the normalized quote;
- (f) a negation word from the **schema's own list** occurs in the quote.

Both same-shaped provenance gates honour it — the per-field gate inside the field loop (where
Creades actually dies) and the identical post-check sweep at the end (the work order asked for a
judgement on the second one: yes, the same condition must release it, otherwise a field surviving
the first gate on the old printed-0-nearby path would still be re-dropped later): the first calls
`_stated_zero` before dropping, the second skips fields already recorded in the run's
`stated_zeros` set. A kept field gets evidence `["quote_on_page", "stated_zero"]` and a warning
naming the sentence; otherwise both gates behave byte-identically to before.

**Confidence lands at 0.50 by the existing rules — no new cap.** Arithmetic: `quote_on_page` 0.35
(the sentence genuinely is on the page — verified by the stricter exact-substring check),
`stated_zero` 0.20 (added to `WEIGHTS` as the exact analogue of `value_derived`'s "stands in for
value_in_quote when the printed number is unreadable"; here the number is never printed at all),
`arith_ok` 0.20, `period_ok`/`page_is_statement`/`unit_ok` 0.05 each = 0.90, then the existing
"the row is on the page but this number is not in it" cap applies → 0.50 — the same tier v048
observed for Svolder's page-verified zero-debt read.

**Negation list: added, and it lives in the schema, not the code.** Without it, a bare row label
quoted alone off a column-major table ("Summa räntebärande skulder", XANO's 8-number row) satisfies
(b)–(e) — verbatim on page, debt vocabulary, digit-free — and would mint a false 0. The list is the
opt-in key's value (`zero_if_stated.negations`: varken, ingen, inga, inget, inte, icke, ej, utan,
saknar, noll, skuldfri/skuldfritt/skuldfria, no, not, neither, nor, none, without, lacks, zero,
nil, debt-free), matched on whole normalized words, so wording fixes are schema edits. Minimum-rule
check: gates (b)–(e) alone were not enough; (f) is the one extra rule that blocks the known
false-accept shape.

**The identity check.** `_check`'s all-buckets-null guard ("would pass on nothing") is lifted only
when the identity's *remaining* operand(s) are themselves stated zeros: a new optional
`stated_zeros` set threads through the six existing `_check` call sites that already receive
`texts=`. Creades: the buckets stay null (no opt-in for them — their descriptions forbid a 0 for an
unprinted bucket), and the check passes as 0+0+0 == 0 with every operand named in the detail. A
total_debt 0 arriving by any other route (a printed "0" row) leaves the old
"missing: due_within_1_year" behaviour untouched — Ericsson, MedCap, Ependion and Acast cases in
the suite all pass unchanged.

## Findings

1. **A dated prose sentence falls back to the old path, on purpose.** "Per 31 december 2025 har
   bolaget inga räntebärande skulder" carries digits (the date), so gate (c) declines it and the
   old gates decide — dropped unless a standalone 0 is printed nearby (which is exactly what saved
   Svolder in v048). Widening (c) to "no digit carrying the value" would need a value-token notion
   that starts re-implementing `quote_on_page`; and the work order's own counter-example pins
   digit-bearing quotes to the original path. Left at the minimum rule count.
2. **Flat Capital is a two-sided datum.** Its real p.18 also prints "of which interest-bearing
   liabilities ... 0 TSEK (0)" on the candidate page — so even the old path can land a 0 here (at
   0.25, quote not found). The p.33 prose sentence remains unreached because p.33 is never a
   candidate — the locator-scope gap v035 recorded, unchanged by this lane.
3. **The corpus had exactly one candidate for this rule.** Scanning all 42 stored seed runs, only
   Creades ever produced a `total_debt: 0 ... dropped` warning; the rule's blast radius on today's
   stored data is that one company, and the 42/42 replay plus the counter-example suite bound it
   from both sides.
