## The shape and the gap

A borrowings note split into a **non-current and a current section**, each closed by its own
Summa/Total row, with **no third grand-total row** anywhere in the block — NOTE's Not 19
(`data/kb/note_2025` p.107, real text):

```
Not 19. Räntebärande skulder
Långfristiga skulder 2025-12-31 2024-12-31
Banklån 7 241 9 112
Leasingskulder hänförlig till materiella anläggningstillgångar 118 027 134 803
Leasingskulder hänförlig till nyttjanderättstillgångar för hyrda fastigheter 103 593 106 108
Summa 228 861 250 023
Kortfristiga skulder
Checkräkningskredit 135 399 -
Factoring (fakturabelåning) 322 054 316 185
...
Summa 595 420 380 108
```

228,861 + 595,420 = **824,281**, printed nowhere as one number; the report's own total exists only
as p.109 prose — "räntebärande skulder **824,2** (630,0) MSEK" — a thousands-to-millions conversion
the provenance gates structurally cannot see (v099 Finding 4). v088 pass 2's model DID compute the
824,281 and was correctly dropped as computed-not-read; `due_within_1_year` survived (595,420 @0.9,
the Kortfristiga Summa row itself). This is v088's gap 2 ("current/non-current granularity only:
Ambea, Karnov, NOTE"). No existing repair reaches the total: `_between_rows` needs ≥2 verified
operand rows (only w1y has one), `_fill_bucket_columns` needs a bucket-column header (there is
none), `_finer_split_rows`/`_date_bucket_derive` anchor on total_debt's own verified row (null).
The maturity buckets such a note names are exactly two — everything non-current and everything
current — so it proves `total_debt` (A+B) and `due_within_1_year` (B, the current section's own
printed subtotal) and nothing else.

## Mechanism (`backend/pipeline/extract.py`, additions only)

- **Scope**: the walk runs on `pages[:2]` + the identity fields' model-cited pages (the
  `_fill_bucket_columns` convention); the prose corroboration scans the full candidate list
  (`pages`) — NOTE's corroborating prose sits on p.109, candidate 4, never in the top-2 window.
- **Structure, not vocabulary** (v088's schema ruling stands — no word lists added): a note TITLE
  row (a debt word of `total_debt`'s own `synonyms` + `row_synonyms`, printing no figures) heads a
  section heading A (`Långfristiga | Non-current | Long-term`), then A's rows, then A's bare
  Summa/Total row; directly below — past furniture only, any printed figure declines the whole
  block (the stacked-table shape) — a section heading B (`Kortfristiga | Current | Short-term`, and
  not A: "non-current" contains "current"), B's rows, B's Summa; and no total-shaped row within 6
  rows after B's Summa — a block that prints its own grand total (Ambea G18's
  "Total interest-bearing liabilities 12,643") is that row's shape, not this one. Headings must
  print no figures (a bare-year header line is furniture); "Non-current lease liabilities 8,220"
  is a data row, not a heading.
- **Proof**: both Summa rows must resolve the SAME year header (`_row_year_column`, row-anchored —
  NOTE's `2025-12-31 2024-12-31` sits on the Långfristiga heading row, reduced per v102) and parse
  to its column count; each section's own detail rows must sum to its Summa in **every** column
  (NOTE A: 7,241+118,027+103,593 = 228,861 / 9,112+134,803+106,108 = 250,023; B likewise 595,420 /
  380,108) — the note's own arithmetic is what proves a bare "Summa" is its section's subtotal and
  not another table's, and what kills a third table nested inside a section. The v103 wrong-table
  guard (`_table_scope`) runs on the Summa row; the function is also carrying-basis only
  (`debt_basis()` — the shape is a balance note; under the undiscounted basis the schema points
  elsewhere).
- **Adoption**: a surviving (verified) model total that DISAGREES with A+B (±2) declines silently —
  the note and the model then name different scopes, a human's question, not a repair's (NOTE's own
  BS lines print 696,629 for the same debt, v099's classification quirk). A model total dropped as
  computed-not-read arrives null and does not block: that is exactly NOTE's case. Corroboration —
  the model's own total matching, or a candidate page's prose printing the total as the /1000
  conversion ±0.1 (p.109's "824,2"; the report truncates its MSEK prose) — only names itself in
  the warning; without it the adoption stands on the two closures.
- **Writes**: `total_debt` = A+B, `value_derived` (the sum is printed nowhere), quote = the
  contiguous span from Summa A through Summa B — both Summa rows verbatim; a two-row join of
  non-adjacent rows is not a page substring under `quote_on_page`'s gap discipline, and the span is
  the `_between_rows` precedent — raw_label = `"Summa (Långfristiga skulder) + Summa (Kortfristiga
  skulder)"`. `due_within_1_year` = B from its own Summa row (`value_in_quote`; the model's own
  equal answer is left untouched, a disagreeing one replaced with a warning naming it). 1–5y / >5y
  are never touched — the note prints nothing that splits them, so they stay null and the check
  stays honestly `missing:`. One adoption per extraction; every decline is silent (counter-examples
  must replay byte-identical, warnings count included).

## Findings for the group

1. **NOTE's prior-year corroboration also exists in prose** — p.109's "(630,0) MSEK" against the
   two sections' 2024 column 250,023 + 380,108 = 630,131 — the report truncates its MSEK prose
   (630,131 → "630,0", 824,281 → "824,2"), so a prose matcher must tolerate ~0.13, not just
   rounding; this lane's ±0.1 gate is deliberately checked against the CURRENT year's pair only
   (824.281 − 824.2 = 0.081) and the prior-year figure is listed here for whoever picks up
   prior-year prose.
2. `prior_year` metadata is honestly absent for NOTE: the span quote's rows include the label-only
   "Kortfristiga skulder" heading, so `_prior_year_fill`'s rows-as-columns admission (every row
   ncols-wide) declines — the two-section shape has no prior-year read short of summing the two
   sections' 2024 columns, which is a v091-shaped extension, not forced here.
3. Ambea's G18 page is now double-covered: the existing v102 block (model answer) and v110's
   all-null block — the pair shape declines in both because the block prints its own grand total,
   which is the pre-existing statement-spread fill's row. Any future shape work on that page has
   two permanent guards.
