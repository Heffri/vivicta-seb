## The gap

`data/kb` holds stored extractions for 102 companies, but `data/reports/` starts empty on a fresh
clone (PDFs gitignored, ~130 MB). `GET /api/kb/{stem}/{section}` needed the PDF to re-register the
report (`register_library` → a real `report_id`), so **every** stored entry 409'd — nothing could be
opened, compared, or exported without first fetching a PDF. This decouples "read the stored
extraction" from "render page images".

## What changed

**Backend** (`backend/app.py`, commit `backend: …`):

- `register_kb_only(stem)` — registers a KB entry from its stored `meta.json` as `kb-<stem>`:
  company/fiscal_year/pages/filename straight from disk, **no PDF path, no parse, no writes** (the
  test asserts `meta.json` is byte-identical after a KB-only open — LESSONS 27's rewrite only ever
  came from the `register_library` path, which this never runs).
- `kb_extraction` — `register_library(entry) if entry else register_kb_only(stem)`; the 409 branch
  is gone.
- `report_pdf` / `page_png` — when `pdf_path(report_id)` doesn't exist (exactly the KB-only case;
  every other registration writes or points at a real file), 404 with the fetch-it detail above.
  `page_png` checks after the existing range check, so an in-range page of a KB-only report gets the
  fetch hint, never a misleading "out of range".
- `list_kb` — each entry gains `pdf_cached` (the same `library_index()` join the open path uses);
  `report_id` prefers the non-`kb-` registration when both exist.

**Frontend** (commit `frontend: …`):

- `types.ts` — `KbEntry.pdf_cached?: boolean` (optional: absent on a pre-v092 backend).
- `KbView.tsx` — `hasPdf(e)` now reads `e.pdf_cached` first, with `GET /api/library` kept as the
  old-backend fallback; Open button and row checkbox are **enabled** for no-PDF rows (only
  `!sections.length` still disables); the "no PDF" badge stays and now carries the tooltip
  "page images unavailable until the PDF is fetched from Extract" (same text on the enabled Open /
  checkbox and the shared sr-only span); "With PDF only" and the header count switch to
  `pdfKnown` (either source) and keep their v019 semantics. The 409-era error block and its
  "Next step" paragraph are removed — that status can no longer occur.
- `SourcePanel.tsx` — the existing broken-page placeholder gains one sentence, "Fetch the PDF from
  Extract (directory search) to see the pages." (one copy change, layout untouched).
- `api.ts` — one comment line updated to the new open contract.

**Docs** (commit `docs: …`): API.md gains the previously-undocumented `/api/kb/{stem}/{section}`
row with the new semantics + `pdf_cached` in the `KbEntry` type; README's fifth contract gap marked
fixed; this file.

**e2e** (`frontend/e2e/tests/kb.spec.ts`, in the frontend commit): the old second test asserted
exactly what this lane removes ("a row with no cached PDF has a disabled Open button"), so the
e2e-green gate required rewriting it: it now filters to `abb_2025`, asserts badge + **enabled**
Open, opens into Results (heading, Export JSON, a real stored value), switches the Source viewer to
Image and asserts both placeholder lines. The atlas test is unchanged. This file was not in the
work order's territory list — flagged here for the supervisor.

## Contract change (for Sebastijan)

`GET /api/kb/{stem}/{section}` **never 409s anymore**. Without the PDF it returns the stored
extraction on a KB-only report (`report_id: "kb-<stem>"`): the table, `/extraction.csv`,
`/extraction.pptx` and multi-open Compare all work. The 404 moved to where the PDF is actually
needed — `/api/reports/{id}/pdf` and `/pages/{n}.png` answer 404 with
`the PDF for '<stem>' is not cached; fetch it from Extract (directory search) to see the pages`.
`GET /api/kb` entries gain `pdf_cached: bool`. Once a PDF is fetched, the same open returns the
regular `lib-<stem>` id (page images live again) and `/api/kb` reports that id.

## Not settled / out of scope

- The Source pane's default viewer is the browser PDF iframe; on a KB-only report that iframe shows
  the backend's 404 JSON (which carries the fetch hint verbatim) until the user switches to Image.
  The work order scoped SourcePanel to one placeholder sentence, so no iframe fallback was built.
- `CompareView`'s per-column error "Next step: fetch the PDF…" (v015) was left as is — it now can
  only fire on non-PDF errors, its text is harmless there, and CompareView is outside territory.
- `run_extract`/`index` on a `kb-` id would fail to find a PDF to parse; the UI never issues those
  for KB opens (Results offers exports only). Not guarded, per territory.
- The README's Frontend table row for KbView still describes v019's disabled-Open behavior; the
  work order scoped README edits to the contract-gap line only.
