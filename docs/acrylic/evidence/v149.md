# v149 — offline income eval breakdown

## Scope and method

Changed only `scripts/eval_breakdown.py` and this evidence file.  The new command reads existing
`eval/labels.csv`, `data/kb/*/extractions/*.json`, and `pages.jsonl`; it imports the scoring
predicates from `eval/run.py`, so its value/page denominators agree with the harness.  It does not
start the API, download a report, mutate the KB, or call a model.

Baseline after the required delivery merge: `origin/acrylic` at `20db158`.

```powershell
python scripts/eval_breakdown.py --stored-kb data/kb
python scripts/eval_breakdown.py --stored-kb data/kb --section income_statement
python scripts/eval_breakdown.py --stored-kb data/kb --section debt_maturity
```

For every scored cross the output records the label value/page, stored value/page, field evidence,
key-specific (or extraction-wide diagnostic) warnings, deterministic-candidate membership, value
occurrences in stored page text, and observable page shape (years, Group/Parent markers, numeric
line count, schema-synonym presence).  It buckets each row exactly once:

- **A** — a stored field is null / was not read;
- **B** — a stored value differs (with conservative unit, Parent, and row/column hints);
- **C** — the value is right but its page is wrong.  Its subreason uses v132's method: the value on
  both pages is label scope; an absent source-page value is either a marked derivation or a citation
  defect candidate; an adjacent page is a continuation candidate; otherwise it remains a semantic
  page-inspection case;
- **D** — the non-null label value is absent from every stored report-text page, a label candidate.

The script explicitly calls these *candidates*: text digit matching cannot prove a table cell.  This
is the correct level of certainty for a zero-model offline triage tool.

Read inputs include `eval/run.py`, `scripts/page_miss.py` (v132 page-text/value semantics),
`scripts/locate_reach.py`, the income schema, and v013/v049/v052/v017.  In particular, v049's
multi-column/page-shape caveat and v052's row-anchored year-header mechanism are why the report
records facts rather than asserting a column from text alone.  A read-only UAW source-tree and
keyword scan found no transferable offline eval-breakdown implementation, so no UAW code was copied.
