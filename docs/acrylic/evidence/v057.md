# v057 — `debt_maturity` hand-verified labels (34-company hardening universe) + `eval/run.py --stored-kb` offline scoring

Lane `v057`, off `origin/acrylic`. Zero model calls. Territory: `eval/labels.csv` (append-only), `eval/run.py`
(new offline mode only, existing API-mode logic byte-for-byte unchanged), `eval/README.md` (one section),
this file. `backend/`, `frontend/`, `scripts/`, `data/` untouched.

## What this is for

`docs/HANDOFF.md`'s open item for Sara: label `debt_maturity` for the Mid Cap universe so `eval/run.py` gives
a number that isn't the backend grading itself. Four hardening rounds (`v035`/`v037`/`v041`/`v048`, seeds 1–4,
40 draws / 34 distinct companies) already did the hard part — each evidence file records, per company, which
page holds the real maturity note, what basis it's on (carrying vs contractual), and whether the printed
figure was hand-checked against the page text. This lane turns that trail into `eval/labels.csv` rows, plus an
offline scoring mode (`--stored-kb`) that replays those same stored extractions through the existing
comparison logic — no API, no model, so the accuracy number isn't the backend's own confidence score.

## Method

1. Read `v035.md`, `v036.md`, `v037.md`, `v040.md`, `v041.md`, `v044.md`, `v046.md`, `v048.md`, `v050.md`,
   `v052.md` in full (the four hardening rounds plus the six extract.py/schema fix tickets between them), plus
   `docs/HANDOFF.md`, `backend/schemas/debt_maturity.json`, `eval/run.py`, `eval/labels.csv`. Also opened
   `v045.md` (two-pass page-selection tuning, not on the work order's reading list but directly cited by
   `v046.md` and holding 32 stored per-company JSON snippets) — reading it materially improved coverage and
   caught one of the two corrections below, so it's listed here rather than silently used.
2. For every company named in those ten files, extracted the claimed page + value + basis, then **read the
   real page text myself**, page by page, from `C:\...\uaw-lanes\vivicta-shared\seed{1,2,3,4}-kb\<stem>\
   pages.jsonl` (read-only) — never trusted a lane's transcription without seeing the raw text. This caught
   two real errors (see Findings) and resolved one architecture gap four lanes had left as "unattributable"
   (XANO Industri).
3. A value is labelled only when (a) the real page + row is identified and (b) the specific number is present,
   verbatim or as a literal-column sum the schema's own `value_convention` sanctions, in the page text I read.
   Disputed values (two tables on different bases, a granularity mismatch, a non-reconciling bucket table) are
   **not** written — listed in the "For Kristian" table below instead, per the work order's own instruction.
4. Every row's `notes` names its source page/table, its basis (carrying vs contractual/undiscounted), and which
   lane(s) it corroborates or corrects.

## `--stored-kb` offline scoring (`eval/run.py`)

Added `--stored-kb DIR` (repeatable): zero API/model calls, reads `<DIR>/<stem>/extractions/<section>.json`
(the shape `extract_section()` already returns) and scores it through the **unmodified** `values_match`/
`page_match`/`print_report` logic. A label row whose `(report_file, section)` has no stored file scores `-`
(excluded from the denominator), not a miss — `print_report`'s aggregate now filters `value_ok is None` the
same way it already filtered `page_ok is None` for "no `expected_page` given"; every existing call path
(`--dry-run`, live API) never produces `value_ok=None`, so this is provably a no-op for them (see Gates).

Ran against `seed1-kb` … `seed4-kb` (the same 4 seeds the hardening rounds used) and `data/kb`:

## Findings

**1. Bergman & Beving: a real year-column bug in the stored extraction, persisting across 4 hardening
rounds.** `v035`/`v036`/`v040`/`v050` all store `total_debt=2062`, `due_within_1_year=476` for this company.
The report's own page 120 table header reads `31 Mar 2026 | 31 Mar 2025` and prints, in that column order,
`Total interest-bearing liabilities 2,390 2,062` and `Total current liabilities 424 476` — **2,062/476 are the
prior-year (31 Mar 2025) comparative, not the report's own current year (31 Mar 2026)**. Verified two
independent ways: the sub-line arithmetic is self-consistent in the printed order (285+0+139=424 for 2026;
322+0+154=476 for 2025), and the same page's own prose states "amounted to MSEK 2,038 (1,626) as of 31 March
2026" for the bank-loan component alone (2,038+352 lease = 2,390, matching the *first* column). This is a
genuine model/pipeline mistake (reading the second column of a two-year table), not a company-specific quirk
— found only because this lane re-derived the number from the raw page text per the work order's own step 2,
rather than trusting the stored value. Labelled `2390`/`424`; scores as a **miss** against every seed1-kb
snapshot (correctly — that's the point).

**2. XANO Industri's "unattributable 8th column" (v035/v036/v044) resolves cleanly once read unscrambled.**
Three lanes flagged this company's bucket-as-columns row as having one numeric column more than the header
could explain, and left `due_1_to_5_years`/`due_after_5_years` null rather than guess. Reading the same page
(84) fresh from `pages.jsonl`, the header is 8 columns, not 7 — `[-30 dgr, 31-90 dgr, 91-360 dgr, **Summa inom
1 år**, Mellan 1-3 år, Mellan 3-5 år, Efter 5 år, Totalt]` — the 4th column is a printed subtotal ("sum within
1 year"), not a bucket boundary the earlier reads' 7-column header omitted. `51,075+768,885+33,784+50,778 =
904,522`, exact, and `due_within_1_year` is the printed subtotal itself (51,075), not a computed sum. Labelled
all 4 fields; `due_1_to_5_years`/`due_after_5_years` score as **misses** against every seed's stored
extraction (the backend still doesn't produce them) — a real, still-open gap, now with a verified answer on
record for whoever picks it up next.

**3. `unit_hint: currency_millions` is prompt guidance, not a normalization the backend performs — labels
must stay in the report's own printed unit.** Tried converting KSEK/TSEK/tEUR/EUR'000-denominated companies'
values to millions per this work order's own reading of the schema's `unit_hint`; testing against real stored
extractions showed the backend reports the value **as printed**, with a separate `unit` field describing the
native currency/scale (`"value": 758938, "unit": "KSEK"` for Knowit, confirmed directly in the stored JSON) —
never rescaled. A millions-converted label can never match a correct extraction. Reverted for all 7 affected
companies (Knowit, NCAB, XANO Industri, Ework, Gentoo Media, Ependion, Better Collective) back to "as printed"
— `eval/README.md`'s own pre-existing convention, and how every existing income_statement row already works
(Hexagon's MEUR, ABB's USD millions, etc. are not rescaled either). Recorded because the work order's own
phrasing pointed the other way and this was only caught by testing against real data, per this lane's own
"premise can be overturned" instruction.

**4. AcadeMedia: page 97 ("M10: Räntebärande skulder", 300/300/0) is the Parent Company note, not the Group's.**
This filing numbers Parent Company notes `M<n>` and Group notes `K<n>`; M10 explicitly says "the Group's
outstanding debt is described in K28" in its own closing sentence, and the schema's own `exclude_keywords`
(`moderbolaget`/`parent company`) exists precisely to steer away from tables like this one. The correct, Group
figure (12,103) is on p.87, Note K28's own roll-forward table — matching what `v037` already used, but worth
recording explicitly since a naive read of the candidate-page list could land on the wrong entity's table.

**5. Better Collective: a two-column-merge ambiguity resolved by anchoring to an unrelated, unambiguous
number.** Page 161's carrying `Debt to credit institutions` row is printed twice, side by side (2025/2024),
and pymupdf's line extraction interleaves them into a single garbled block; `v045` read `259,946` for FY2025,
this lane reads `259,691`. Resolved by anchoring to the cash-flow statement (p.129, unambiguous: `Cash and
cash equivalents period end: Cash 13,494 37,674` for [2025,2024]) and tracing which "Total financial assets"
line (63,763+0+37,674=101,437 vs 73,596+0+13,494=87,090) shares a physical column with which "Debt to credit
institutions" figure — 87,090 pairs with 2025's own cash (13,494), and that column's liability lines sum to
≈345,823, closest to that column's own "Total financial instruments" line (346,078) — placing `259,691` in
2025, `259,946` in 2024. `v045`'s own reading was the FY2024 comparative.
