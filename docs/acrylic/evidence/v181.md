# v181 — structured reasons for empty debt maturity fields

## Scope and contract

`debt_maturity` now adds `missing_reason` only to a final-null standard field
(`total_debt`, `due_within_1_year`, `due_1_to_5_years`, or
`due_after_5_years`). The attachment has the documented `code`, `detail`, optional
page/quote, and (for off-grid disclosures) the original `disclosed` span, amount,
unit, page, and quote. It never fills a standard bucket, changes a value, changes
checks, or adds a reason to a non-null field.

The deterministic causes are: table column absent, off-grid span, a current versus
non-current-only split, lease-only or parent-only scope, a straddling interval, and
the final `not_found` fallback. Existing facts are recorded at the guard that proves
them and attached only after all repair paths complete, so a later proven repair
wins over a reason.

The API contract in `docs/API.md` and `frontend/src/types.ts` is identical. The
Results table adds `Why empty:` followed by the factual detail, and shows a compact
`As disclosed in the report` table for raw off-grid spans; the existing
`absent_in_table` verification badge remains the sole presentation for that case.
The PPTX field table has the same one-sentence `Why empty:` column.

## Targeted red → green

Before the implementation, the new off-grid regression assertion failed because a
null standard bucket had no structured reason. After the implementation,
`python -m pipeline.test_confidence` passes its off-grid/no-mapping,
straddling-range, not-found, parent-only, lease-only, and legacy
absent-in-table cases, plus its PPTX assertion that the exported table contains the
same `Why empty:` detail. This is a behavior change in metadata only; the fixture
values stay null.
