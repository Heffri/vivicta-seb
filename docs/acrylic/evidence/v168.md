## 缺陷(工单标题,全部核实为真)

`merge._same`/`matches_stored` 只比数值(±2):同值异单位(100 MSEK vs 100 TSEK)、异 period、
异 fiscal_year 的存量、异 maturity_basis 的存量,都会被当成一致/支持票。第三票取用在 app.py
只排人工复核(`has_reviews`),不看存量顶层自带的 `maturity_basis`/`fiscal_year` —— 切换
carrying/undiscounted(DEBT_BASIS)后再跑、或报告 meta 的 fiscal_year 变了,旧答案照投。

## 规则落地(全在 merge.py 纯函数内)

- **`_same_field(a, b)`(新)**:值规则同 `_same`(±2、null==null);两边都非空时加核 unit 与
  period。unit 按**数量级+币种**比较,不是字面串:`MSEK`/`SEK M`/`SEK m`/`SEKm`/`SEK million`
  同属百万 SEK,`KSEK`/`TSEK`/`SEK '000`/`THOUSANDS OF SEK`/`SEK thousands` 同属千 SEK,
  `Miljoner kronor`/`Mkr` 亦归 SEK(别名表);**MSEK vs TSEK 差 1000 倍,永不相等**;币种不同
  (MSEK vs MEUR)也不等。单边未知(一方无 unit/period)不算同("未知不自动算相同");双边都
  没印则无矛盾,值规则说了算;null==null 的空票一致与元数据无关(空答案没有可资格化的数字)。
- **`stored_ineligible(run1, stored)`(新)**:第三票资格 = 同 report(`report_id`)、section、
  fiscal_year、maturity_basis,四项**缺一即不合格**(存量顶层缺元数据 → 不参与)。run1 的元数据
  就是现场值(刚抽完):与之对比即与现状对比。同一 report(stem)由路由读文件路径构造保证,
  `report_id` 相等再加一道防线。
- **`matches_stored`**:先资格核对(不合格 → False,精确跳过不触发),再逐字段 `_same_field`。
  app.py 的调用点无需改:不合格时它返回 False → 照常跑 run2 → `merge_runs` 落注记。
- **`merge_runs`**:majority 且存量不合格 → 视同无第三票(决策退化为 union,与既有
  stored=None 路径一致),merge 块写 `"stored_vote": "not eligible: <原因>"`(原因含具体字段与
  两侧值,如 `stored fiscal_year 2024 != 2025`);`_pick` 的两处 `_same(值,值)` 换成
  `_same_field(a, b)`(agree/conflict 判定与文案标签随之同问题化),**冲突 → null 分支一字未动**;
  `_majority` 的三票一致判定改走 `_same_field`(异尺度的两个 100 不再凑成两票多数)。
- **附件门**:run1 的 `prior_year`/`buckets_by_year` 是对 run1 自己行的确定性读出,合并后仅当其
  覆盖的每个字段**仍携带 run1 的那个答案**(`_same_field(merged[k], run1[k])`;另一遍对同一答案
  的副本 —— v145 实测翻转 0 —— 算数)才随行;否则丢掉并在 warnings 写
  `merge: prior_year dropped -- <字段> is no longer run1's answer`(`buckets_by_year` 只门
  `total_debt`,其身份闭合计在它身上)。工单允许"不带(或标来源)",取不带;判定取"答案"而非
  winner 名字,依据是工单引 gpt6 原文"无法继续支撑当前字段时不展示成当前结果的附件" —— 一致
  平局下 published 值就是 run1 的值(±2 同带,附件闭合同带成立),按 winner 名字丢会把有效附件
  在 conf 平局(tie → run2)时全数丢光。若判定应为字面 winner,一行可改(`merge_runs` 附件门)。

## 单位解析器(实现的副产物,单独交代)

语料扫描(74 对 raw run + data/kb 全部 debt_maturity 存量)得到 26 种单位拼法。解析器
`_unit_key`:词形(billion/million/miljoner/thousand/tusen/mn…,含瑞典语)→ 独立词
(`SEK m`)→ `'000`/`000` 千位记法 → 前缀粘字(`MSEK`/`KSEK`/`TSEK`/`Tkr`,要求余下部分是已知
币种,`Miljoner …` 的首字母不误剥)→ 后缀粘字(`SEKm`,要求 `SEK`/`EUR`/`USD`… 已知币种,
裸 `SEK`/`NOK` 永不会被读成千位)。别名:`KRONOR`/`KR`→`SEK`、`EURO`→`EUR`。33 个词汇用例
全对(脚本内联在上面的核验命令里);`Tkr`/`Mkr` 经 `KR` 别名归 SEK,故与 `TSEK`/`MSEK` 可比。
