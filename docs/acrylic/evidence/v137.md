### Finding 1 — `--user-data-dir` does not isolate a packaged run on this build

The work order (and the dev-mode lesson behind it) prescribes `--user-data-dir <dir>` to keep a
lane's smoke off the owner's single-instance lock and userData. On the packaged exe that switch
is **ignored end to end**: the custom dir was never created, the launch wrote its log and
Chromium profile files into the default `%APPDATA%` userData, and a second launch (attempted with
a redirected `APPDATA` env var) died on the single-instance lock — the lock is keyed on
`app.getPath('userData')`, which `desktop/main.js` never overrides (no argv handling anywhere in
the shell). Dev mode's `--user-data-dir` advice and the packaged app's real behavior have
diverged; the packaged escape hatches that DO exist are documented in `desktop/README.md`
(`ARP_DEV_BACKEND_DIR`, dev-mode reuse) and none of them relocate userData. Left unfixed —
desktop code is outside this lane's territory; reported for the supervisor.

### Finding 2 — the owner's existing userData pins the old Enea extraction (v107 semantics working as designed)

The default userData has existed since 09-16 (102-entry KB era). The every-launch merge
(`desktop/data-sync.js`, v107) copies **only files the user does not have** — so the 09-16-era
`enea_2025` extraction (total null, pre-c387a5e) survives every refresh, while new stems (linc,
rejlers, …) land fine. Byte-checked: the freshly staged bundle in the app dir
(`resources/data/kb/enea_2025/extractions/debt_maturity.json`) **does carry `total_debt 305,555`**
(v131's section-subtotal join, published in the `data:` commit), so a fresh install — or the owner
after clearing their userData — gets 305,555 from this app build; the owner's current install will
keep serving the old null for enea until their userData is reset. Data freshness is therefore
proven through the packaged app by #1 (206 served, +104 merge line) and #3 (new stems present),
and by the byte check; the literal enea-total-via-API assertion is unreachable without touching
the owner's app data, which this lane did not do.
