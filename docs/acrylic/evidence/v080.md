## Five sources, cheapest first

```
POST /api/reports/fetch { company, year, country?, hint? }
└─ fetch.fetch_report
   ├─ 1  MFN company feeds → release attachments (+ stub-notice → issuer-site harvest)
   ├─ 2  Nasdaq Nordic "Annual Financial Report" notice attachments
   ├─ 3  web: issuer-page crawl + DuckDuckGo filetype:pdf
   ├─ 4  model's own web search (codex/claude only), ≤3 direct-PDF-or-IR-page URLs        (v074)
   └─ 5  ONLY when 1–4 all produced nothing usable                                        (v080, new)
         crawl whatever page-shaped leftover those attempts produced -- a model reply
         naming an IR page instead of a PDF, a web-search hit that served a page, or the
         guessed IR path for the domain of a direct link that 404d -- one hop deep.
         Every harvested .pdf link passes the same IS_AR/BAD_URL/NOT_REPORT gate and the
         same download+validate chain; unlike 1-4 (first survivor wins), this source
         downloads every harvested candidate within budget (≤8, 20s each, 90s total) and
         keeps the one with the most pages. Survivor: note "IR page crawl",
         tags ["fetched", "foreign"].
```

## What actually changed in `fetch.py`

- `SEARCH_SYSTEM` gained one sentence: *"If you cannot find a direct PDF link, a URL for the company's
  investor-relations or annual-report page is also acceptable."* The model still only ever replies with
  the same JSON shape; nothing else about level 4 changed.
- `_stub_pages`'s host→guessed-IR-path list is now the named `_IR_PATHS` constant behind a small
  `_ir_guesses(hosts)` helper (pure refactor, same five paths, same behaviour) so the new `_host_guesses`
  can reuse it for a *dead* direct link's own domain (Shell-style) instead of only a stub PDF's text.
- New: `_host_guesses`, `_ir_links`, `_crawl_ir_page`, `_ir_page_report` (fifth source itself).
- `fetch_report`'s two existing candidate loops (the plain-candidate loop and the model-candidate loop)
  each gained two bookkeeping lines: on a request exception, guess IR paths for the URL's own domain
  (`_host_guesses`); when a fetch succeeds but the payload isn't a PDF at all, remember the URL itself
  as a page to crawl. Both are pure list bookkeeping — no new network calls, so a fetch that succeeds
  anywhere in levels 1–4 is completely unaffected (same candidates tried, same latency). Only once *both*
  loops are exhausted does a new block call `_ir_page_report` on whatever got collected.

**Shell is not fixed by this lane, and the failure shape is fully diagnosed**: the model already finds
the right file; a pre-existing, shared filter (`BAD_URL`, used by all five sources) rejects it for a
reason unrelated to its actual content (it matches "sustainab" in a URL path segment, not the document
itself). Fixing that regex is outside this lane's assigned surface (`fetch.py`'s fifth-source addition
+ one `SEARCH_SYSTEM` sentence, per the work order) and touches all four earlier sources at once, so it
is flagged here for a follow-up lane rather than changed under this ticket.

**Nestlé stays on the 67-page Annual Review.** The fix this lane adds is conditional — it only engages
when the model hands back a *page* instead of a direct link — and today the model still returns a
direct, validating link to the summary volume, so level 4 succeeds before level 5 gets a turn. This was
one of the two outcomes the work order itself anticipated ("全本/仍摘要").

None of the 4 live trials exercised the fifth source — every company either succeeded earlier or was
filtered before reaching it. That is a genuine, reproducible property of today's model behaviour and
network conditions, not a sign the mechanism is unused: it is what the work order's own two-way
"fixed / documented failure shape" framing expects can happen, since level 4 already covers most cases
after v074. The mechanism itself — the part actually new in this lane — is proven deterministically
instead, in `test_fetch.py`.

## Tests

`backend/pipeline/test_fetch.py` — 9 pre-existing assertion groups (v074) plus 4 new (v080), all
against a loopback http server serving generated PDFs and static HTML pages, zero model calls:

- **10.** A model reply names the issuer's IR page instead of a direct PDF → `fetch_report` crawls it,
  drops an interim link (no `IS_AR` match) sitting next to the real one, and registers the real report
  with `note: "IR page crawl"`, `tags: ["fetched", "foreign"]`, and both URLs recorded in `tried`.
- **11.** The crawled page links both a shorter and a longer valid report (mirroring Nestlé's Annual
  Review next to its actual Annual Report) — the fifth source downloads both within budget and keeps
  the one with more pages, not just the first one found.
- **12.** The IR page itself carries no PDF link but points one hop to a same-domain reports page that
  does — the crawl follows that single hop and finds the report there.
- **13.** A direct link that 404s outright (Shell's shape) leaves no page to crawl: `_host_guesses`
  derives the same IR-path guesses `_stub_pages` already makes, seeded from the dead URL's own domain,
  gated on that domain actually naming the company (an unrelated domain guesses nothing).

Existing groups 1–9 pass unchanged (checked line by line): none of their candidate URLs are ever pages
or 404s that name the company's own domain, so `page_seeds` stays empty in every one and the new final
block never fires — confirmed by rerunning the full suite after the new groups were added.
