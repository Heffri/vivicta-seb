## 6. Two real bugs found live this lane, neither in `desktop/**`'s shipped code

1. **PowerShell's `Start-Process -ArgumentList` silently mis-splits a `--flag=value` argument when
   `value` contains a space**, unlike passing the same array to Node's `child_process.spawn`. First
   launch attempt used `Start-Process -FilePath $exe -ArgumentList @("--user-data-dir=<lane path with
   a space>", "--remote-debugging-port=9247")`; `Get-CimInstance`'s own `CommandLine` readout showed
   the resulting child processes' `--user-data-dir` had silently fallen back to Electron's **shared
   default** `%APPDATA%\annual-report-parser-desktop` instead of the isolated lane path — the intended
   value was present verbatim in the *stub's own* command line but unquoted, so Chromium's own
   whitespace-splitting argv parser (inherited by every Electron/Chromium child process) cut it at the
   space. Not a `desktop/**` bug — Electron's own `--user-data-dir` switch handling is correct and is
   exactly what every prior packaging lane's own launch commands already relied on (v032 §4, v033 §7);
   this is a PowerShell-launcher gotcha specific to any lane path containing a space, worth a LESSONS
   entry for whoever else double-click-tests a build this way (not added here — outside this lane's
   territory to edit shared process docs; flagging per common.md's own "发现" convention instead).
   Fixed by launching through Node's `spawn()` with an argv array instead, which Windows'
   `CreateProcess` argument-reconstruction quotes correctly per-element.
2. **A `waitForSelector` on text that's already true on the *previous* screen races the actual
   navigation.** The first acceptance pass waited on `text=Atlas Copco` after clicking the KB row's
   `Open` button — but "Atlas Copco" is also the company name already visible in the *pre-click*,
   still-open KB table row, so the wait resolved instantly and the screenshot captured the KB list,
   not the opened Results view (caught by looking at the actual PNG, not by the script's own boolean
   check, which reported `kbShowsRealCompany: true` correctly but for the wrong screen). Fixed by
   waiting on `text=Export JSON` instead — a string that only renders in `ResultsView`, matching
   `common.md`'s own documented `shot.mjs` convention (`waittext=Export JSON`) for exactly this
   transition, which would have avoided the mistake if consulted first.
