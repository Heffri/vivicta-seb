# v183 — registration never returns plaintext 500

## Scope and reference

- Read the v178 skip record before reproducing. Its HAKI named-link fix (`c669b19`) remains in place.
- Checked UAW `src/annual-report/pdf/open-annual-report.ts`: it opens pages and classifies a sparse text layer, but has no report-cache manifest behavior to adapt here. This change is limited to this backend's registration cache boundary.
- All live work used an isolated `ARP_DATA_DIR`; report PDFs and generated KB text stayed outside the repository.

## Root cause

An empty `ARP_DATA_DIR` intentionally has no `reports/index.json`. `app.library_index()` unconditionally read that file before `/api/reports/fetch` began discovery, raising `FileNotFoundError`. FastAPI therefore returned plaintext HTTP 500 for both reports. The reports had not yet been downloaded or parsed, so the failure was cache registration setup rather than a HAKI- or Cinclus-specific PDF defect.

`library_index()` now returns an empty list when the manifest is absent. A present manifest keeps the existing JSON and on-disk-PDF filtering behavior unchanged.

Commit: `60dcbbf` — `backend: treat absent report index as empty`.

## Red → green

### Red

1. With an empty isolated data directory containing only `companies.json`, `POST /api/reports/fetch` with `download_pdf: true` returned plaintext HTTP 500 for both **HAKI Safety 2025** and **Cinclus Pharma 2025**.
2. The focused regression was added to `pipeline.test_fetch`: patching `app.LIBRARY` to an empty directory made `app.library_index()` raise `FileNotFoundError` while reading `index.json`.

### Green

1. `python -m pipeline.test_fetch` passes after the guard (`fetch self-check ok`).
2. Restarted the fixture backend with a new empty isolated directory containing only `companies.json`:

| report | fetch | registered pages | `GET /api/kb/{stem}/pages/1` |
| --- | ---: | ---: | ---: |
| HAKI Safety 2025 | 200 | 80 | 200; 96 characters |
| Cinclus Pharma 2025 | 200 | 87 | 200; 52 characters |

The successful registrations created `reports/index.json` normally.

3. A separate isolated run registered five existing report-cache PDFs without any 500:

| PDF | registration result |
| --- | --- |
| `academedia_2025.pdf` | 200, 112 pages |
| `acast_2025.pdf` | 200, 91 pages |

| `apotea_2025.pdf` | 422: readable reason that local OCR language files `eng, swe` are missing |

The final 422 is the existing, intentional scanned-PDF policy; it confirms the required human-readable 4xx behavior rather than a server error.
