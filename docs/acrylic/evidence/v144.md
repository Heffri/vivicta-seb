## The two narrow guards

1. `_fill_bucket_columns` now requires the source row's recognised bucket values to sum to its
   selected total within ±2 before it may replace a non-null model total. Subtotal-superseded
   `_excluded` columns are not double-counted (the XANO subtotal form remains closed). If the
   existing total cites that very unclosed row, it is dropped as unproven rather than perpetuated
   in a stored replay.
2. `_row_amounts` remains header-count driven, not score-driven. `85 151` splits into `85`, `151`
   when the header has five amounts; under MTG's four recognised headers that split would create a
   fifth value, so it remains an ambiguity for guard 1 rather than becoming a guessed repair.
   Boozt's sparse six-column `78 273` reading still splits because it lands exactly on its header
   count, while the genuine Swedish grouping `1 234 567` remains one amount. No scoring heuristic
   or issuer-specific branch was added.
