## Premise check (the work order asked to verify, not assume)

`LibraryEntry.file === KbEntry.stem + '.pdf'` — checked two ways, not just read from source:

1. **Backend source** — `backend/app.py:261`, `GET /api/kb/{stem}/{section}`'s own 409 check:
   `entry = next(e for e in library_index() if e["file"] == f"{stem}.pdf")`. This is the exact
   join the frontend now mirrors — not an inference, the same key the backend uses to decide the 409.
2. **Real data** — `data/reports/index.json` has 114 entries; every one of the 102 `data/kb/*` stems
   has a matching `file: "<stem>.pdf"` entry (checked with a throwaway `python -c` loop, 0 mismatches).
   Right now 0 of those 114 files are actually on disk (`present_on_disk` empty) until a PDF is copied
   into `data/reports/`, matching common.md's note that the cache starts empty.

Premise holds, not overturned. No backend change, no key translation needed.

## What changed

`KbView.tsx`:

- **Load** — `getLibrary()` fired alongside `getKb()`/`getSchemas()` in the mount effect. Result kept
  as `pdfFiles: Set<string> | null` (the `file` basenames), not the raw array — only membership is
  needed. `null` means "not known yet or the call failed"; `hasPdf(stem) = !pdfFiles || pdfFiles.has(stem + '.pdf')`
  treats unknown the same as available, which *is* the requirement-4 fallback, not a separate code path.
- **Badge** — rows without a cached PDF get an `outline` badge "no PDF" next to the company name/stem
  (same recipe already used for the Embeddings column's "not yet": `variant="outline"` +
  `text-muted-foreground`, muted not danger — this isn't an error state).
- **Open button(s)** — `disabled` gains `|| !available`; add `title="PDF not cached — fetch it from the
  Extract tab first"` and `aria-describedby` pointing at one shared `sr-only` span (id `kb-no-pdf-desc`,
  rendered once per table) carrying the same sentence, so assistive tech gets it without a per-row
  duplicate node.
- **Checkbox** — same `available` folded into its existing `disabled={!e.sections.length}` condition
  (now `|| !available`), plus a `title` for a native tooltip. Otherwise ticking a no-PDF row and hitting
  Compare would 409 on that leg, same failure mode v010's Compare-column error was documented for.
- **Header count** — `"102 reports"` → `"102 reports · 1 with PDF"`, but only when `pdfFiles` is
  non-null; falls back to the old unsuffixed text when the library call hasn't resolved yet or failed
  (see below — showing a count we don't actually have would be worse than not showing one).
- **"With PDF only" toggle** — new checkbox next to the filter input (same bare
  `<input type=checkbox accent-ring>` pattern the row-select checkboxes already use — no `Switch`
  primitive exists, matches v005's precedent for not inventing one for a single consumer). Display-only,
  folded into the existing `filtered` predicate, `selected` untouched. Default off. Disabled (with a
  title) when `pdfFiles` is null — toggling a filter that can't actually filter would silently no-op,
  which is worse than graying it out.
- **Logic untouched** — `open()`, `onOpen`, `toggle()`, `withSection`/`section` selection: byte-for-byte
  same as before this change.
