## The gap

v044's present-label guard (a null `null_as_zero` bucket is only zero-filled when its own synonym label is
absent from the search rows) searched **every row of every candidate page**. Swedish notes routinely stack
several tables per page, so a bucket word printed by a *different* table blocked a 0 the operands' own table
really implies: MedCap's carrying-amount maturity table (p.101) has no `>5 år` row, but the contractual
cash-flow table's `>5år` header (p.102) sat in the candidate-page search, so `due_after_5_years` stayed out
of the zero-fill and `maturity_sums_to_total` sat at `missing: due_after_5_years` although
54.3+48.0+616.5 = 718.8 ≈ 718.7 closes the identity.

## What changed (2 files, +118/−29 vs the merged base)

- **`backend/pipeline/extract.py`** — `_check`'s search rows are now, when provable, the rows of the
  operands' own table; new helper `_operand_table_rows` (placed next to `_row_year_column`, whose upward
  walk it reuses via `_year_run`). **Table-span definition:** anchor each *real* operand of the identity's
  expr — `total_debt` included, so the span reaches the Totalt row — to its exact `_page_rows` row (the same
  standard `_column_values`/`_derived_value` anchor rows by); per page, the span runs from the nearest
  year-header row above the page's topmost anchor (`_year_run` over the growing window; the page top when no
  header sits above, so a headerless table never narrows the search) down to the page's bottommost anchor.
  **No printable operand row anywhere → v044's whole-page search, unweakened** — quotes the model composed
  rather than copied give no provable boundary, and the guard must not get weaker on doubt. Synonym matching
  itself (normalize_ws digit-gluing, substring per row) is byte-identical to v044's.
- **`backend/pipeline/test_confidence.py`** — the two MedCap end-to-end cases re-expectationed to what the
  scoped guard honestly produces on the real page text, plus three new cases (in-table bucket word, stored
  state, same-page two tables) — see Red/green. The v044 *direct* `_check` cases and XANO/Ework/Ependion
  expectations are untouched and stay green (the v044 direct cases carry no quotes in `fields`, so they
  exercise the page-level fallback path by design).

## Findings

- **The work order's "MedCap → passed" holds for the stored/replayed state, not for a fresh extraction.**
  Scoping the guard removes the cross-table `<1 år` hit that was the *only* thing keeping
  `due_within_1_year` out of the zero set on MedCap's carrying table — its own bucket rows
  (`6 månader eller mindre`, `6 – 12 månader`) are printed right there but no schema synonym names them.
  Fresh extractions therefore zero-fill both nulls, the check reads failed (not missing), and v052's
  above-window derivation — triggered only by a missing operand — no longer fires: 102.3 is lost and the
  verified fields recap to 0.5. Reported to the supervisor mid-lane with probe evidence. **Root fix is a
  schema-vocabulary change, out of this lane's territory:** adding month-range synonyms
  (`6 månader eller mindre`, `6 – 12 månader`) to `due_within_1_year` restores the whole chain
  (guard keeps it out → missing → v052 derivation fills 102.3 → passed).
- **Nelly's new pass is technically permitted but semantically lucky** — the stored answer is the lease
  note's total, and the identity closes only because both buckets are confirmed 0s. A borrowings-maturity
  extraction for Nelly would want `due_1_to_5_years` from `Långfristiga`, which the schema deliberately
  does not synonym-map (v040). Flagged for the schema lane, not worked around here.
- The stored MedCap stub (joined two-row quote) takes a pre-existing detour: `_segment_column` votes the
  joined quote into another column (48), and the `value_derived` repair reads it back to 102.3. That
  detour predates this lane; on the pre-v058 code the repair was *suppressed* (the check read missing,
  which skips the repair loop), so the mangled 48 stuck — v058's passing check lets the pipeline self-heal.
- `_between_rows`/`_row_year_column`/`_stated_zero`/v054's retry entry points: only called, never modified.
- Not done: README (supervisor patches at merge, per the work order); no schema edits; no model calls.
