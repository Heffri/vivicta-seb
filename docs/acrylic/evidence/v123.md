## The measure (new tool): `scripts/locate_reach.py`

Per labelled company, is the label page inside the locator's candidate window?

- **debt_maturity (87 companies)**: every `eval/labels.csv` `expected_page`, one column per row
  (a company may hold several; a company takes its worst page's class).
- **income_statement (101 companies)**: labels.csv covers only 12 income companies, so the expected
  page is the **majority `source.page` of the stored `data/kb` extraction** — the v008 measure
  ("101 家已存抽取的多数 source page"), which is where the work order's 101 comes from.
- Classes per page: `in` (a candidate) / `adjacent` (±1 of one — the two-pass companion rule's reach)
  / `unreachable`; `empty` when the candidate list is empty (company-wide). Each row also prints the
  candidate list and the label page's own **rank and score** from `locate.scored_pages` (new, pure
  refactor out of `candidate_pages`) — `#N @score` below top_n or `noscore` (no keyword on the page,
  it never entered the ranking) is the why for every miss.
- `--baseline <ref>` loads locate.py **and** `schemas/<section>.json` as of that ref (git show, the
  replay_check mechanism) and prints both sides' totals plus every per-company class move — a
  schema-keyword change reads as honestly as a locator-code change (the script's first cut swapped
  only locate.py and showed a false "0 moves" for keyword commits; fixed before delivery).

## The three changes (one commit each, each gated by locate_reach before/after on both sections)

1. **`locate: budget trim demotes to the snippet tail instead of dropping top-n pages`** — the trim
   now bounds only the window prefix (`WINDOW_PAGES = 4`, the deepest full-text read); an oversized
   page is demoted past the window, never dropped. Debt 66→**77** reachable (12 unreachable→in, 4
   adjacent→in, inwido/rvrc to adjacent); income 101/101, 0 moves. Token cost: pass-1 snippets grow
   by the untrimmed tail (≤ top_n pages × ~1.4k chars); full-text reads bounded exactly as before.
   Red/green: the ctt shape (two huge pages, small pages ranked #3/#4) dropped pages 5,7 on the old
   code, keeps them now — captured as `pipeline.test_locate.py` (new, 8th backend suite).
2. **`locate: debt keywords +loans from banks/credit institutions/förfall`** — three generic
   borrowings-row words for the noscore bucket: "Loans from banks" (bhg's Note 21 row), "credit
   institutions" (byggmax/cellavision/morrow/hexatronic/ovzon/better_collective rows — it was already
   a `row_synonym`, just not a page keyword), bare "förfall" (oresund's "Förfallanalys", whose
   candidate list was empty). Debt 77→**83** reachable (cellavision, hexatronic, byggmax, morrow,
   bhg, oresund unreachable→in; ovzon, better_collective adjacent→in); **zero companies move down**;
   income 101/101 (separate schema file, mechanically untouched — attested anyway).
3. **`locate: top_n 8 → 10`** — the one label page ranking #9 (inwido's Note 21) becomes a
   candidate; the only class move on either section is inwido adjacent→in (debt in 78→79, reachable
   stays 83). Cost: pass-1 snippets for up to two more pages. top_n 12 was measured — identical
   outcome to 10, so 10 is where it stopped.

Also committed: `locate: split scored_pages out of candidate_pages` (pure refactor, candidate lists
verified byte-identical over all 206 kb stems × both sections before anything else was built on it)
and `scripts: locate_reach.py` itself.

## What was tried and rejected (measured, not kept)

- **Balance-sheet keywords** (`balance sheet` / `balansräkning` / `rapport över finansiell
  ställning` / `statement of financial position`): +4–6 companies, but **svolder and hoist_finance
  go in→unreachable** (BS pages score high — heading +5, digit density — and crowd the top-8; still
  true at top_n 10 and 12). Net positive on the headline, negative on the no-loss rule — rejected,
  the v017 lesson applied to a different word family. Swedish-only variants trade the same way
  ("balansräkning" alone: flerie+kabe in, svolder out; "rapport över finansiell ställning" alone:
  kabe in, nelly in→adjacent).
- **Bare "borrowing"** (meren/byggmax shape): meren in, instalco in→adjacent — rejected (byggmax was
  already fixed cleanly by "credit institutions").
- **"reconciliation of liabilities" / "financing reconciliation"** (the IFRS financing-reconciliation
  note): only cellavision, already fixed by "credit institutions"; instalco soft-degrades — rejected.
- **top_n 12**: no additional gain over 10 — rejected (pass-1 cost for nothing).

## Premise corrections for whoever reads the work order (all verified, none blocking)

1. **replay_check's window never comes from locate.** Its candidate pages are derived from the
   *stored* json (the two-pass warning's recorded list, else the cited pages) — a locator change
   cannot move a replay window, so "候选页变化会改变回放窗口" is not how the tool works. Run anyway
   per the work order: **205 companies, 205 same, 0 changed** (baseline origin/acrylic, both
   sections) — attested, and expected by construction.
2. **v088's Inwido folio defect does not reproduce on the current baseline.** v088 recorded
   line-start folios ("165 Annual Report 2025 |") defeating `_folios` so `_folio_offset` returned
   None report-wide. Today `_folio_offset(inwido) == 0` — the standalone-folio-line shape ("150" on
   its own line) votes fine (the pages were re-parsed since; PARSER_VERSION has moved). A
   line-start folio pattern was implemented and measured: **zero** companies' offsets revive, zero
   class moves anywhere — not committed (LESSONS 10/11: check the defect still exists first).
3. **The "101 家" income measure is the stored-extraction majority page** (v008's own external
   check), not labels.csv — income labels exist for only 12 companies (one of them the placeholder
   `nordic_industrials_2025`). The tool says so in its docstring; the red line is consistent with
   v008's "101/101".
